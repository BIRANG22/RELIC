# 타임라인 스킬 예약 드래그 앤 드롭 설계

## 1. 목적

전투 스킬 목록의 스킬을 타임라인에 드래그 앤 드롭하여 예약하고, 이미 예약된 플레이어 행동도 같은 슬롯 내부 또는 다른 슬롯으로 옮길 수 있게 한다.

드래그 앤 드롭은 새로운 예약 규칙을 만들지 않는다. 클릭으로 예약할 때 적용되는 캐릭터 소유권, 슬롯 제한, 행동 수용량, 자원, 장비 효과, 행동 순서 및 네트워크 권한 검사를 동일하게 적용한다.

## 2. 목표

- 스킬 목록에서 타임라인 슬롯으로 스킬을 드래그하여 예약한다.
- 슬롯의 앞, 행동 사이, 마지막 위치에 삽입할 수 있다.
- 기존 플레이어 예약을 같은 슬롯 안에서 재정렬할 수 있다.
- 기존 플레이어 예약을 다른 슬롯의 원하는 위치로 옮길 수 있다.
- 중간에 삽입하면 기존 행동은 뒤로 자연스럽게 밀린다.
- 이동 예약을 옮길 때 기존 상대 이동 경로를 유지한다.
- 새 이동 스킬은 드롭한 뒤 이동 위치와 경로를 그리드에서 입력한다.
- 드롭에 실패하면 원본 예약과 비용 및 프리뷰가 전혀 바뀌지 않는다.
- 기존 플레이어와 몬스터 행동 순서 규칙을 유지한다.

## 3. 제외 범위

- 몬스터 행동은 드래그하거나 재배치할 수 없다.
- 기존 예약을 옮기는 동작으로 스킬 방향이나 이동 경로를 다시 편집하지 않는다.
- 드래그 앤 드롭으로 기존 예약 조건을 우회할 수 없다.
- 플레이어 행동을 몬스터 행동 구간에 강제로 삽입할 수 없다.

## 4. 기본 구현 원칙

`BattleTimelineController`에 드래그 앤 드롭용 트랜잭션 API를 둔다.

대상 슬롯과 삽입 위치에 대한 전체 검증을 먼저 수행하고, 검증에 성공한 경우에만 실제 슬롯 목록을 변경한다. 원본 행동을 먼저 제거한 다음 대상 슬롯 등록을 시도하는 방식은 사용하지 않는다. 이 방식은 실패 시 비용, 예약 이력, 방향, 이동 경로 및 네트워크 상태를 복구하기 어렵기 때문이다.

예약의 식별은 화면에 표시된 오래된 인덱스가 아니라 `PlayerReservedCommand` 객체 또는 네트워크에서도 유지되는 안정적인 예약 ID를 사용한다.

## 5. 드래그 시작 지점

### 5.1 스킬 목록

`SkillListSlotUI`에서 드래그를 시작한다. 드래그 데이터에는 다음 정보가 포함된다.

- 선택된 `CharacterRuntimeData`
- `SkillMasterData`
- 스킬 아이콘
- 신규 예약임을 나타내는 구분값

기존 클릭 예약 방식은 그대로 유지한다.

### 5.2 기존 타임라인 예약

플레이어 예약 아이콘에서 드래그를 시작한다. 드래그 데이터에는 다음 정보가 포함된다.

- 정확한 `PlayerReservedCommand` 또는 안정적인 예약 ID
- 원본 슬롯
- 원본 플레이어 행동 인덱스
- 기존 예약 이동임을 나타내는 구분값

몬스터 행동은 드래그 소스로 동작하지 않는다.

## 6. 드롭 위치와 삽입 규칙

각 타임라인 슬롯은 다음 삽입 위치를 제공한다.

- 첫 번째 플레이어 행동 앞
- 플레이어 행동 사이
- 마지막 플레이어 행동 뒤
- 슬롯 본체에 드롭할 경우 포인터에서 가장 가까운 합법적 삽입 위치

삽입 위치는 화면의 `Order01~05` 번호가 아니라 플레이어 명령 목록의 삽입 인덱스로 표현한다. 삽입 인덱스 이후에 있던 플레이어 행동들은 한 칸씩 뒤로 밀린다.

같은 슬롯 내부에서 뒤쪽 행동을 앞쪽으로 옮기거나 앞쪽 행동을 뒤쪽으로 옮길 때는 원본을 제외한 목록을 기준으로 최종 삽입 인덱스를 계산해야 한다.

## 7. 플레이어와 몬스터 행동 순서

기존 실행 및 표시 순서를 그대로 유지한다.

1. 신속 플레이어 행동
2. 몬스터 행동
3. 일반 플레이어 행동

플레이어 행동의 드롭 위치는 해당 행동이 속하는 플레이어 구간 내부에서만 유효하다. 몬스터 행동이 표시된 영역에 드롭하면, 드래그 중인 행동의 신속 여부에 따라 가장 가까운 합법적인 플레이어 구간 경계로 보정한다.

따라서 사용자는 플레이어 행동 사이의 순서를 바꿀 수 있지만, 기존 순서 계산을 무시하고 일반 플레이어 행동을 몬스터보다 앞에 놓거나 신속 행동을 몬스터 뒤에 놓을 수는 없다.

## 8. 신규 방향 스킬 예약

이동을 제외한 방향 기반 스킬을 스킬 목록에서 드롭하면 다음 흐름을 따른다.

1. 대상 슬롯과 플레이어 삽입 위치를 결정한다.
2. 기존 클릭 예약과 동일한 조건을 검사한다.
3. 기존 방향 결정 및 범위 계산 로직을 사용해 `PlayerReservedCommand`를 생성한다.
4. 명령을 슬롯 마지막이 아니라 지정된 삽입 위치에 넣는다.
5. 전체 예약 비용, 위치, 방향 및 범위를 다시 계산한다.

## 9. 신규 이동 스킬 예약

신규 이동 스킬은 드롭 시점에 이동 경로가 없으므로 즉시 명령을 생성하지 않는다.

드롭 시 다음 대기 정보를 저장한다.

- 캐릭터
- 이동 스킬
- 대상 슬롯
- 플레이어 삽입 위치

그 후 기존 그리드 이동 선택 단계로 진입한다. 사용자가 이동 위치와 경로를 확정하면 `PlayerReservedCommand`에 상대 이동 경로를 기록하고, 대상 슬롯과 삽입 위치에 대해 최종 조건 검사를 다시 수행한 뒤 삽입한다.

그리드 선택을 취소하면 대기 정보만 제거하고 타임라인은 변경하지 않는다.

## 10. 기존 예약 이동

기존 예약은 하나의 원자적 객체로 이동한다.

방향 스킬을 옮길 때 다음 데이터는 유지한다.

- 선택 방향
- 스킬 및 캐릭터
- 예약에 필요한 고유 선택 데이터

다음 데이터는 새 순서에 맞게 다시 계산한다.

- 실제 시전 위치
- 범위 그리드
- 선행 행동에 의존하는 효과 및 비용

이동 스킬을 옮길 때는 절대 도착 그리드를 유지하지 않는다. `왼쪽, 왼쪽, 위`와 같은 순서화된 상대 이동 단계를 유지한다. 슬롯을 옮긴 뒤에는 앞선 행동의 결과 위치에서 이 상대 경로를 다시 실행한다.

## 11. 이동 재시뮬레이션 예시

### 초기 상태

- 캐릭터 현재 위치의 오른쪽 2칸 위치에 벽이 있다.
- 1번 슬롯: 왼쪽 2칸, 위 1칸 이동
- 2번 슬롯: 오른쪽 3칸 이동

### 변경

- 1번 슬롯의 이동 예약을 3번 슬롯으로 옮긴다.

### 변경 후 실행

1. 2번 슬롯의 `오른쪽 3칸 이동`을 먼저 시도한다.
2. 오른쪽 두 번째 칸이 벽이므로 벽 앞에서 멈추며 실제로는 오른쪽 1칸 이동한다.
3. 3번 슬롯으로 옮긴 이동은 변경된 위치에서 시작한다.
4. 보존된 상대 경로에 따라 왼쪽 2칸 이동한 뒤 위로 1칸 이동한다.

즉, 슬롯 변경은 절대 목적지를 보존하는 기능이 아니다. 이동 의도인 상대 경로를 보존하고 새로운 타임라인 순서에서 전체 이동을 다시 시뮬레이션하는 기능이다.

각 이동 단계의 충돌, 벽, 점유 셀 및 이동 불가 조건도 기존 이동 실행 로직과 동일하게 다시 판정한다.

## 12. 공통 검증

클릭 예약과 드래그 앤 드롭이 하나의 공통 검증 경로를 사용하도록 정리한다. 검증 항목은 다음과 같다.

- 전투가 플레이어 예약 입력 단계인지
- 슬롯 선택과 입력이 잠겨 있지 않은지
- 대상 슬롯이 유효하고 네트워크 관전 또는 다른 플레이어에 의해 잠기지 않았는지
- 대상 슬롯이 해당 캐릭터의 행동을 받을 수 있는지
- 대상 슬롯의 행동 수와 타임라인 칸 수가 한도를 넘지 않는지
- 같은 캐릭터만 등록 가능한 슬롯 규칙
- 캐릭터 생존 및 소유권
- HP, 코스트, 자원, 실드 비용
- 장비, 유물 및 스킬별 예약 조건
- 첫 행동, 이전 공격, 이전 이동 및 슬롯 위치에 따른 비용 보정
- 신속과 몬스터 순서를 포함한 행동 순서 규칙
- 네트워크 권한

기존 예약을 옮길 때는 원본 예약을 원본 위치에서 제외하고 대상 위치에 넣은 가상 명령 목록을 만들어 전체 조건을 계산한다. 검증 중에는 실제 슬롯 목록과 실제 예약 비용을 변경하지 않는다.

## 13. 검증 실패 처리

검증이 실패하면 다음 상태를 모두 유지한다.

- 원본 슬롯과 순서
- 예약 행동 객체
- 이동 상대 경로
- 선택 방향
- 비용과 자원 예약값
- 예약 이력
- 위치, 방향 및 범위 프리뷰

기존 예약 실패 경고를 표시하고 드래그 아이콘은 원래 위치로 돌아간다.

## 14. 성공 후 갱신

성공 시 한 번의 트랜잭션으로 다음 작업을 수행한다.

1. 원본 위치에서 기존 예약을 제거한다. 신규 스킬이면 생략한다.
2. 대상 플레이어 삽입 인덱스에 명령을 삽입한다.
3. 예약 이력을 새 슬롯과 순서에 맞게 갱신한다.
4. 전체 예약 비용을 타임라인 순서대로 다시 계산한다.
5. 실제 캐릭터 상태를 시작점으로 모든 예약 위치와 방향을 재시뮬레이션한다.
6. 이동 경로, 고스트, 공격 범위 및 타임라인 UI를 갱신한다.
7. 멀티플레이 상태를 동기화한다.

## 15. 드래그 시각 피드백

- 드래그 중 합법적인 슬롯과 삽입 위치를 강조한다.
- 등록할 수 없는 슬롯은 금지 상태로 표시한다.
- 기존 예약의 원본은 이동 성공 전까지 화면과 데이터에 유지한다.
- 새 이동 스킬의 그리드 입력 중에는 선택한 슬롯과 삽입 위치를 계속 강조한다.
- 성공하면 한 번만 타임라인을 갱신한다.
- 실패하면 타임라인을 다시 만들지 않고 드래그 표시만 원래 위치로 복귀시킨다.

## 16. 네트워크

기존 예약 이동 및 재정렬용 네트워크 명령에는 다음 정보가 필요하다.

- 안정적인 예약 ID
- 원본 슬롯
- 대상 슬롯
- 대상 플레이어 삽입 인덱스

호스트는 권위 상태를 기준으로 동일한 공통 조건 검사를 다시 수행한다. 승인된 경우에만 원자적으로 적용하고 모든 클라이언트에 결과를 전파한다. 거절된 경우 클라이언트의 원본 예약은 유지하며 권위 스냅샷으로 상태를 정합화한다.

신규 스킬 예약은 기존 예약 네트워크 흐름을 사용하되 대상 슬롯과 삽입 인덱스를 포함한다.

## 17. 테스트 항목

- 방향 스킬을 빈 슬롯에 드롭해 예약한다.
- 방향 스킬을 두 플레이어 행동 사이에 삽입한다.
- 새 이동 스킬 드롭 후 그리드 경로를 선택해 지정 위치에 삽입한다.
- 새 이동 스킬의 그리드 선택을 취소하면 타임라인이 변하지 않는다.
- 기존 이동 예약을 같은 슬롯에서 재정렬해도 상대 경로가 유지된다.
- 기존 이동 예약을 다른 슬롯으로 옮기면 앞 행동 결과에서 상대 경로를 다시 실행한다.
- 벽 예시에서 오른쪽 이동이 1칸에서 멈춘 뒤 왼쪽 2칸, 위 1칸 경로가 실행된다.
- 기존 방향 스킬의 방향은 유지되고 범위는 새 시전 위치에서 재계산된다.
- 같은 슬롯 앞/뒤 이동 시 삽입 인덱스가 정확하다.
- 다른 슬롯으로 이동하면 양쪽 슬롯의 행동이 정확히 밀린다.
- 슬롯 용량, 캐릭터, 비용, 자원, 잠금 또는 소유권 검증 실패 시 원본이 유지된다.
- 신속 플레이어, 몬스터, 일반 플레이어 순서가 깨지지 않는다.
- 오래된 UI 인덱스나 중복 드롭 요청이 다른 행동을 이동하거나 삭제하지 않는다.
- 호스트와 클라이언트의 최종 순서 및 경로가 동일하다.
