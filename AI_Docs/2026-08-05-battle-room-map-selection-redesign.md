# 배틀 룸 유지형 지도 선택 UI 설계

## 목표

배틀씬 최초 진입 시 전체 지도 패널 대신 Start 노드의 StartRoom을 바로 연다. 모든 룸이 끝나면 기존 `BattlePanelTransition`이 화면을 가리는 동안 종료된 룸 배경과 캐릭터를 유지하고, 캐릭터를 왼쪽 가로 1열로 재배치하며 룸 전용 UI 대신 하단 가로 지도와 오른쪽 다음 노드 선택 버튼을 표시한다.

## 핵심 흐름

1. 새 런은 생성된 Start 노드를 자동 선택해 StartRoom에서 시작한다.
2. 룸 완료는 먼저 현재 `NodeIndex`를 클리어 상태로 기록한다.
3. `BattlePanelTransition`의 화면 덮임 콜백에서 룸을 끄지 않고 지도 선택 표시 상태를 적용한다.
4. 캐릭터는 파티 순서에 따른 왼쪽 가로 슬롯으로 이동하되 전투용 `CurrentGridIndex`는 변경하지 않는다.
5. 룸별 상호작용 UI와 전투 HUD를 끄고 `MapSelectionHUD`를 연다.
6. 지도는 읽기 전용 진행 표시로 사용한다. 노드의 `Button`은 향후 호버 정보 확장을 위해 유지하지만 이동 클릭은 연결하지 않는다.
7. 실제 이동은 현재 노드의 `NextNodeIndices`로 만든 오른쪽 버튼 최대 3개에서만 수행한다.
8. 선택 유효성을 런타임 계층에서 다시 검증한 후 기존 전환으로 다음 룸을 연다.

## 지도 배치

- 진행축은 왼쪽에서 오른쪽이다.
- `Position.x = XStart + LayerIndex * XGap`으로 고정한다.
- 같은 레이어의 노드는 위에서 아래로 고정 간격 배치한다.
- 기존 `XJitter`, `YJitter`와 좌표용 랜덤 호출은 제거한다.
- 연결 생성의 랜덤성은 기존 seed 기반 `BattleRandom`을 유지한다.
- 지도 `ScrollRect`는 가로 이동만 허용하고 현재 또는 다음 선택 가능 노드의 평균 X 위치로 자동 포커스한다.

## 책임 분리

- `MapRuntimeProgressUtility`: 시작 노드와 선택 가능한 다음 노드 조회, 선택 검증.
- `ProceduralMapGenerator`: 고정된 왼쪽→오른쪽 좌표 생성.
- `BattleMapPanel`: 읽기 전용 지도 렌더링과 가로 포커스.
- `BattleNextNodeSelectionPanel`: 최대 3개 선택 버튼 표시와 `NodeIndex` 선택 요청.
- `BattleRoomMapSelectionPresenter`: 활성 룸 유지, 룸 UI 숨김, 캐릭터 표시용 재배치.
- `BattleSceneController`: 룸 완료 결과에서 지도 선택 상태로 전환하고 유효한 노드 선택을 다음 룸 전환으로 연결.

## 멀티플레이 경계

UI는 노드 선택 결과를 직접 확정하지 않는다. 선택 요청은 안정적인 `NodeIndex`로 전달하며 현재 맵 런타임의 연결 관계와 클리어 상태를 검증한 후 상태를 변경한다. 캐릭터 지도 선택용 위치 이동은 표시 전용이며 전투 그리드 상태를 변경하지 않는다. 네트워크 프레임워크는 핵심 로직에 추가하지 않는다.

## 예외 처리

- Start 노드가 없으면 기존 지도 선택 상태를 열고 경고를 남긴다.
- 다음 노드가 3개보다 적으면 필요한 버튼만 표시한다.
- 다음 노드가 없으면 선택 버튼을 모두 숨긴다.
- 잘못되거나 현재 연결에 없는 `NodeIndex` 선택 요청은 무시하고 경고를 남긴다.
- 룸별 UI 또는 캐릭터 앵커 참조가 없으면 가능한 표시 상태는 유지하고 누락 참조를 경고한다.

## 검증

- 새 런에서 Start 노드 자동 선택과 StartRoom 직접 진입.
- 저장된 미완료 노드 복원 유지.
- 좌표 랜덤 제거와 레이어별 X 증가.
- 현재 클리어 노드의 다음 노드만 최대 3개 반환.
- 지도 노드 클릭으로 이동하지 않음.
- 다음 노드 버튼이 `NodeIndex`를 전달함.
- 모든 룸에서 배경 유지, 룸 UI 숨김, 캐릭터 왼쪽 가로 배치.
- 컴파일 및 EditMode 테스트. Unity batchmode는 실행하지 않는다.
