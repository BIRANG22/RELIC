# 거점 스테이지 선택 및 전투 진입 설계

## 목적

거점의 `Position/CentralBase/Play` 월드 스프라이트를 클릭하면 기존 `StageSelectPanel`을 거점 화면 위에 오버레이로 표시한다. 테마 카드를 직접 클릭하면 해당 테마를 확정하고 별도 플레이 버튼 없이 즉시 전투에 진입한다.

## 화면 구성

- 기존 `StageSelectPanel`을 `LobbyMainPanel` 의존 관계에서 분리하여 `PositionPanel` 아래의 오버레이로 이동한다.
- 오버레이는 화면 전체 입력 차단 영역과 기존 `StageSelectPanel`로 구성한다.
- 입력 차단 영역은 뒤쪽 거점 오브젝트 클릭을 막지만 자체 클릭 동작은 수행하지 않는다.
- `StageSelectPanel` 내부에 닫기 버튼을 추가한다.
- 닫기 버튼은 오버레이만 비활성화하며 `LobbyViewState`를 변경하지 않는다.
- 오버레이는 거점 진입 시 기본적으로 닫힌 상태다.

## Play 월드 스프라이트

`PositionStageSelectController`가 다음 동작을 담당한다.

- `Play` 스프라이트 클릭 입력 처리
- 클릭에 필요한 `PolygonCollider2D` 자동 준비
- 스테이지 선택 오버레이 열기
- 닫기 버튼을 통한 오버레이 닫기
- 필수 참조가 없으면 경고 후 안전하게 종료

`Play` 클릭은 화면 표시만 담당하며 맵이나 전투 데이터를 직접 변경하지 않는다.

## 테마 선택과 전투 진입

- 캐러셀 좌우 이동은 테마 미리보기만 변경한다.
- 캐러셀 이동만으로는 전투에 진입하지 않는다.
- 사용자가 테마 카드를 직접 클릭하면 해당 카드의 기존 맵 선택 로직을 먼저 실행한다.
- 선택 적용이 끝나면 기존 `BattlePlayButton.OnClickPlay()`를 호출한다.
- 별도의 UI 플레이 버튼은 사용하지 않는다.
- 잠긴 테마, 허용되지 않은 침식 단계, 파티 인원, 맵 선택 여부, 런타임 전송 및 게임 상태 전환 검증은 기존 `BattlePlayButton` 로직을 그대로 사용한다.
- 전투 진입 검증이 실패하면 기존 경고 UI를 표시하고 `StageSelectPanel`은 열린 상태를 유지한다.

## 기존 로비 기능 호환

- 기존 `StageSelectPanel`, `LobbyStageButtonCarousel`, 테마 카드와 `BattlePlayButton`을 재사용한다.
- 기존 로비의 UI `PlayButton`은 이번 작업에서 삭제하지 않는다. 거점 흐름에서는 직접 사용하지 않는다.
- 로비 상태 전체 제거와 다른 기능 이동은 이번 작업 범위에 포함하지 않는다.

## 검증

- `Position/CentralBase/Play` 클릭 시 거점 화면 위에 `StageSelectPanel`이 열린다.
- 패널이 열린 동안 뒤쪽 `Cha1~3`과 거점 오브젝트가 클릭되지 않는다.
- 패널 바깥 영역 클릭은 아무 동작도 하지 않는다.
- 닫기 버튼으로 패널을 닫고 다시 열 수 있다.
- 캐러셀 이동만으로는 전투에 진입하지 않는다.
- 테마 카드를 직접 클릭하면 해당 테마가 적용되고 기존 검증을 거쳐 전투에 진입한다.
- 전투 진입 검증 실패 시 기존 경고가 표시되고 패널은 유지된다.

## 멀티플레이 경계

새 컨트롤러는 UI 표시와 기존 전투 진입 명령 호출만 담당한다. 맵 선택 데이터와 전투 런타임 상태는 기존 ID 기반 저장소 및 전송 서비스를 계속 사용하며, 월드 스프라이트나 패널 참조를 전투 핵심 상태에 저장하지 않는다.
