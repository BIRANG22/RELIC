# 몬스터 AI 기존 데이터 권위화 구현 계획

## 작업 1: 데이터 기반 이동 범위 API

- `MonsterSkillRangeService`에 `BuildRangeOffsets(MonsterSkillData, bool, RangeDatabase)`를 추가한다.
- 사용자 정의 `SkillRangeData`를 사용한 실패 테스트를 먼저 작성한다.
- 방향 반전, 원점 제외, 누락 데이터의 빈 결과를 검증한다.

## 작업 2: 전체 AI 이동 후보 전환

- 머크, 블롭, 랜서, 블라이트, 베스파, 신더, 드라우그, 바로우, 루크, 모르트, 아라벨라의 정적 이동 좌표 배열을 제거한다.
- 각 AI가 자신의 이동 스킬 데이터를 조회해 공통 API의 후보를 사용하게 한다.
- 정확히 2칸 이동 등 기존 행동 정책 필터는 유지한다.
- 아라벨라 1·2페이즈가 각 이동 스킬의 실제 범위를 따르는 회귀 테스트를 추가한다.

## 작업 3: 공격·특수 거리 중복 제거

- 아라벨라 근접 공격 판정과 바로우 곡사 범위를 스킬 데이터에서 읽는다.
- 루크 돌진 최대 거리는 기존 스킬 데이터의 거리 값에서 읽을 수 있는지 확인 후 교체한다.
- 실행부의 동일 수치 중복도 같은 데이터 소스를 사용하게 한다.
- 데이터에 대응 값이 없는 행동 정책 상수는 유지한다.

## 작업 4: 전수 검사 및 검증

- 전체 몬스터 AI·플래너·실행부의 범위/거리 리터럴을 다시 검색한다.
- 남은 항목을 식별 분기, 행동 정책, 데이터 중복으로 분류하고 데이터 중복만 제거한다.
- 관련 EditMode 테스트, 전체 EditMode 테스트 가능한 범위, `Assembly-CSharp`와 테스트 어셈블리 컴파일을 검증한다.

## 검토 초점

- 범위 데이터가 없을 때 기존 하드코딩으로 잘못 이동하지 않는가.
- 좌우 비대칭 범위가 현재 방향에 맞게 반전되는가.
- 다칸 몬스터의 점유·경로 검사는 기존 방식 그대로 유지되는가.
- 정책상 일부 거리만 선택하는 AI가 데이터 범위를 벗어나지 않는가.
- 예약 시뮬레이션과 실제 실행이 같은 데이터 기반 오프셋을 사용하는가.
