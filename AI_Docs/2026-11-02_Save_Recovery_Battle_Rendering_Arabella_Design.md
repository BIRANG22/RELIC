# 저장 복구·전투 렌더 정렬·아라벨라 등장 연출 설계

## 목표

- 강제 종료 뒤에도 마지막으로 확정된 탐사 상태에서 이어하기가 가능해야 한다.
- 이어하기가 불가능한 저장본은 전투 임시 상태를 로비 런타임에 유출하지 않아야 한다.
- 캐릭터, 몬스터, 그림자, 그리드 효과, 월드 VFX가 동일한 발 위치 기반 정렬 규칙을 사용해야 한다.
- Muck 분열 연출의 포물선 높이가 Blob의 앞뒤 정렬을 변경하지 않아야 한다.
- 아라벨라 등장 연출은 단일 재생 주체가 방향과 클립 순서를 제어해야 한다.

## 조사 결과

### 저장

- 부팅 시 `SaveSystem.TryLoadProgress`가 이어하기 유효성보다 먼저 전체 저장본을 런타임 Store에 적용한다.
- `CanContinueBattle`가 false여도 저장본의 캐릭터·전투 데이터가 이미 적용될 수 있다.
- 저장은 대상 JSON 파일에 직접 덮어써 중간 종료 시 손상 가능성이 있다.
- 강제 종료 이벤트는 보장되지 않으므로 종료 시점 저장만으로 해결할 수 없다.

### 렌더 정렬

- 유닛 본체는 `Unit` Sorting Layer와 `YSortSprite`를 사용한다.
- 다수의 전투 프리팹 그림자는 `Default` Sorting Layer의 고정 order를 사용한다.
- Muck 분열은 Blob 루트 Transform의 Y를 포물선으로 변경하고, `YSortSprite`는 이 시각적 Y를 정렬 좌표로 사용한다.
- 그리드 효과와 월드 VFX는 별도 Y 정렬 유틸리티를 사용하므로 기준값과 offset의 일관성 검사가 필요하다.

### 아라벨라

- `Mon_B_01_appear.controller`의 무조건 전이는 Exit Time과 조건이 모두 없어 Unity가 무시한다.
- `SpriteTransformSequence`가 PlayableGraph로 등장 클립을 직접 재생하고 flip/rotation도 직접 제어한다.
- Controller의 자동 전이를 활성화하면 두 재생 주체가 충돌한다.

## 권장 구조

### 저장 경계

1. 디스크 저장은 임시 파일 작성 후 원본 교체 방식으로 수행한다.
2. 정상 원본이 있으면 교체 전에 백업본으로 보존한다.
3. 원본 읽기 실패 시 백업본을 읽고 원본을 복구한다.
4. 부팅 복원은 저장본 분류 후 적용한다.
   - 유효 탐사: 전체 저장본 적용
   - 비유효 탐사: 전투/맵/Resume/전투 중 캐릭터 상태를 정리한 로비 안전 스냅샷 적용
5. 탐사 중 결과가 확정되는 기존 체크포인트 경계를 유지하고, 저장 파일 쓰기 자체를 중단 안전하게 만든다.

### 렌더 경계

1. 논리적 발 위치를 정렬 기준으로 사용한다.
2. 점프·분열 같은 시각적 오프셋은 Sprite 자식에만 적용하거나 `YSortSprite`의 정렬 좌표를 고정한다.
3. 그림자는 본체와 같은 `Unit` Sorting Layer에서 본체보다 작은 상대 order를 사용한다.
4. 그리드 효과와 VFX는 `BattleWorldVfxSortUtility`를 통해 같은 Y multiplier 규칙을 사용한다.

### 아라벨라 연출 경계

1. 배경 `appear` Animator의 Controller 연결을 제거한다.
2. Animator 컴포넌트는 PlayableGraph 출력 대상으로 유지한다.
3. 클립과 방향은 `SpriteTransformSequence` 단계만 소유한다.

## 검증 기준

- 유효하지 않은 탐사 저장본을 부팅 복원해도 전투 유물과 장착 유물이 로비 상태에 남지 않는다.
- 원본 저장 파일 손상 시 백업 저장본을 읽을 수 있다.
- Muck 분열 중 Blob의 정렬 기준은 목적지 발 위치에서 변하지 않는다.
- 모든 전투 캐릭터/몬스터 그림자는 `Unit` 레이어의 본체 상대 정렬을 사용한다.
- 아라벨라 등장 Controller에 무효 전이가 없고 배경 등장 오브젝트가 Controller를 참조하지 않는다.

## 멀티플레이 경계

저장 복원은 Snapshot 정합성을 강화하며 전투 결과 계산을 변경하지 않는다. 렌더 정렬과 등장 연출은 표현 계층에만 한정한다. Muck의 분열 대상·위치·결과는 기존 전투 상태 흐름을 유지하고 시각적 이동만 분리한다.
