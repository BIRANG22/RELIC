# 탐사 정산 패널 레이아웃 개선 설계

## 목적

`ExplorationResultPanel`을 제공된 레퍼런스처럼 좌측 탐사 요약, 중앙 캐릭터 정보, 하단 획득물, 우측 하단 확인 버튼 구조로 정리한다. 동적 데이터가 로컬라이징 컴포넌트에 덮어써지거나 호버 정보가 기존 레이아웃을 밀어내는 문제도 함께 해결한다.

## 목표

- `클리어`, 하드모드 설명, 레드더스티움 설명 문구를 제거한다.
- 로비의 하드모드 선택 아이콘 리소스를 침식도 표시에서 재사용한다.
- 소요 시간과 로비에서 선택한 난이도 침식 점수를 동적 값으로 확실히 표시한다.
- 캐릭터별 `레벨/경험치 → 초상화 → 유물/스킬` 순서를 고정하고 스킬 아이콘을 키운다.
- 획득 아이템을 DB 아이콘과 수량으로 표시한다.
- 레드더스티움은 아이콘과 `+ 숫자`만 표시한다.
- 보이는 정보 아이콘에만 명확한 호버/클릭 영역을 제공한다.
- 전투 상세 정보는 다른 요소를 밀지 않는 작은 오버레이 패널로 표시한다.

## 비목표

- 보상 계산, 경험치 계산, 맵 진행 및 전투 결과 로직은 변경하지 않는다.
- 캐릭터·아이템·하드모드 아이콘을 새 enum이나 switch로 연결하지 않는다.
- 네트워크 프레임워크나 전투 상태 변경 로직을 추가하지 않는다.

## 확인된 원인

- `ExplorationReportStageName`의 `LocalizedTMPText`가 런타임 플레이타임을 스테이지명으로 다시 덮어쓴다.
- `ExplorationReportStageResult`의 `LocalizedTMPText`가 런타임 침식도를 `클리어`로 다시 덮어쓴다.
- `ExplorationReportAcquiredItemsLabel`의 로컬라이징 원문이 `몬스터 처치`로 남아 있다.
- `ExplorationReportHardModeLabel`에는 과거 `입힌 피해량` 로컬라이징 연결이 남아 있다.
- 상세 정보 오버레이가 캐릭터 행 내부에 남아 있어 행 콘텐츠와 완전히 분리되지 않는다.
- 스킬 슬롯 런타임 배율 `0.42`가 작고 획득 아이템 루트가 가로선 오브젝트를 겸한다.
- 정산패널의 침식도 숫자가 로비 난이도 점수가 아니라 탐사 중 누적되는 `BattleRuntimeData.ErosionValue`를 표시한다.
- 선택 침식 슬롯이 전용 영역이 아니라 `ExplorationReportStagePreview`를 부모로 재사용한다.
- 정산 패널 복구 과정에서 일부 `RectTransform.m_Father`와 부모의 `m_Children` 목록이 서로 달라져 Scene View 피킹 중 Unity 네이티브 크래시가 발생한다.
- 캐릭터 행 루트가 `y: 300`으로 올라가 레퍼런스보다 높게 배치된다.
- 정보 아이콘 이벤트가 행에 전달된 뒤 화면 좌표 포함 여부를 다시 판정해 정상적인 아이콘 포인터 이벤트도 누락될 수 있다.

## 접근 방식

1. **씬 중심 재구성 + 최소 바인딩 코드 수정(선택)**: 고정 UI는 Battle 씬에 명시적으로 배치하고 스크립트는 DB 조회와 값 바인딩만 담당한다. 아트 조정이 쉽고 프로젝트 규칙에 가장 잘 맞는다.
2. 런타임 전면 생성: 구현은 빠르지만 씬에서 위치와 리소스를 조정하기 어렵고 명시적 참조 원칙에 맞지 않는다.
3. 패널 전체 프리팹 재작성: 장기 재사용에는 유리하지만 현재 변경 범위보다 크고 기존 씬 변경과 충돌 위험이 높다.

## 선택 설계

- 1번 방식을 사용한다.
- 동적 TMP에는 고정 문구용 로컬라이징 컴포넌트를 두지 않는다.
- 하드모드 아이콘은 Lobby 씬 `Erosion_Select/Icon`이 사용하는 스프라이트를 재사용한다.
- 획득 아이템 루트와 구분선을 분리한다.
- 캐릭터 상세 정보는 정산패널 최상위의 공용 오버레이 루트에 배치한다. 행은 표시할 통계와 기준 아이콘 위치만 전달하며, 오버레이 활성화가 행의 자식 수·크기·위치를 바꾸지 않게 한다.
- 정보 아이콘은 기존 프로젝트의 `question.png`를 사용하며 아이콘 Rect 자체가 포인터 대상이 된다.
- 정보 아이콘 전용 포인터 컴포넌트만 행의 상세 정보 API를 호출한다. 행 전체에서는 포인터 인터페이스를 제거해 중복 버블링과 재판정을 막는다.
- 세 캐릭터 행은 동일한 부모에서 `x: -325/0/325`, `y: 0`을 사용하고 공통 부모를 `y: 120`에 배치한다.
- 숨겨진 레거시 통계 텍스트도 부모·자식 참조를 양방향으로 유지해 에디터 피킹 안정성을 보장한다.
- 통계 오버레이는 정보 아이콘의 하단 중앙을 기준으로 12px 아래에 배치하고, 패널 경계를 넘는 경우에만 내부로 보정한다.
- 패널 로컬 좌표를 오버레이의 좌측 상단 앵커 기준 `anchoredPosition`으로 변환해 좌측 상단으로 이중 이동하지 않게 한다.
- 로비 난이도 침식 점수는 `SelectedErosionDifficultyIds`의 각 `ErosionData.Score` 합계로 계산한다. 탐사 중 누적되는 `ErosionValue`는 정산패널에 표시하지 않는다.
- 침식 영역은 붉은 침식 아이콘과 총점, 선택한 난이도 아이콘 격자로 구성한다. 각 선택 아이콘에는 `ErosionData.Tier`의 `I/II/III` 배지를 겹쳐 종류와 단계를 함께 표시한다.
- 침식 아이콘은 로비에서 캐시한 실제 표시 스프라이트를 우선하고 `ErosionIconDatabase`를 fallback으로 사용한다.
- 아이콘 데이터는 기존 `CharacterIconDatabase`, `RelicIconDatabase`, `SkillIconDatabase`, `ErosionIconDatabase` 및 가방 아이템 DB 흐름을 유지한다.

## 제약

- 문서는 `AI_Docs`에만 둔다.
- 테스트는 `Assets/Tests/EditMode~/`에만 둔다.
- Unity 에디터가 열려 있으므로 batchmode 테스트는 실행하지 않는다.
- 씬/프리팹 참조를 우선하고 이름 검색은 기존 호환 바인딩에만 남긴다.

## 멀티플레이 경계

정산 데이터의 생성·보상·상태 변경에는 손대지 않고 이미 확정된 런타임 결과를 UI에 표시하는 부분만 변경한다. 따라서 `Command -> State Change -> Result/Event` 전투 경계에는 영향이 없다.
