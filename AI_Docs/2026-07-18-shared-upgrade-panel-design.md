# 공용 강화 패널 설계

## 목표

로비와 배틀씬이 하나의 `UpgradePanel.prefab` 외형을 공유하되, 각 씬의 강화 규칙과 런타임 데이터는 기존처럼 분리한다.

## 구조

- 공용 프리팹에는 패널 계층, 스킬 아이콘 목록, 상세 정보, 휠, 강화 및 닫기 버튼을 둔다.
- `SkillUpgradePanelContextSelector`가 활성 씬을 판별해 로비에서는 `LobbySkillUpgradePanelUI`, 배틀에서는 `SkillUpgradePanel`만 활성화한다.
- 버튼 이벤트는 활성 컨트롤러가 런타임에 직접 바인딩해 씬 오브젝트의 영구 이벤트에 의존하지 않는다.
- 배틀의 `RestRoomController`는 프리팹 인스턴스의 `SkillUpgradePanel`을 계속 참조한다.

## 규칙 보존

- 로비: BlueDustium 가격 증가, 횟수 제한 없음, 성공 후 패널 유지, 로비 런타임 사용.
- 배틀: 기존 휴게실 1회 제한, 배틀 런타임 사용, 완료 연출 및 기존 닫기 흐름 유지.
- 전투 계산과 UI 컨텍스트 선택은 분리하며 배틀 데이터 구조는 변경하지 않는다.

## 검증

- 같은 프리팹 GUID가 로비와 배틀씬에 존재하는지 검사한다.
- 두 컨트롤러 중 씬에 맞는 하나만 활성화되는지 테스트한다.
- `RestRoomController.upgradePanel` 참조가 공용 프리팹의 배틀 컨트롤러를 가리키는지 검사한다.
- 배틀 강화 제한 및 로비 가격 정책 회귀 테스트를 유지한다.
