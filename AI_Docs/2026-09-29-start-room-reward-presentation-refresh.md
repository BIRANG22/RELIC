# 시작 노드 보상 표시 갱신 수정

## 문제

시작 노드에서 공격 외 선택지로 생성된 보상은 유효한 `RewardId`를 가지고 있어도, 생성 시점의 이름과 아이콘이 이미 채워져 있으면 보상 패널이 DB 조회를 생략했다. 이 때문에 `미번역` 같은 임시 문자열이나 잘못된 아이콘 상태가 그대로 표시될 수 있었다.

## 설계

- 아이템, 유물, 기억 보상은 보상 패널을 열 때마다 `RewardId`를 정규화하고 현재 DB 및 선택 언어를 기준으로 이름과 설명을 다시 계산한다.
- 아이콘은 각 아이콘 DB를 우선 사용하고, 기억 데이터에 직접 연결된 아이콘도 대체 경로로 사용한다.
- 아이콘 조회 실패가 기존의 유효한 아이콘을 `null`로 덮어쓰지 않게 한다.
- 더스티움과 빈 `RewardId`는 기존 표시 흐름을 유지한다.
- 엑셀 원본과 빈 번역 셀 정책은 변경하지 않는다.

## 구현 및 검증 계획

1. ID 기반 보상이 캐시된 표시값과 무관하게 갱신 대상인지 검증하는 EditMode 회귀 테스트를 추가한다.
2. `BattleRewardPanelUI`의 조건부 갱신을 ID 기반 보상 전체 갱신으로 변경한다.
3. 런타임 및 에디터 C# 프로젝트를 컴파일한다.
4. Unity 에디터가 열린 환경이므로 batchmode 테스트는 실행하지 않고, 필요 시 Unity Test Runner에서 회귀 테스트를 확인한다.
