# Battle Camera Impact Beats Design

## Intent

모든 피해 공격에 공통된 끊김을 주되, 근접/원거리와 타격 방향에 따라 카메라 반응을 달리해 충돌의 몰입감을 높인다. 기존의 연속 노이즈 중심 임팩트를 `접촉 직전 압축 -> Impact Lock -> 방향성 반동 -> 오버슈트 복귀` 비트로 재구성한다.

## Goals

- 모든 실제 피해 명중은 짧고 명확한 충돌 비트를 갖는다.
- 근접 공격은 강한 압축과 방향성 반동, 원거리 공격은 약한 압축과 짧은 반동을 사용한다.
- 공격자와 대상의 상대 위치 또는 커맨드 방향을 이용해 반동 방향을 안정적으로 결정한다.
- 기존 줌, 히트스톱, 다단/연속 행동 그룹 정책을 유지한다.
- 기획/아트가 인스펙터에서 비트 강도와 시간을 조절할 수 있게 한다.

## Non-goals

- 스킬별 데이터베이스나 신규 네트워크 동기화 데이터를 추가하지 않는다.
- 애니메이션 이벤트, VFX 완료 여부로 전투 결과를 결정하지 않는다.
- 전투 데미지, 타겟, 넉백 판정을 변경하지 않는다.

## Findings

- `BattleCameraController`가 공격자 줌, Z 임팩트, 히트스톱, 셰이크, 복귀를 담당한다.
- `BattleHitImpactFeedback`는 공격자/대상/방향 정보를 이미 받아 캐릭터 밀림과 카메라 임팩트를 동시에 실행한다.
- 현재 카메라 임팩트에는 수평 타격 방향이 전달되지 않으며, 줌 인/노이즈 셰이크/줌 아웃이 연속적으로 이어진다.
- 다단 공격은 마지막 내부 타격, 연속 행동 그룹은 그룹 경계에서만 강한 외부 임팩트를 재생하도록 이미 제한된다.

## Approaches

1. 스킬별 완전 수동 카메라 데이터: 개성은 가장 크지만 현재 요청보다 데이터/호출부 변경 범위가 크다.
2. 근접/원거리 고정 연출: 구현은 단순하지만 공격 방향과 충돌 리듬 차이가 약하다.
3. 공통 비트 + 공격 유형/방향 보정: 기존 호출 구조를 유지하면서 근접/원거리 강도와 좌우 반동을 구분할 수 있다. 이번 구현에서 선택한다.

## Recommended Design

- 근접 피해 카메라 API에 정규화된 수평 방향 `-1` 또는 `1`을 전달한다.
- 압축 비트는 충돌 방향으로 짧게 이동하면서 기존 Z 줌을 함께 수행한다.
- Impact Lock은 기존 히트스톱과 VFX 일시정지를 유지한다.
- 반동 비트는 충돌 반대 방향으로 빠르게 이동한다.
- 복귀 비트는 기준점을 조금 지나치는 오버슈트와 최종 정착의 두 구간으로 나눈다.
- 원거리 피해는 방향 정보가 없는 기존 호출을 유지하고, 방향성 XY 이동 없이 약한 Z 압축과 짧은 복귀 비트를 사용한다.
- 노이즈 셰이크는 기존 기능을 보존하되 방향성 킥 위에 작은 질감으로만 겹친다.
- 모든 새 값은 `BattleCameraController`의 인스펙터 직렬화 필드로 제공한다.

## Default Tuning

- 근접 압축 X: `0.08`, 반동 X: `0.16`, 오버슈트 X: `0.035`
- 압축 시간: `0.035s`, 반동 시간: `0.045s`, 정착 시간: `0.09s`
- 방향 값이 없거나 0이면 오른쪽(`1`)을 안전한 기본값으로 사용한다.
- 원거리 공격은 기존 Z 값과 시간을 유지하며 XY 방향성 킥을 적용하지 않는다.

## Testing

- EditMode 테스트에서 방향 정규화, 압축/반동/오버슈트 오프셋 부호, 0 이하 강도 클램프를 검증한다.
- 기존 카메라/피격 피드백 테스트와 C# 프로젝트 컴파일을 검증한다.
- Unity 에디터 화면의 실제 타격감과 인스펙터 튜닝은 수동 확인 대상으로 남긴다.

## Multiplayer Boundary

카메라와 피격 연출 계층만 변경한다. 전투 Command, 상태 변경, 결과 이벤트, 랜덤, 네트워크 동기화 데이터에는 영향이 없다.
