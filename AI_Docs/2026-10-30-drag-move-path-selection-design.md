# 드래그 이동 경로 선택 설계

## 목적

기존 클릭 최단 경로 이동을 유지하면서, 이동 칸을 누른 채 인접 칸을 드래그하면 사용자가 지나간 경로 그대로 이동을 예약할 수 있게 한다.

## 현재 구조

- `GridCell.OnMouseDown`이 즉시 `GridManager.OnCellClicked`를 발생시킨다.
- `PlayerSkillReservationController`는 클릭된 목적지의 첫 번째 예약 가능 최단 경로를 즉시 확정한다.
- `PlayerReservedCommand`는 `VisualMoveSteps`에 전체 이동 스텝을 이미 보존하므로 실행 및 네트워크 모델은 드래그 경로도 표현할 수 있다.

## 선택한 설계

- 이동 선택 중 포인터 다운 시 클릭된 칸까지 기존 최단 경로를 드래그 세션의 초기 경로로 복사한다.
- 기존 클릭 이벤트는 드래그 세션 중 즉시 예약하지 않고, 포인터 업에서 초기 경로를 확정한다. 결과는 기존 클릭 이동과 같다.
- 누른 상태로 인접한 유효 칸에 진입하면 해당 칸을 경로 끝에 추가한다.
- 이미 경로에 포함된 칸으로 돌아가면 그 칸 이후의 경로를 제거한다.
- 장애물, 점유 칸, 그리드 밖, 이동 비용 또는 예약 슬롯 한도를 넘는 추가는 거부하고 현재 경로를 유지한다.
- 포인터 업 시 마지막 경로를 기존 `BuildMoveReservationCommands`와 `ConfirmCommands`에 전달한다.
- 이동 선택 이외의 스킬과 유물 타기팅은 기존 클릭 흐름을 유지한다.

## 입력 및 상태 경계

- `GridCell`은 포인터 다운·업을 `GridManager`에 통지만 한다.
- `PlayerSkillReservationController`가 드래그 세션과 경로를 소유한다.
- 경로 추가·되돌리기 규칙은 Scene Object와 분리된 순수 `MoveDragPathState`에서 처리한다.
- 프리뷰는 드래그 경로의 이동 스텝을 그대로 재생하며 전투 결과를 계산하지 않는다.

## 고려한 대안

- 매 호버 칸마다 새로운 최단 경로를 계산하면 사용자가 그린 경로를 보존하지 못해 제외한다.
- 드래그 전용 새 예약 명령 타입은 기존 명령이 전체 스텝을 이미 저장하므로 불필요해 제외한다.

## 검증

- 인접 칸 추가, 비인접 칸 무시, 이전 칸 복귀 시 접미 경로 제거를 EditMode 테스트로 검증한다.
- 기존 클릭 경로는 초기 최단 경로가 릴리스 시 그대로 확정되는 호출 구조를 확인한다.
- 런타임과 EditMode 테스트 어셈블리 컴파일을 확인한다.
