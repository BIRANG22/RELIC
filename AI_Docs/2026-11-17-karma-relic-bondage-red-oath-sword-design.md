# 카르마 유물·속박·붉은 서약검 수정 설계

## 의도

- 카르마를 사용하는 기억용 유물은 스킬 분류가 아니라 실제 소비 자원을 기준으로 발동한다.
- 니아의 불꽃은 범위 내 몬스터에게 속박을 부여하고, 속박된 몬스터의 다음 이동을 취소한다.
- 붉은 서약검은 공격 기억이 실제 사용하는 자원의 소모량을 1 증가시키고 피해량을 2 증가시킨다.

## 범위

- `Relic_P_59` 사슬낫, `Relic_P_60` 마력 렌즈, `Relic_P_61` 마력 수정의 조건을 `ReferenceResource.UniqueResource`로 통일한다.
- `BondageEffect`가 명시적 `PlayerTarget` 또는 `MonsterTarget`에만 상태를 부여하도록 변경한다.
- 붉은 서약검은 새 효과 ID `E_Attack_Resource_Cost_Delta`를 사용하며 공격 기억의 `ReferenceResource`에 따라 HP, 마나, 카르마 중 하나에 비용 증가를 적용한다.
- `X` 가변 비용 공격은 추가 소모량을 먼저 확보하고 남은 자원으로 `X`를 다시 계산한다. 카르마 3의 제네시스는 `X=2`, 최종 소모량 3으로 처리한다.
- 붉은 서약검의 피해 증가 `E_Attack_Value_Delta` 2는 유지한다.
- 런타임 CSV의 효과 이름·설명을 실제 동작과 일치시킨다.

## 비범위

- 공용 `AddStatusToDefaultTarget`의 전역 우선순위는 변경하지 않는다.
- 다른 비용 증감 유물과 룬의 의미는 변경하지 않는다.
- 네트워크 프레임워크나 전역 전투 상태 구조는 추가하지 않는다.

## 접근 방식

1. 채택: 의미가 명확한 새 효과 ID와 소비 자원 기반 비용 분배를 사용한다. 기존 `Cost`가 마나를 의미하는 코드 관례를 보존하면서 붉은 서약검만 정확히 확장할 수 있다.
2. 미채택: 기존 `E_Attack_Cost_Delta`의 의미를 모든 자원으로 바꾼다. 수정량은 적지만 효과 ID와 실제 동작이 어긋나고 이후 마나 전용 효과와 충돌할 수 있다.

## 판정 및 데이터 흐름

- 유물 조건: `PlayerReservedCommand.SkillData.ReferenceResource`를 읽어 상태 변경 전에 결정한다.
- 비용 변경: 예약 Command가 가진 기본 비용을 초기화한 뒤 실제 소비 자원 필드 하나에만 델타를 적용한다.
- 가변 비용 변경: 이미 적용된 비용 보정과 붉은 서약검 추가 비용을 가용 자원에서 제외한 예산으로 `ResolvedX`, 효과 수치 및 횟수를 함께 다시 계산한다.
- 속박: 효과 컨텍스트의 명시적 대상에게 상태를 추가하고, 몬스터 이동 Command 실행 직전에 기존 `TryConsumeOnTrigger`가 상태를 소비하며 이동을 취소한다.
- UI/VFX/사운드는 판정을 수행하지 않고 기존 결과를 표시한다.

## 검증

- EditMode 테스트로 카르마 소비/비소비 조건, 속박 대상, HP·마나·카르마 비용 분배와 비공격 미적용을 검증한다.
- Assembly-CSharp와 Assembly-CSharp-Editor를 컴파일한다.
- Unity 에디터 화면 및 실제 전투 연출은 직접 제어하지 않으며 미검증 항목으로 남긴다.

## 멀티플레이 경계

모든 변경은 Command의 안정적인 스킬 데이터와 런타임 상태를 기준으로 결정된다. Scene Object나 UI 상태를 전투 판정 근거로 추가하지 않으므로 멀티플레이 구조 영향은 없다.
