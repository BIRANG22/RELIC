# 그리드 효과 미리보기 툴팁 호버 설계

## 의도

아라벨라 낙인(`GR_Stigma`) 배치 미리보기에서도 실제 배치된 그리드 효과와 동일하게 이름과 설명 툴팁을 확인할 수 있게 한다.

## 원인

`BattleGridEffectController.TryCreatePlacementPreview`는 미리보기의 전투 상호작용을 막기 위해 모든 Collider/Collider2D를 비활성화한다. 이후 `GridEffectHoverTarget.Attach`가 호출되지만 기존의 비활성 `BoxCollider2D`를 호버 대상으로 선택하며, `Update`는 비활성 콜라이더에 대해 호버 판정을 중단한다. `Attach`에 전달되는 `fallbackSize`는 현재 사용되지 않는다.

## 목표와 비목표

- 미리보기의 기존 `BoxCollider2D`를 trigger 호버 영역으로 재활성화한다.
- 별도 fallback 자식을 만들지 않고 프리팹에 작성된 크기와 위치를 보존한다.
- 전투 명령 실행 중에도 읽기 전용 그리드 효과 툴팁을 표시한다.
- 실제 배치된 그리드 효과의 기존 활성 콜라이더 동작은 변경하지 않는다.
- 툴팁 외 전투 상태, VFX 표현, 충돌 판정은 변경하지 않는다.

## 검토한 접근

1. 기존 콜라이더를 trigger로 재활성화: 프리팹의 작성된 호버 영역을 그대로 사용하며 Inspector에서도 활성 상태를 확인할 수 있어 채택한다.
2. `fallbackSize` 기반 전용 자식 콜라이더 생성: 루트 스케일의 영향을 받아 의도보다 작은 영역이 생길 수 있고 원본은 계속 꺼져 있어 제외한다.
3. 프리팹 직접 수정: 특정 프리팹만 고치며 공통 미리보기 생성 경로의 재발을 막지 못해 제외한다.

## 설계

`GridEffectHoverTarget`은 기존 `BoxCollider2D`가 비활성 상태여도 찾아서 trigger로 전환하고 활성화한다. 새 콜라이더는 기존 콜라이더가 전혀 없을 때만 `fallbackSize`로 생성한다. `GridEffectTooltipUI`는 전투 종료 상태만 차단하고 `BattleTurnExecutor.IsExecuting`은 표시 차단 조건으로 사용하지 않는다. 두 변경 모두 읽기 전용 표시 경로이며 전투 명령이나 상태 변경에는 관여하지 않는다.

## 검증

EditMode 회귀 테스트로 비활성 원본 콜라이더가 동일 크기의 trigger로 재활성화되는지 확인한다. 이후 프로젝트 컴파일과 변경 파일 정적 검사를 수행한다.

## 겹친 호버 소유권

낙인은 월드 기준 약 `2 x 1.2`, 거미줄은 약 `1.64 x 0.385`의 호버 영역을 사용한다. 인접하거나 겹친 영역에서 거미줄이 툴팁 소유권을 가져간 뒤 이탈해도 낙인은 계속 호버 상태라 `false -> true` 전환이 다시 발생하지 않았다. 각 호버 대상에 진입 순서를 기록하고 마지막으로 진입한 대상을 우선한다. 현재 우선 대상이 이탈하면 아직 호버 중인 직전 대상을 즉시 복구한다. 툴팁 위치 갱신도 현재 소유자만 수행한다.
