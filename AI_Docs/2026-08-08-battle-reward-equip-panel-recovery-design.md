# 전투 보상 장착 패널 복구 설계

## 목표

전투 보상 `Equip_panel`에서 장착 불가 상태를 거친 뒤에도 다른 유효한 캐릭터를 선택하여 기억 또는 유물을 정상 장착할 수 있게 한다. `Char1~3` 카드 전체를 공통 선택 영역으로 사용하고, `Delete_Button`은 기억은 무보상 포기, 유물은 구매가의 30%를 잔재로 지급한 뒤 보상 흐름을 완료한다.

## 조사 결과

- 현재 캐릭터 카드 클릭은 유물 슬롯만 자동 선택하며, 기억은 내부 스킬 슬롯을 별도로 눌러야 한다.
- 확인 버튼은 저장된 선택 인덱스만 검사하고 실제 런타임 슬롯 상태는 적용 단계에서 다시 검사한 뒤 조용히 종료한다.
- 장착 성공 시 비활성화된 `Delete_Button`이 다음 `Open`에서 다시 활성화되지 않는다.
- 지원하지 않는 전용 기억 슬롯도 클릭 가능한 것처럼 표시된다.
- 카드 및 슬롯 이벤트 등록에서 `RemoveAllListeners`를 사용하여 다른 리스너를 제거할 수 있다.

## 권장 구조

캐릭터 카드 클릭을 보상 종류별 선택 명령으로 통일한다.

- 유물: 선택한 캐릭터의 호환 빈 슬롯을 다시 탐색한다.
- 기억: 자유 슬롯(런타임 2, 3) 중 빈 슬롯을 우선하고, 없으면 교체 가능한 기억이 있는 첫 슬롯을 선택한다.
- 선택할 수 없으면 선택 인덱스를 비우고 확인 버튼을 비활성화한다.
- 확인 직전에도 같은 규칙으로 현재 선택이 유효한지 검증하여 오래된 선택 상태로 저장하지 않는다.
- 패널을 열 때 Confirm/Delete 상호작용 상태를 항상 현재 보상 기준으로 초기화한다.
- 내부 기억 슬롯 클릭은 선택 정밀 조정용으로 유지하되 지원되는 슬롯만 상호작용할 수 있다.

## 삭제 처리

- 기억: 런타임 보상이나 재화를 추가하지 않고 보상 완료 콜백만 실행한다.
- 유물: 기존 `LobbyRelicPricePolicy` 구매가에 `relicExtractionRate` 30%를 내림 계산하여 잔재에 더하고 완료한다.
- 두 경로 모두 콜백은 한 번만 실행한다.

## 테스트 및 검증

- 기억 자동 슬롯 선택 정책: 빈 슬롯 우선, 교체 가능 슬롯 대체, 불가능한 경우 실패.
- 캐릭터 카드 전체에 Button이 연결되고 지원하지 않는 기억 슬롯은 비활성화됨.
- 패널 재개방 시 삭제 버튼이 다시 활성화됨.
- 유물 추출률 30%와 기억 무보상 삭제 경로를 회귀 검증.
- Unity 에디터가 열려 있으므로 batchmode는 사용하지 않고 C# 프로젝트 빌드로 컴파일을 검증한다.

## 멀티플레이 경계

이번 변경은 로컬 보상 선택 UI와 기존 런타임 저장소 호출을 안정화하며 새로운 네트워크 프레임워크나 전역 상태를 추가하지 않는다. 향후 동기화 시 선택 결과는 CharacterId, SkillId, RelicId와 슬롯 인덱스로 전달할 수 있는 기존 경계를 유지한다.
