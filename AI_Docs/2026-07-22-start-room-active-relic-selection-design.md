# StartRoom 액티브 유물 선택 설계

## 목표

StartRoom의 유물 선택지가 숫자 범위나 씬 인스펙터 설정에 의존하지 않고, 현재 `RelicDatabase`에 등록된 액티브 유물 전체를 자동으로 후보로 사용하도록 한다.

## 접근 방식

### 채택안: DB 전체 조회 후 액티브 ID 필터링

- `RelicDatabase.GetAll()` 결과를 조회한다.
- `FragmentId`가 `Relic_A_`로 시작하는 유물만 후보로 추가한다.
- 이미 보유하거나 장착한 유물은 기존 로직으로 제외한다.
- 남은 후보를 섞고 `choiceCount`만큼 표시한다.

이 방식은 액티브 유물 ID가 추가되거나 삭제되어도 씬의 최소·최대 번호를 수정할 필요가 없다.

### 제외안

- `relicIdPrefix = Relic_A_`, 숫자 범위 `1~15`: 현재 문제는 해결하지만 새 액티브 유물이 추가될 때마다 범위를 갱신해야 한다.
- `Type == Active`만 검사: 의미상 명확하지만 이번 요청은 액티브 유물 ID가 확실히 구분된다는 전제를 사용하므로 ID 접두사 기준이 더 직접적이다.

## 코드 변경

- `RelicChoiceAreaUI`에서 숫자 범위 설정 필드와 분기 로직을 제거한다.
- 액티브 유물 판별용 `Relic_A_` 접두사를 한 곳에 정의한다.
- DB 전체에서 액티브 유물만 수집하는 로직을 사용한다.
- `Battle.unity`, `DebugBattle.unity`에 남은 직렬화된 숫자 범위 값은 더 이상 동작에 영향을 주지 않도록 제거한다.

## 테스트

- StartRoom 선택 로직이 `Relic_A_` 유물만 후보로 포함하는지 검증한다.
- 번호가 연속되지 않아도 액티브 유물이 포함되는지 검증한다.
- 패시브 유물과 다른 ID는 제외되는지 검증한다.
- Battle/DebugBattle 씬이 제거된 숫자 범위 설정을 보유하지 않는지 검증한다.

Unity 에디터가 열려 있으므로 batchmode 테스트는 실행하지 않고, 가능한 정적 검증과 MSBuild 컴파일을 수행한다.

## 멀티플레이 경계

이번 변경은 선택 후보 생성과 UI 표시 범위에만 영향을 주며 전투 상태 변경, 랜덤 결과 기록 구조, 네트워크 경계는 변경하지 않는다.
