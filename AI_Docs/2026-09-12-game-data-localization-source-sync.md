# 게임데이터 로컬라이제이션 원문 동기화

## 문제

`Localization Manager`의 게임데이터 전체검사는 기존 키의 한국어 원문이 바뀌어도 기존 행을 갱신하지 않고, 원문 해시가 붙은 새 키를 추가한다. 런타임은 `data.{sheet}.{id}.{field}` 안정 키만 조회하므로 새 해시 키는 소비되지 않고 기존 번역이 계속 표시된다.

## 결정

게임데이터 문구의 정체성은 원문 문자열이 아니라 `시트 + 안정 ID + 표시 필드`다. 전체검사는 해당 안정 키를 기본 키로 사용하며, 같은 검사에서 동일한 안정 키가 여러 번 등장하는 구조적 중복(Event 선택지 등)에만 원문 해시를 붙인다.

기존 키의 `Korean(ko)`가 게임데이터 원문과 다르면 적용 단계에서 해당 셀을 갱신한다. 의미가 달라질 수 있는 다른 언어 번역 열은 비워 `Untranslated` 상태로 만들어 재번역을 요구한다. `Key`와 `Id`는 보존한다.

## 적용 범위

- `LocalizationManagerWindow`: 게임데이터 후보의 새 항목/원문 변경을 구분하고, 과거 워크북 키 존재만으로 해시 키를 만들지 않는다.
- `LocalizationWorkbookWriter`: 기존 워크북 행의 한국어 원문을 갱신하고 번역 열을 비운다.
- EditMode 회귀 테스트: 안정 키 원문 변경 시 번역 초기화와 ID 보존을 검증한다.
- 전체 정리: 워크북·String Table 키를 코드, 씬, 프리팹, 게임데이터의 실제 소비 키와 대조한다. 어느 소비처에도 없는 키만 제거하며, 삭제 전후 키 목록과 개수를 검증한다.
- 정적 TMP 편집: 인스펙터의 현재 `text`와 게임데이터만 원문으로 사용한다. `koreanSource`는 키 연결 후 기록되는 결과값이며, 후보 판단에 사용하지 않는다. 기존 키는 워크북의 한국어 원문이 현재 입력값과 일치할 때만 재사용하고, 아니면 같은 원문 키를 찾거나 새 키를 만든다.
- 적용 순서: 워크북 추가·갱신 후 Import하고 TMP를 재연결한다. 이후 실제 참조를 다시 수집해 미사용 기존 키를 삭제하고, 빈 행/사용 범위를 압축한 뒤 최종 Import한다.
- 워크북 정리: 전체검사·적용 마지막에 A열(`Key`)이 비어 있는 데이터 행을 제거하고 남은 행을 연속 행 번호로 재배치한다.

## 제외 범위

- 정적 TMP 바인딩 복구 동작은 변경하지 않는다.
