# 이벤트룸 런 지속 스탯 보너스 설계

## 배경

`Event_01` 3번 선택지 데이터는 `RollTable / 파티 전원 최대 체력 / RT002`로 정상 로드된다.
선택지 실행 서비스도 파티 캐릭터의 `MaxHP`를 즉시 증가시키지만, 다음 배틀룸 입장 시 `BattleEquipmentEffectService.ApplyBattleStartEffects`가 마스터 데이터 기반으로 `MaxHP`를 다시 계산하면서 이벤트 증가분이 사라진다.

## 목표

- 이벤트 선택지로 얻은 최대 체력 보너스가 다음 배틀룸에서도 유지된다.
- 장비, 룬, 상태 효과로 계산되는 전투 시작 보너스는 전투방 입장마다 중복 누적되지 않는다.
- 최대 코스트 이벤트/실패 결과도 같은 덮어쓰기 문제를 피한다.

## 권장 구조

`CharacterRuntimeData`에 런 지속 보너스 값을 명시적으로 저장한다.

- `RunMaxHPBonus`: 이벤트 등 런 진행 중 획득한 최대 체력 보너스.
- `RunMaxCostBonus`: 이벤트 등 런 진행 중 획득한 최대 코스트 보너스.

`EventChoiceExecutionService`의 파티 최대 체력/최대 코스트 변경은 현재 전투 표시를 위해 `MaxHP`/`MaxCost`도 즉시 갱신하되, 런 지속 보너스 필드도 같이 변경한다.

`BattleEquipmentEffectService.ApplyBattleStartEffects`는 아래 순서로 최종 전투 시작 스탯을 계산한다.

1. 마스터 기본값을 기준값으로 사용한다.
2. 런 지속 보너스를 기준값에 더한다.
3. 장비/룬/상태 기반 보너스를 더한다.
4. 현재 HP는 사망자는 1로 부활, 생존자는 기존 체력 비율/완전 회복 상태를 보존한다.

## 멀티플레이 경계

이번 변경은 캐릭터 ID에 연결된 런타임 데이터 필드만 변경한다. UI/VFX/사운드는 결과를 계산하지 않고 선택 결과 이벤트만 표시하며, 상태 변경은 `EventChoiceExecutionService`와 전투 시작 계산 서비스에 남긴다.

## 검증

- `RT002` 실행 후 `RunMaxHPBonus`, `MaxHP`, `CurrentHP`가 증가하는지 테스트한다.
- 전투 시작 효과 적용 후 마스터 기본 최대 체력으로 덮이지 않고 런 보너스가 보존되는지 테스트한다.
- 장비 최대 체력 보너스가 전투 시작마다 중복 누적되지 않는지 테스트한다.
