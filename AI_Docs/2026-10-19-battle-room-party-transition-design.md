# 전투방 파티 진입·퇴장 이동 연출 설계

## 목적

배틀씬의 전투 노드 진입·퇴장 시 기존 화면 페이드와 전환 위치는 유지하면서, 플레이어 캐릭터 3명이 동시에 걷는 이동 연출을 추가한다.

- 진입: 화면 왼쪽에서 각 캐릭터의 배치 그리드 위치까지 이동한다.
- 퇴장: 현재 서 있는 위치에서 화면 오른쪽 방향으로 이동한다.
- 기존 페이드인·페이드아웃의 시작과 종료 시점은 변경하지 않는다.
- 이벤트·휴식·시작 노드의 별도 월드 캐릭터에는 적용하지 않는다.

## 핵심 원칙

이 기능은 전투 결과를 계산하지 않는 표현 계층이다. `CurrentGridIndex`, 그리드 점유, HP, 턴, 명령 또는 노드 완료 상태를 변경하지 않는다. 캐릭터 GameObject의 Transform과 SpriteRenderer 표시 상태, 걷기·대기 애니메이션만 제어한다.

전투 노드 전환의 기존 흐름은 그대로 유지한다.

`노드 선택 → 화면 가림 → 전투방 구성/캐릭터 스폰 → 화면 열림`

`전투방 완료 → 화면 가림 → 맵 복귀 → 화면 열림`

파티 이동 연출은 이 흐름의 화면 열림 또는 가림 구간에 병렬로 실행한다.

## 구조

### BattleRoomPartyTransitionPresenter

전투방 루트에 배치하는 표현 전용 MonoBehaviour다.

책임:

- 활성 전투방에 속한 살아 있는 플레이어 `BattleCharacter` 수집
- 캐릭터별 연출 시작 위치, 원래 위치, 퇴장 목표 위치 기록
- 모든 캐릭터의 동시 이동 및 알파 보간
- 이동 시작 시 `BattleUnitAnimator.PlayMove()` 호출
- 이동 완료·취소·비활성화 시 `PlayIdle()`과 원래 표시 상태 복구
- 중복 진입·퇴장 요청 방지 및 진행 중 연출 취소 처리

인스펙터 설정:

- `entryOffset`: 최종 그리드 위치를 기준으로 한 진입 시작 월드 오프셋. 기본값은 왼쪽 방향이다.
- `exitOffset`: 현재 위치를 기준으로 한 퇴장 목표 월드 오프셋. 기본값은 오른쪽 방향이다.
- `entryDuration`, `exitDuration`: 기존 전환 구간과 맞출 이동 시간.
- `entryCurve`, `exitCurve`: 위치 보간 커브.
- `fadeCharacters`: 기존 캐릭터 페이드가 별도 구현되어 있지 않을 경우 SpriteRenderer 알파를 함께 보간하는 옵션.

캐릭터 목록은 `BattleRoom` 자식 범위에서만 찾고 몬스터는 제외한다. `CharacterId`나 `CurrentGridIndex`를 변경하지 않는다.

### BattleRoomLoader 연동

캐릭터 스폰과 그리드 배치가 완료된 시점에 진입 연출을 준비한다. Presenter는 이 시점의 월드 위치를 최종 위치로 캡처한 뒤 캐릭터를 `entryOffset`만큼 옮긴다.

전투 입력은 기존 로더가 허용하는 시점보다 빨라지지 않는다. 진입 이동이 아직 진행 중이면 입력 준비 완료를 Presenter 완료 이후까지 지연하고, 연출이 비활성화되었거나 Presenter가 없으면 기존 흐름을 그대로 사용한다.

### BattleSceneController 연동

전투방에서 맵으로 돌아가기 전에 Presenter의 퇴장 연출을 요청한다. 퇴장 연출과 기존 화면 가림을 같은 시점에 시작하고, 둘 다 완료된 뒤 기존 `onCovered` 정리와 맵 복귀를 수행한다.

전투방 외 노드, 네트워크 상태 적용, 저장 복원처럼 연출 없이 즉시 상태를 맞춰야 하는 경로는 이동을 재생하지 않고 Presenter를 최종 상태로 정리한다.

### BattleUnitAnimator 사용

캐릭터 프리팹에 이미 설정된 `moveStateName`과 `idleStateName`을 그대로 사용한다.

- 이동 시작: `PlayMove()`
- 이동 완료·취소: `PlayIdle()`

Animator 상태 이름을 새로 하드코딩하거나 캐릭터별 switch를 추가하지 않는다.

## 연출 흐름

### 진입

1. 기존 화면 전환이 방을 완전히 가린다.
2. 기존 로더가 전투방과 플레이어 캐릭터를 생성하고 그리드에 배치한다.
3. Presenter가 각 캐릭터의 최종 위치와 SpriteRenderer 원래 색상을 캡처한다.
4. 캐릭터를 최종 위치에서 `entryOffset`만큼 이동한 위치에 둔다.
5. 화면이 열리는 구간과 동시에 세 캐릭터가 원래 그리드 위치로 이동하고 알파가 1로 보간된다.
6. 이동 완료 후 위치를 정확히 보정하고 `PlayIdle()`을 호출한다.
7. 기존 전투 입력 준비 흐름을 계속한다.

### 퇴장

1. 전투 노드 완료 후 기존 화면 가림과 동시에 퇴장 연출을 시작한다.
2. 세 캐릭터가 각자의 현재 위치에서 `exitOffset` 방향으로 이동하고 알파가 0으로 보간된다.
3. 화면 가림과 캐릭터 이동이 모두 완료되면 기존 전투방 정리와 맵 복귀를 수행한다.
4. 전투방이 비활성화되기 전 Presenter가 알파·애니메이션 임시 상태를 정리한다.

## 예외 처리

- Presenter 또는 캐릭터 Animator가 없으면 해당 부분만 생략하고 노드 전환은 계속한다.
- 캐릭터가 1~2명이어도 존재하는 캐릭터만 동시에 처리한다.
- 사망 캐릭터는 기존 전투 종료 표시 정책을 유지하며 강제로 되살리거나 활성화하지 않는다.
- 연출 도중 오브젝트가 파괴되면 해당 캐릭터를 건너뛰고 나머지와 전환을 완료한다.
- 시간 배율과 무관하게 기존 화면 전환과 맞추기 위해 `Time.unscaledDeltaTime`을 사용한다. 이는 표현용 시간이며 전투 판정에는 사용하지 않는다.
- 저장 복원, 네트워크 스냅샷 적용, 즉시 방 정리 경로에서는 Transform과 알파를 최종 상태로 즉시 정리한다.

## 테스트

테스트는 `Assets/Tests/EditMode~/` 또는 `Assets/Tests/PlayMode~/`에만 작성한다.

- 시작 위치가 `finalPosition + entryOffset`인지 검증한다.
- 진입 완료 위치가 원래 그리드 위치와 정확히 같은지 검증한다.
- 퇴장 목표가 요청 시점의 위치에 `exitOffset`을 더한 값인지 검증한다.
- 여러 캐릭터가 같은 정규화 시간으로 동시에 보간되는지 검증한다.
- 연출이 `CurrentGridIndex`와 전투 런타임 데이터를 변경하지 않는지 검증한다.
- Presenter·Animator 누락 및 도중 파괴 시 전환 완료 콜백이 유지되는지 검증한다.
- 구현 코드와 테스트 어셈블리 컴파일을 확인한다.

Unity 에디터가 열려 있다는 프로젝트 규칙에 따라 batchmode 테스트는 실행하지 않는다.

## 멀티플레이 경계

이 기능은 로컬 표현 연출이다. 동기화 대상은 기존 `CharacterId`, `CurrentGridIndex`, 전투 상태와 노드 상태이며, 진입·퇴장 중의 보간 위치와 알파는 네트워크 상태로 저장하거나 전송하지 않는다. 원격 상태가 갱신되면 연출을 중단하고 authoritative 그리드 위치를 기준으로 표시를 복구할 수 있어야 한다.

## 완료 조건

- 전투 노드 진입 시 모든 활성 플레이어 캐릭터가 왼쪽에서 각자의 그리드 위치로 동시에 이동한다.
- 전투 노드 퇴장 시 모든 활성 플레이어 캐릭터가 현재 위치에서 오른쪽으로 동시에 이동한다.
- 이동 중 걷기 애니메이션, 완료 후 대기 애니메이션이 재생된다.
- 기존 화면 전환의 시작 위치, 종료 위치 및 노드 전환 결과가 바뀌지 않는다.
- 전투 상태와 멀티플레이 동기화 데이터에 변화가 없다.
