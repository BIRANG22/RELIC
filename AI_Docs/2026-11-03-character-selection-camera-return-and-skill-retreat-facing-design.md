# 캐릭터 선택 카메라 복귀 및 스킬 후퇴 방향 유지 설계

## 의도

전투 입력 대기 중 캐릭터를 선택한 상태에서 우클릭하면 선택 상태는 유지하면서 카메라만 기본 전투 시점으로 복귀시킨다. 또한 공격 스킬에 포함된 후퇴 이동은 이동 방향을 바라보지 않고 공격 당시 방향을 유지한다.

## 목표

- 캐릭터만 선택된 상태의 우클릭으로 선택 카메라를 기본 위치로 복귀시킨다.
- 카메라 복귀 후에도 선택 캐릭터, 선택 강조, HUD 상태를 유지한다.
- 카메라 복귀에 사용된 우클릭으로 기존 행동 예약을 동시에 취소하지 않는다.
- 일반 이동은 기존처럼 이동 방향을 바라본다.
- 방향성 공격 스킬의 `E_Move`/`E_Rush` 이동은 전진·후퇴 여부와 관계없이 시전 방향을 유지한다.

## 비목표

- 캐릭터 선택 해제 규칙과 좌클릭 바깥 영역 동작은 변경하지 않는다.
- 몬스터 이동 및 피격에 의한 방향 변경은 변경하지 않는다.
- 스킬 이동 거리, 충돌, 출혈, 코스트 및 피해 결과는 변경하지 않는다.
- 카메라 보간 값이나 씬·프리팹 데이터를 변경하지 않는다.

## 제약

- 우클릭 입력은 전투 행동 실행 또는 입력 잠금 중에는 처리하지 않는다.
- 몬스터 정보창 닫기와 활성 스킬 선택 취소는 기존 우선순위를 유지한다.
- 전투 결과 상태와 연출/UI 경계를 분리한다.
- 테스트는 `Assets/Tests/EditMode~/` 아래에만 작성한다.
- Unity 에디터 직접 제어 및 batchmode 테스트는 수행하지 않는다.

## 검토한 접근

### 선택한 접근: 기존 입력·스킬 실행 경로에서 책임을 제한해 수정

`BattleTimelineController`의 우클릭 처리에서 활성 스킬 선택 취소 이후, 캐릭터가 선택되어 있으면 `BattleCameraController.StartReturnDefaultKeepingCharacterSelection()`을 요청하고 입력을 소비한다. 이 명시적 API만 캐릭터 선택 포커스 차단 규칙을 우회하며 몬스터 정보 포커스는 계속 보호한다. `BattleActionRunner.ExecutePlayerDirectionalMoveEffect()`에서는 스킬 이동 전후의 Facing 변경을 제거하고 명령의 시전 방향을 유지한다.

기존 카메라 소유권과 스킬 이동 결과 계산 경계를 유지하며 변경 범위가 가장 작다.

### 대안 1: 카메라 복귀와 예약 취소를 동시에 수행

기존 우클릭 예약 취소 흐름을 유지할 수 있지만 한 번의 입력으로 카메라와 예약이 동시에 변경되어 오조작 위험이 있으므로 선택하지 않았다.

### 대안 2: 모든 이동에 Facing 유지 옵션 추가

확장성은 있지만 일반 이동과 몬스터 이동까지 영향을 줄 수 있고 현재 요청보다 범위가 크므로 선택하지 않았다.

## 상세 동작

1. 몬스터 정보창이 열려 있으면 우클릭은 기존처럼 정보창 닫기에만 사용한다.
2. 이동/스킬 타게팅이 활성 상태면 우클릭은 기존처럼 해당 선택 취소에만 사용한다.
3. 위 상태가 아니고 캐릭터가 선택되어 있으면 선택 유지 전용 API로 카메라 기본 복귀를 요청하고 우클릭을 소비한다.
4. 캐릭터가 선택되어 있지 않을 때만 기존 마지막 행동 예약 취소가 실행된다.
5. 일반 이동 명령은 기존 `ApplyPlayerMoveFacing`을 계속 사용한다.
6. 스킬 효과 이동은 위치·충돌 결과만 적용하며 Facing과 `RuntimeData.Direction`을 이동 방향으로 변경하지 않는다.

## 멀티플레이 경계

카메라 복귀는 로컬 표현 요청이다. 스킬 이동의 위치·충돌·피해 결과는 변경하지 않고, 이미 명령에 저장된 시전 방향을 유지하므로 별도의 네트워크 프레임워크나 동기화 상태를 추가하지 않는다.
