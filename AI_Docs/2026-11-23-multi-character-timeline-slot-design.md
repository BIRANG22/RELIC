# 다중 캐릭터 타임라인 슬롯 설계

## 의도

하나의 전투 타임라인 슬롯에 서로 다른 캐릭터의 행동을 함께 예약할 수 있게 한다. 기존 슬롯 행동 용량, 행동 순서, 실행 충돌 분리, 캐릭터별 장비 제한과 멀티플레이 편집 잠금은 유지한다.

## 목표

- 서로 다른 `CharacterId`의 `PlayerReservedCommand`를 동일 슬롯에 추가·삽입·이동할 수 있다.
- 네트워크 스냅샷에서도 동일 슬롯의 다중 캐릭터 명령을 복원할 수 있다.
- `BattleActionBatchBuilder`가 기존처럼 액터 및 위치 충돌을 기준으로 명령을 결정론적으로 분리한다.

## 비목표

- 슬롯당 최대 행동 용량 5를 변경하지 않는다.
- 다른 멀티플레이 사용자가 제어하는 명령이 있는 슬롯의 편집 잠금을 제거하지 않는다. 단순 열람 표시는 기존처럼 편집을 막지 않는다.
- 명령 실행 순서, Swift/몬스터 단계, UI 레이아웃을 재설계하지 않는다.
- 그리드 한 칸의 유닛 점유 규칙은 변경하지 않는다.

## 제약

- 상태는 기존 `CharacterId`, `ReservationId`, 타임라인 슬롯 인덱스를 사용한다.
- UI가 전투 결과를 계산하지 않으며 기존 Command -> State Change -> Result/Event 경계를 유지한다.
- 테스트는 `Assets/Tests/EditMode~/` 아래에만 작성한다.
- Unity 에디터 batchmode 테스트는 실행하지 않는다.

## 검토한 접근

### 선택: 캐릭터 독점 검사만 제거

`ReserveTurnSlotUI`의 첫 명령 캐릭터 기반 수락 검사와 이를 중복 호출하는 컨트롤러 검사를 제거한다. 기존 리스트·용량·삽입 구조를 재사용하며, 실행 배치는 캐릭터별 예약 순서를 보존하고 이동 목적지와 효과 대상의 교차 충돌도 분리한다. 네트워크 모델은 바꾸지 않고 호스트가 슬롯 내 모든 명령의 제어 권한을 검증한다.

### 제외: 멀티플레이 슬롯 편집 잠금까지 제거

동시 편집 시 명령 삽입 순서와 충돌 해결 정책이 추가로 필요하다. 요청 범위를 벗어나고 네트워크 결정성 위험이 커 제외한다.

### 제외: 캐릭터별 하위 슬롯 모델 추가

명시적인 그룹 표현은 가능하지만 스냅샷과 UI 데이터 구조를 크게 변경한다. 현재 명령 리스트와 배치 빌더가 이미 다중 액터를 처리할 수 있어 불필요하다.

## 권장 동작

1. 슬롯은 캐릭터와 관계없이 유효한 명령을 수락한다.
2. `TimelineEntryCost` 합계가 최대 용량을 넘으면 기존처럼 거부한다.
3. 명령 이동과 네트워크 복원도 같은 규칙을 사용한다.
4. 실행 시 기존 `BattleActionBatchBuilder`가 동일 액터 또는 공간 충돌을 별도 배치로 분리한다.
5. 다른 멀티플레이 멤버가 제어하는 명령이 있는 슬롯의 편집 제한은 유지하고, 단순 열람 표시는 기존처럼 허용한다.
6. 같은 캐릭터의 예약 순서는 충돌 배치가 나뉘어도 역전되지 않는다.

## 검증 기준

- 서로 다른 두 캐릭터 명령을 한 슬롯에 순서대로 추가할 수 있다.
- 서로 다른 캐릭터 명령을 기존 명령 사이에 삽입할 수 있다.
- 다른 슬롯의 명령을 서로 다른 캐릭터가 있는 슬롯으로 이동할 수 있다.
- 네트워크 스냅샷 복원이 다중 캐릭터 명령을 유지한다.
- 슬롯 용량 초과는 계속 거부된다.
- 동일 캐릭터 연속 이동 병합 등 기존 캐릭터별 동작은 유지된다.

## 멀티플레이 경계

명령과 스냅샷의 ID 구조는 바뀌지 않는다. 동일 슬롯에 여러 `CharacterId`가 존재할 수 있게 되지만, 호스트 검증과 다른 멤버 제어 캐릭터가 포함된 슬롯의 편집 잠금은 유지한다.
