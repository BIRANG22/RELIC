# 몬스터 인포 이름 연결 및 패시브 매 턴 발동 설계

## 문제

- 몬스터 인포의 스킬 이름과 상태이상 이름이 엑셀 원본 이름 대신 누락된 로컬라이징 키 또는 효과 ID로 표시될 수 있다.
- 구형 몬스터 인포는 일부 효과 ID만 하드코딩된 `switch`로 표시한다.
- 패시브 갱신에 최대 카르마 도달 조건이 남아 있어 매 턴 적용 요구와 충돌한다.

## 설계

1. 몬스터 인포 전용 이름 조회기 `MonsterInfoDataNameResolver`를 둔다.
2. 스킬은 `MonsterSkillData.Name`, 효과는 `EffectMasterData.Name`을 우선 반환한다. 이 객체들은 엑셀에서 로드된 DB 데이터다.
3. 이름이 비어 있을 때만 각각 `SkillId`, `EffectId`를 반환한다.
4. 신규 아이템 UI와 구형 몬스터 인포 UI가 같은 조회기를 사용한다.
5. 설명과 타입의 기존 로컬라이징은 이번 변경 범위에서 유지한다.
6. 패시브 적용 여부는 패시브 스킬과 런타임 데이터의 존재 여부로 결정하며 현재/최대 카르마를 조건으로 사용하지 않는다.
7. 기존 전투 시작 및 턴 전환의 패시브 갱신 호출 흐름은 유지한다.

## 멀티플레이 경계

- 이름 조회 변경은 표시 전용이며 전투 상태를 변경하지 않는다.
- 패시브 상태 변경 시점은 기존 턴 실행기의 갱신 흐름을 그대로 사용한다.
- Scene Object 또는 UI가 패시브 결과를 계산하지 않으며, `CharacterRuntimeData`와 `SkillId` 기반 흐름을 유지한다.

## 검증

- EditMode: 스킬/효과 엑셀 이름 우선 및 ID 폴백.
- EditMode: 현재 카르마가 0이어도 장착 패시브가 적용 대상임을 검증.
- C# 프로젝트 컴파일로 신규/기존 호출부 연결을 검증.
