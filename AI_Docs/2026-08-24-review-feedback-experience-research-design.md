# 리뷰 피드백 경험치 및 연구 결과 패널 설계

## 목표

- 패배 결과에서도 이미 클리어한 이전 방과 전투 통계 경험치를 정산한다.
- 캐릭터 `Exp`를 누적 경험치로 해석하고, 레벨 내 경험치로 저장된 기존 값은 계산 시 누적값으로 보정한다.
- 결과 행의 `LV UP` 표시는 실제 레벨이 오른 경우에만 활성화한다.
- 로비 씬의 `ResearchResultPanel`은 기본 비활성 상태로 두고, pending 연구 결과가 있을 때만 자동으로 열린다.

## 경험치 정산

- `BattleStageClearExperienceService.BuildContext`는 기존처럼 패배 시 현재 노드를 제외하고, 클리어된 이전 노드만 컨텍스트에 포함한다.
- `ExplorationResultPanelUI`는 승리/패배와 무관하게 `BuildContext`를 호출한다.
- 결과 패널 UI는 경험치 적용 여부를 패배 플래그로 차단하지 않고, 서비스가 `context`와 캐릭터 통계를 기준으로 미리보기와 적용을 계산하게 한다.

## 누적 경험치

- `CharacterRuntimeData.Exp`는 누적 경험치로 저장한다.
- 레벨 `N`의 시작 누적 경험치는 `(N - 1) * 1000`으로 본다.
- 저장된 `Exp`가 현재 레벨 시작 누적 경험치보다 작으면 기존 레벨 내 경험치 데이터로 보고, 계산 시 `레벨 시작 누적 + Exp`로 보정한다.
- 적용 후에는 항상 누적 경험치를 다시 저장한다.

## UI 표시

- 캐릭터 결과 행의 `LevelUp` 루트는 `leveledUp` 값이 true일 때만 활성화한다.
- 경험치 획득량 텍스트와 슬라이더 진행도는 기존처럼 표시한다.

## 로비 연구 결과 패널

- `Lobby.unity`의 `ResearchResultPanel`은 씬 기본 상태를 비활성으로 둔다.
- `ResearchResultPanelUI`는 씬 로드 후 비활성 패널도 찾아 pending 연구 결과가 있으면 활성화하는 정적 진입점을 제공한다.
- 패널이 활성화되면 기존 정산 흐름을 재사용하고, pending이 없으면 다시 비활성화한다.

## 경계

- 경험치 계산과 저장은 서비스 계층에 둔다.
- UI는 미리보기 표시와 사용자 확인 후 서비스 호출만 담당한다.
- 전투 결과 계산, 맵 생성, 보상 랜덤에는 영향을 주지 않는다.
