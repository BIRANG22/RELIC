# DebugBattle 배틀효과디버그 정리 설계

## 목표

DebugBattle 씬의 배틀효과디버그 창을 실제 전투 HUD 테스트 흐름에 맞춘다.
스킬 사용은 디버그 창에서 직접 시전하지 않고, 선택한 스킬을 BattleCharacterPanel 슬롯에 장착한 뒤 BattleHUD에서 직접 사용한다.

## 범위

- 수정 씬은 `Assets/Project/Scenes/YDM/DebugBattle.unity`로 제한한다.
- `Lobby.unity`, `Battle.unity`는 수정하지 않는다.
- 데이터 선택 목록은 하드코딩 프리셋 대신 `DataManager`의 엑셀 기반 런타임 DB를 사용한다.

## UI 구조

배틀효과디버그 창은 다음 순서로 표시한다.

1. 캐릭터
2. 스킬
3. 유물
4. 룬
5. Compound
6. 그리드효과
7. 상태이상 테스트
8. 스탯 테스트
9. 배틀 제어

최상단에는 `ID 검색` 입력을 둔다. 각 섹션은 현재 검색어로 필터링된 항목을 드롭다운으로 고르고, 대상 슬롯 버튼을 누르면 즉시 적용한다.

## 슬롯 적용

- 캐릭터: 선택한 캐릭터를 아군 1번 테스트 캐릭터로 교체한다.
- 스킬: BattleCharacterPanel 표시 슬롯에 맞춰 `Ability`, `Skill 1`, `Skill 2`, `Unique`를 교체한다.
- 유물: 패시브 유물 슬롯 1~6만 표시한다.
- 룬: 런타임 룬 슬롯 1~12를 표시하되 BattleCharacterPanel에 보이는 슬롯은 1~6이다.
- Compound: 유물과 분리된 별도 슬롯으로 표시한다.
- 그리드효과: 선택한 그리드효과를 0~34 그리드 버튼 클릭으로 즉시 배치한다.

## Compound 처리

요구사항상 액티브 유물 UI는 제거한다. 다만 기존 전투 HUD의 Compound 사용 경로는 내부적으로 `EquippedRelicIds[0]`를 참조하므로, DebugBattle에서는 해당 내부 슬롯을 `Compound` 전용 슬롯으로만 표기한다.

## 스탯 테스트

상태이상 테스트 아래에 HP, 스테미나, 아머, 스테미나 회복량 조절 행을 둔다.
각 행은 `-10`, `-1`, `+1`, `+10` 버튼으로 조절한다.

## 멀티플레이 경계

이번 변경은 DebugBattle 전용 테스트 UI와 런타임 데이터 편의 조작이다.
전투 결과 계산 로직, 랜덤, 네트워크 동기화 구조는 변경하지 않는다.
