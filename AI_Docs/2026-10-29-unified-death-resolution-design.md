# 피해 원인 공통 사망 처리 설계

## 의도

스킬, 상태효과, 그리드 효과, 침식도처럼 피해 원인이 달라도 HP가 0이 된 이후의 전투불능·사망 처리는 같은 진입점을 사용하게 한다. 피해 계산 규칙은 원인별로 유지하고, 확정된 상태를 통계·특수 사망·이벤트·연출로 전달하는 단계만 통합한다.

## 현재 문제

- 침식도 피해는 플레이어 런타임을 전투불능으로 만들지만 `PlayDead()`를 호출하지 않는다.
- 그리드 플레이어 피해는 애니메이션을 재생하지만 피해·사망 통계와 공통 피해 이벤트를 발생시키지 않는다.
- 일반 플레이어 피해의 `HandlePlayerDeathIfNeeded()`는 생존과 사망 양쪽에서 반환하여 `HandleDeath()`가 실행되지 않는다.
- 그리드 몬스터 피해는 의존성이 없는 `BattleDeathService`를 생성하여 런타임 등록 해제와 네크로맨시 기록을 누락할 수 있다.
- 아라벨라 1페이즈는 그리드 피해로 HP 0이 되면 페이즈 전환 판정보다 먼저 `PlayDead()`가 실행된다. 동일 Animator의 사망 1회 제한 때문에 2페이즈 최종 사망 연출도 누락될 수 있다.

## 선택한 접근

### 플레이어

`BattlePlayerIncapacitationService`를 추가한다.

1. `hpBefore > 0 && CurrentHP <= 0` 전환만 최초 전투불능으로 인정한다.
2. `CharacterRuntimeData.HandleDeath()`로 보호막·예약 비용·상태효과를 정리한다.
3. 전투불능 침식도 증가와 `BattleUnitAnimator.PlayDead()`를 한 번의 공통 처리에서 실행한다.
4. 일반 피해, 상태효과, 그리드 효과, 침식도 피해가 이 서비스를 호출한다.
5. 피해량 통계와 피해 이벤트는 각 피해 원인이 실제 감소량을 확정한 뒤 동일 순서로 호출한다.

### 몬스터

기존 `BattleDeathService`를 사망 처리 단일 진입점으로 유지한다.

1. `BattleGridEffectController`는 몬스터 HP와 피해 표현만 갱신하고 임시 `BattleDeathService`를 생성하지 않는다.
2. 실제 `BattleActionRunner`와 `BattleDeathService` 호출 문맥이 보유한 정상 서비스를 사용한다.
3. 그리드 이동으로 몬스터가 죽으면 `BattleActionRunner`가 정상 `deathService.HandleMonsterDead()`를 호출한다.
4. 아라벨라 1페이즈는 `PlayDead()` 대신 기존 페이즈 전환 경로를 사용하며, 2페이즈 최종 사망만 Dead 연출을 재생한다.

## 고려한 대안

- 모든 피해 계산을 `BattleEffectUtility`로 통합: 방어막, 결속, 직접 피격 침식도 등 원인별 규칙까지 바뀔 위험이 있어 제외한다.
- 각 경로에 누락된 호출만 개별 추가: 수정은 작지만 새 피해 경로에서 같은 누락이 재발하므로 제외한다.
- 하나의 거대한 플레이어·몬스터 공용 사망 서비스: 보상, 보스 페이즈, 플레이어 통계 책임이 섞이므로 제외한다.

## 목표

- 플레이어의 모든 치명 피해가 같은 전투불능 상태 정리를 사용한다.
- 침식도와 그리드 피해도 정상 피해와 같은 사망 통계·이벤트·연출을 발생시킨다.
- 몬스터 그리드 사망이 정상 `BattleDeathService`의 보상·등록 해제·특수 사망 처리를 사용한다.
- 아라벨라 1페이즈 그리드 사망이 Dead 연출을 선행하지 않는다.

## 비목표

- 피해량, 방어막, 결속, 배리어, 그리드 면역 규칙은 변경하지 않는다.
- 보상 수치와 침식도 증가량은 변경하지 않는다.
- 새로운 네트워크 프레임워크를 추가하지 않는다.

## 검증

- 순수 런타임 테스트로 최초 전투불능 판정과 상태 정리를 검증한다.
- 그리드 효과 결과 표현이 아라벨라 1페이즈에 Dead를 선택하지 않는 정책을 검증한다.
- 소스 호출 경계 테스트 대신 실제 공개 정책과 런타임 결과를 검증한다.
- 런타임 및 Editor 테스트 프로젝트를 컴파일한다.
- Unity 에디터 직접 제어와 batchmode 테스트는 수행하지 않는다.

## 멀티플레이 영향

사망 판정은 `CharacterId`/`RuntimeId`가 연결된 런타임의 HP 전환 결과로 결정한다. 피해 원인은 각 Command에서 계산하고 공통 상태 변경 결과를 이벤트·표현 계층으로 전달하므로 향후 동기화 시 같은 입력에서 같은 사망 결과를 재생할 수 있다.
