# Untranslated 전수 수정 및 ID 기반 표시 갱신 설계

## 목표

영어 로케일에서 `Untranslated`가 노출되는 데이터·키·텍스트 소유권 문제를 제거한다. 유물·기억·아이템·캐릭터처럼 안정적인 ID로 표시 데이터를 조회하는 UI는 열린 상태에서 언어를 변경해도 현재 ID를 기준으로 이름·설명·등급을 즉시 다시 계산한다.

## 확인된 원인

1. Event 선택지의 런타임 canonical 키와 워크북 키가 일치하지 않는 항목이 남아 있다.
2. `S_Core_53`~`S_Core_84`의 이름·효과 영어 번역 64개가 비어 있다.
3. 코드가 직접 조회하는 플레이어 표시 키 41개가 워크북에 없으며, 구형 `relic.rarity.*` 키가 공통 등급 키와 혼재한다.
4. `CharacterSettingPanel/NameText`와 주사위·결과 TMP는 런타임 작성자와 정적 로컬라이저가 동시에 값을 쓴다.
5. ID 기반 presenter가 로케일 변경 이벤트를 받지 않거나, 이미 계산된 `Name`/`Description` 캐시를 계속 표시한다.

## 설계

### 1. 로컬라이제이션 데이터 원본

- `Localization.xlsx`를 문자열 원본으로 유지한다.
- Event 반복 필드는 `data.event.{event_id}.choice_{order}_{field}`만 사용한다.
- 활성 GameData의 canonical 키에는 한국어 원문과 영어 번역이 모두 존재해야 한다.
- 코드의 명시적 플레이어 표시 키도 워크북에 존재해야 한다.
- 유물 등급은 `common.rarity.*`와 `RelicRarityUtility`로 통일하고 구형 `relic.rarity.*` 조회를 제거한다.

### 2. 동적 텍스트 소유권

- presenter가 ID로 최종 표시값을 계산하는 TMP는 정적 `LocalizedTMPText`가 소유하지 않는다.
- 전역 자동 바인더의 비동기 재적용도 막아야 하는 대상에는 `LocalizationAutoBindingIgnore`를 함께 사용한다.
- 캐릭터 이름, 주사위 버튼, 이벤트 결과, 보상 슬롯과 보상 상세 텍스트에 동일한 소유권 규칙을 적용한다.

### 3. 열린 ID 기반 UI의 로케일 변경

- 로컬라이제이션 테이블 준비가 끝난 뒤 한 번 발생하는 공통 런타임 갱신 신호를 제공한다.
- ID 기반 presenter는 활성화 동안 이 신호를 구독하고 현재 보관 중인 ID로 DB를 다시 조회한다.
- 보상 UI는 `BattleRewardData.Name/Description`보다 `RewardId` 재조회를 우선한다.
- 기억 설명의 수치·RichText 치환은 새 로케일 템플릿을 얻은 뒤 다시 수행한다.
- 비활성 UI는 다음 활성화 시 기존 초기화 경로로 현재 로케일을 반영한다.

### 4. 이벤트 주사위 문구

- `굴리기`, `확인`, `성공`, `실패`, `판정 성공`, `판정 실패`를 안정적인 키로 관리한다.
- presenter는 버튼 상태를 보관하고 활성화·상태 변경·로케일 변경 시 상태에 맞는 키를 적용한다.
- 이벤트 결과 계산과 표시 번역은 분리하며, 판정 결과 자체는 기존 전투 상태 흐름을 변경하지 않는다.

### 5. 검증과 재발 방지

- 활성 GameData canonical 키와 영어 번역 커버리지를 검사한다.
- 명시적 런타임 키가 워크북에 존재하는지 검사한다.
- 워크북과 Shared Data/locale table의 ID·엔트리 일치를 검사한다.
- Event 반복 필드가 순번 기반 키를 사용하는지 검사한다.
- 동적 TMP에 충돌 작성자가 남지 않았는지 검사한다.
- 열린 보상/ID 기반 presenter가 로케일 갱신 신호에서 현재 ID를 다시 해석하는지 검사한다.

## 범위 제외

- 전투 결과, 보상 추첨, 인벤토리 상태, 랜덤 시드, 네트워크 동기화 데이터는 변경하지 않는다.
- 번역과 무관한 UI 구조 개편은 하지 않는다.

## 멀티플레이 경계

표시 문자열의 조회와 갱신 시점만 변경한다. `Command -> State Change -> Result/Event` 흐름과 안정적인 ID 기반 상태는 유지되며 동기화 결과에는 영향이 없다.
# 후속 재현 보완 (2026-09-29)

- 로비 월드 오브젝트 호버는 `LobbyWorldObjectHoverName`의 안정 키 9개를 모든 지원 언어 테이블에 추가하고, 공용 이름 TMP를 런타임 동적 작성자 전용으로 고정한다.
- 주사위 굴림 완료 시 `ReadyToConfirm` 상태 전환을 버튼 번역 재적용보다 먼저 수행한다.
- 언어 변경 갱신 순서는 `테이블 로드 완료 → 정적 로컬라이저 갱신 → ID 기반 presenter 갱신`으로 고정한다. presenter 이벤트는 구독자별 예외를 격리한다.
- 로비 유물 상점은 열린 상태에서 언어가 바뀌면 현재 offer ID로 이름·희귀도·설명을 다시 조회하며 해당 TMP의 정적 로컬라이저 소유권을 제거한다.
