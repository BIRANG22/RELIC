# 스킬 강화 개념 제거 설계

## 목적

Core와 Ability 스킬의 기본/강화 홀짝 쌍을 제거한다. 기존 강화형의 수치와 연출 연결을 단일 기본 스킬 데이터로 승격하고, 보상·상점·이벤트·로비에서 강화형이라는 개념을 더 이상 판정하거나 제공하지 않는다.

## 데이터 변환

- Core는 기존 짝수 ID `S_Core_02~80`의 행을 유지하고 새 ID `S_Core_01~40`으로 재번호화한다.
- Ability는 기존 짝수 ID `S_Ability_02~20`의 행을 유지하고 새 ID `S_Ability_01~10`으로 재번호화한다.
- 승격된 행은 `Level=1`로 바꾸고 한글·영문 표시 이름의 후행 `+`를 제거한다.
- 기존 홀수 행과 홀수 행 전용 리소스 매핑은 제거한다.
- GameData의 Effect·Rune 등 내부 참조, Localization 키, 캐릭터 기본 Ability, SkillIcon/VFX/AttackOverride/Sound/RewardPool 등 외부 참조는 같은 매핑으로 갱신한다.
- `GameDataRuntime.csv`는 수정된 `GameData.xlsx`로부터 다시 생성한다.
- 기존 저장 데이터는 초기화 가능하므로 구 ID 마이그레이션을 제공하지 않는다.

## 런타임 구조

`SkillRarityUtility`의 기존 호출 호환 API는 직렬화된 UI와 오래된 호출부의 안전한 전환을 위해 남기되 홀짝 계산을 수행하지 않는 고정 정책으로 바꾼다. 모든 스킬은 기본형으로 취급하고, 강화 가능 여부와 대응 짝 조회는 항상 실패한다. Core 보상 후보 수집은 `Category.Core`, 보상 희귀도, 파티 소유권, 전역 허용 목록, 중복 소유 여부만 검사한다.

전투 종료, 시작방, 이벤트방, 휴식방 상점의 후보 수집도 같은 단일 ID 규칙을 사용한다. 랜덤 선택은 기존 `BattleRandom` 흐름을 유지한다.

## 강화 기능 제거

- 로비 스킬 강화 진입 버튼은 비활성화한다.
- 휴식방·로비 강화 패널은 공용 강화 정책에서 후보가 생성되지 않아 실행할 수 없게 한다.
- 스킬 각성 이벤트 `Event_08`과 해당 맵 항목을 데이터에서 제거한다.
- 모든 SkillMaster의 Level이 1이므로 강화 여부 마크는 표시되지 않는다.
- 기존 직렬화 참조와 저장 필드는 Missing Script 및 구 세이브 역직렬화 오류를 피하기 위한 무동작 호환 껍데기로 유지한다.

## 오류 및 무결성

- 최종 Core ID는 정확히 `01~40`, Ability ID는 정확히 `01~10`이어야 한다.
- 두 카테고리에 `Level=2`, `+` 표시 이름, 짝수/홀수 변형 판정 코드가 남지 않아야 한다.
- 모든 새 SkillId 참조는 SkillMaster 또는 허용된 외부 ID를 가리켜야 한다.
- 아이콘·VFX 등 중복된 새 ID가 생기면 기존 짝수 행의 연결만 보존한다.

## 검증

- EditMode 테스트로 단일 코어 후보가 ID 홀짝과 무관하게 포함되는지 확인한다.
- 데이터 검증 테스트로 Core 40개, Ability 10개, 연속 ID, Level 1, 이름의 `+` 제거, 참조 무결성을 확인한다.
- C# 프로젝트를 빌드해 제거된 타입과 API 참조가 남지 않았는지 확인한다.
- Unity 에디터는 열려 있다고 가정하며 batchmode 테스트는 실행하지 않는다.

## 멀티플레이 영향

보상 결과는 계속 안정적인 `SkillId`와 기존 `BattleRandom` 결과로 표현된다. 홀짝 대응 규칙과 강화 상태가 제거되어 동기화 상태가 단순해지며, UI/VFX/사운드는 전투 결과 계산에 참여하지 않는다.
