# 전 노드 파티 입장·퇴장 연출 설계

## 조사 결과

- 기존 구현과 씬 참조는 머지 후에도 남아 있다.
- 전투 캐릭터 생성 루트는 `BattleRoom` 하위이므로 대상 탐색 계층이 끊긴 문제는 아니다.
- 화면 전환은 덮기 1초, 완전 가림 0.3초, 열기 1초다.
- 기존 입장은 방 생성 콜백 직후 `0.3초 지연 + 0.35초 이동`으로 실행되어 완전 가림과 열리기 초반에 대부분 소비된다.
- 기존 퇴장은 0.3초 동안 화면 덮기와 동시에 실행되어 짧고, 대각선 가림에 빠르게 가려진다.
- 기존 연출기는 `BattleCharacter`만 수집하고 `BattleRoom`에서만 호출되므로 이벤트·휴식·상점 등 공용 방 캐릭터와 지도 선택 캐릭터에는 적용되지 않는다.

## 목표 동작

1. 모든 노드 진입 시 캐릭터는 왼쪽에서 현재 배치된 자리로 동시에 이동하며 나타난다.
2. 모든 노드 종료 시 캐릭터는 현재 자리에서 오른쪽으로 동시에 이동하며 사라진다.
3. 지도 선택 단계의 캐릭터는 입장 연출 없이 즉시 최종 위치에 표시한다.
4. 지도에서 다음 노드를 선택하면 지도 캐릭터가 화면 페이드아웃과 동시에 오른쪽으로 퇴장한다.
5. 저장 이어하기·복원 경로는 중간 연출을 재생하지 않고 최종 위치를 보장한다.

## 권장 구조

- 기존 `BattleRoomPartyTransitionPresenter`를 공용 파티 연출기로 확장한다.
- 연출 대상 루트를 호출자가 명시적으로 전달한다. 루트 내부의 활성 `BattleCharacter`와 `BattleMapSelectionCharacterMarker`를 수집하고 Transform 기준으로 중복 제거한다.
- 전투방은 `BattleUnitSpawner.PlayerRoot`를 전달한다. 이로써 씬 계층 변경에도 캐릭터 대상이 명확하다.
- 비전투 노드와 지도 선택은 `BattleSceneController`가 `sharedPartyPresentationRoot`를 전달한다.
- 지도→노드 전환은 지도 캐릭터 퇴장과 화면 덮기를 동시에 시작한다. 방 생성 후 화면이 충분히 열린 시점에 새 노드 캐릭터 입장을 시작한다.
- 노드→지도 전환은 현재 노드 캐릭터 퇴장과 화면 덮기를 동시에 시작하고, 완전히 가려진 뒤 지도 캐릭터를 새로 생성해 최종 위치에 둔다.
- 걷기 애니메이션은 `BattleUnitAnimator`가 있는 전투 캐릭터에 기존 `PlayMove/PlayIdle`을 사용한다.
- 이벤트·휴식 프리팹은 대부분 `moveStateName`이 비어 있고 이벤트용 Animator Controller에 `Move` 상태가 없으므로, 이동 구간에만 CharacterPrefabDB의 동일 캐릭터 전투 프리팹 Animator Controller를 사용하고 종료·취소 시 원래 이벤트/휴식 Controller와 Idle로 복원한다.
- 지도·휴식 캐릭터의 자원 UI/VFX 앵커는 고정 스폰 포인트가 아니라 이동하는 캐릭터 Transform을 사용한다. 따라서 입장·퇴장 중에도 캐릭터와 연출 위치가 함께 이동한다.
- 비전투 프리팹의 이동 VFX가 비어 있는 경우에는 전투 프리팹의 `Vfx_move_cha` 설정을 읽되, 인스턴스화는 현재 비전투 캐릭터의 `vfxSpawnPoint`에서 수행한다. 이로써 지도·모든 비전투 노드의 입장/퇴장 VFX가 캐릭터 위치를 기준으로 정렬된다.
- Direct World 방식의 `Vfx_move_cha`는 비전투 프리팹의 Transform 스케일을 상속하므로, 전투 프리팹의 VFX 스폰 지점 월드 스케일을 현재 비전투 캐릭터 스폰 지점 월드 스케일로 나눈 비율을 VFX 로컬 스케일에 적용한다. 위치는 현재 캐릭터 기준을 그대로 유지하면서 전투 노드와 동일한 월드 크기를 보장한다.
- 비전투 프리팹의 `vfxSpawnPoint`는 `HealVfxSpawn`이며 이동 VFX 기준점이 아니므로, 전환 이동 VFX는 파티 캐릭터 루트 Transform에 생성한다. 전투 프리팹의 이동 VFX 스폰 스케일과 이 루트 스케일의 비율로 보정한다.
- 맵에서 노드로 전환할 때는 화면이 완전히 가려진 `onCovered` 콜백에서 노드 생성과 동시에 입장 준비·재생을 시작한다. 따라서 페이드 공개 전에 시작 위치와 투명 상태가 확정되어 원래 위치에 서 있는 프레임이 노출되지 않는다.

## 타이밍

- 퇴장은 화면 덮기와 동시에 시작하되 이동 시간을 화면 덮기 시간 안에서 식별 가능한 길이로 맞춘다.
- 입장은 화면이 열리기 시작한 뒤 보이도록 화면 전환 완료 또는 명시적인 열림 시점 이후에 시작한다.
- 위치와 알파는 `Time.unscaledDeltaTime` 기반의 표시 전용 연출이며 전투 결과나 상태 변경에 관여하지 않는다.

## 예외 및 복구

- 대상이 없거나 비활성화된 경우 완료된 Task를 반환한다.
- 전환 중 대상이 파괴돼도 남은 대상만 처리하고 완료한다.
- 새 전환 시작 전 기존 연출을 취소하고 색상과 최종 위치를 복원한다.
- 동일 Transform이 두 표식에 잡혀도 한 번만 연출한다.

## 멀티플레이 경계

이 변경은 캐릭터 표시 Transform, SpriteRenderer 알파, 걷기 애니메이션만 제어한다. RuntimeId, 전투 상태, 명령, 결과 이벤트, 랜덤에는 영향을 주지 않는다.
