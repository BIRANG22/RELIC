# 몬스터 정보 패널 반복 개폐 안정화 설계

## 목적

전투 중 몬스터 정보 패널을 ESC 또는 우클릭으로 반복 개폐할 때 동적 UI 생성·파괴와 블러 복제 전체 재생성이 누적되어 프레임이 멈추는 문제를 줄인다.

## 조사 결과

- 패널을 열 때마다 몬스터 스킬과 상태 항목을 `Instantiate`한다.
- 패널을 닫을 때마다 생성 항목을 `Destroy`하므로 실제 삭제가 프레임 끝까지 지연된다.
- 동적 항목을 만든 뒤 `RefreshBlurReplica`가 기존 블러 복제 트리를 폐기하고 전체 계층을 다시 복제한다.
- 블러 활성 중에는 복제된 Transform, Graphic, TMP, Mask를 계속 동기화한다.
- ESC·우클릭 프레임 가드, 카메라 이동 코루틴 교체, 로케일 이벤트 해제에서는 장기 누적 경로가 확인되지 않았다.

## 권장 설계

1. 스킬 및 상태 항목은 한 번 생성한 뒤 리스트에 보관한다.
2. 다음 몬스터를 표시할 때 기존 항목을 순서대로 다시 바인딩하고 부족한 수량만 추가 생성한다.
3. 사용하지 않는 항목은 파괴하지 않고 비활성화한다.
4. 패널을 닫을 때도 항목을 파괴하지 않고 비활성화하여 다음 열기에 재사용한다.
5. 블러 복제본은 항목 풀이 실제로 증가해 계층이 바뀐 경우에만 무효화한다. 데이터 재바인딩과 활성 상태 변경은 기존 동기화 경로를 사용한다.
6. Canvas 계층 자체가 파괴되는 `OnDisable`에서는 보유 항목 참조만 정리하며 Unity 생명주기에 맡긴다.

## 검증

- 재사용 풀은 필요한 수량까지 한 번만 확장되고 이후 같은 수량 요청에서 기존 인스턴스를 반환해야 한다.
- 사용 수량을 줄이면 남는 항목은 비활성화되어야 한다.
- 다시 수량을 늘리면 비활성 항목을 재사용하고 새 인스턴스를 만들지 않아야 한다.
- Assembly-CSharp 및 Editor 어셈블리 컴파일로 실제 사용 코드와 테스트의 컴파일을 확인한다.
- Unity Profiler 및 실제 반복 개폐 화면은 프로젝트 규칙에 따라 미검증 항목으로 남긴다.

## 멀티플레이 경계

몬스터 런타임 데이터는 읽기만 하며 전투 Command, State Change, Result/Event, RuntimeId 및 네트워크 Snapshot을 변경하지 않는다. 변경 범위는 로컬 UI 표시와 블러 프레젠테이션에 한정한다.
