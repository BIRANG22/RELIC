# 기본 전투 최종 정산 종료 화면 설계

## 목적

기본 전투의 마지막 전투를 마친 뒤 로비로 즉시 이동하지 않고, 정산 패널과 로비 사이에 기존 데모 종료 문구를 표시한다.

## 사용자 흐름

`전투 종료 → 정산 패널 → 데모 종료 텍스트 패널과 확인 버튼 → 로비`

정산 패널의 기존 확인 버튼을 처음 누르면 로비 정리·저장·이동을 수행하지 않고 종료 텍스트 패널을 표시한다. 종료 텍스트 패널에서 확인 버튼을 누르면 기존 로비 복귀 처리를 그대로 실행한다.

## 조건과 범위

- 기본 전투의 완료 정산에만 적용한다.
- 데모 전투의 기존 마지막 노드 종료 화면과 지도 복귀 흐름은 변경하지 않는다.
- 튜토리얼 및 패배 정산의 기존 로비 이동 흐름은 유지한다.
- 종료 문구와 검은 배경은 `DemoEndingPanel`의 기존 구성을 재사용한다.
- 종료 패널에는 확인 버튼을 명시적으로 연결하며, UI는 전투 결과를 계산하거나 상태를 변경하지 않는다.

## 검토한 접근

1. **정산 UI에 종료 화면 단계를 추가한다 — 선택.** 로비 이동을 소유한 `ExplorationResultPanelUI`가 마지막 기본 전투 완료 여부를 읽고, 첫 확인에서는 종료 패널만 표시하며 두 번째 확인에서 기존 로비 이동을 실행한다. 요청한 순서가 코드 흐름과 일치한다.
2. `BattleSceneController.ReturnToMap`의 말단 분기를 일반 전투에도 적용한다. 정산 후 로비로 가는 흐름에는 `ReturnToMap`이 사용되지 않으므로 요청한 타이밍을 구현할 수 없다.
3. 별도 종료 씬을 추가한다. 현재 씬에 이미 동일 패널이 있어 불필요하게 씬 전환과 상태 전달이 늘어난다.

## 검증

- 순수 정책 테스트로 기본 전투 최종 승리만 종료 단계를 요구하는지 검증한다.
- 데모, 튜토리얼, 패배, 다음 노드가 남은 기본 전투는 제외되는지 검증한다.
- 씬 YAML에서 종료 패널과 확인 버튼 참조 및 기존 문구를 검사한다.
- 런타임 및 Editor 테스트 어셈블리를 컴파일한다.

## 멀티플레이 영향

동기화 대상 전투 상태와 결과를 변경하지 않는다. 이미 확정된 전투·맵 상태를 읽어 로컬 UI 표시 순서만 제어하고, 기존 로비 복귀 처리는 최종 확인 뒤 동일하게 실행한다.
