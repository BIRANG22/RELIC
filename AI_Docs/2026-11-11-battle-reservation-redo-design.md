# 전투 예약 Redo 설계

## 의도

배틀 예약 단계에서 우클릭 Undo로 제거한 플레이어 명령을 다시 원래 예약 상태로 복원할 수 있게 한다. 실수로 Undo했을 때 동일 행동을 처음부터 다시 입력하지 않아도 되는 것이 목표다.

## 범위

- `Alt+우클릭`으로 가장 최근 Undo를 Redo한다.
- 연속 Undo와 연속 Redo를 LIFO 순서로 지원한다.
- 예약 추가를 Undo하면 명령을 제거하고, Redo하면 원래 슬롯·순서에 다시 넣는다.
- 예약 이동을 Undo하면 이동 전 슬롯·순서로 되돌리고, Redo하면 이동 후 슬롯·순서로 다시 옮긴다.
- 같은 슬롯 안에서 순서만 바꾼 이동과 여러 번의 연속 이동도 한 단계씩 Undo/Redo한다.
- 새 예약, 직접 삭제, 전체 초기화처럼 Undo/Redo 흐름 밖에서 예약 상태가 바뀌면 Redo 기록을 폐기한다.
- 기존 우클릭의 몬스터 정보 닫기와 스킬 선택 취소 우선순위는 유지한다.
- 실행 중이거나 입력이 잠긴 상태에서는 Undo/Redo 모두 동작하지 않는다.

## 비범위

- 턴이 실행된 이후의 예약 복원
- 몬스터 예약의 Undo/Redo
- 저장 파일 또는 네트워크를 통한 Redo 기록 영속화
- 별도 UI 버튼이나 히스토리 목록

## 접근 방식

1. **작업 종류가 있는 예약 히스토리(채택)**: 예약 추가와 예약 이동을 구분하고 이동 전·후 슬롯/순서를 저장한다. 현재 `playerReservationHistory` 구조를 확장하면서 명령 객체를 복제하지 않아도 된다.
2. 전체 타임라인 스냅샷: 복원은 단순하지만 매 변경마다 모든 명령을 복제해야 하고 런타임 참조와 예약 비용 상태까지 함께 다뤄야 해 과하다.
3. 모든 편집을 Command 객체로 승격: 장기적으로 확장성은 좋지만 현재 기능 하나를 위해 예약 관련 전체 변경 경로를 재구성해야 한다.

## 설계

`PlayerReservationHistoryEntry`에 작업 종류와 출발/도착 슬롯·순서를 저장한다. 예약 추가 엔트리는 기존처럼 Undo에서 제거하고 Redo에서 재삽입한다. 예약 이동 엔트리는 Undo에서 출발 위치로, Redo에서 도착 위치로 명령을 옮긴다. 이동 복원은 기존 `TryMovePlayerReservationInternal`의 슬롯·캐릭터·장비·용량·전체 비용 검증과 롤백 방식을 재사용하되 새 사용자 편집으로 기록하지 않고 반대 스택으로 동일 엔트리를 전달한다.

일반 예약 변경은 Redo 분기를 만든 과거와 더 이상 일치하지 않으므로 Redo 스택을 지운다. Redo 자체가 내부 삽입을 수행할 때는 스택을 지우지 않도록 명시적인 복원 메서드를 사용한다.

## 멀티플레이 경계

Redo 입력은 로컬 UI에서 시작하고, 명령은 기존 `PlayerReservedCommand`와 슬롯 인덱스로 표현한다. 현재 우클릭 Undo가 네트워크 명령을 전송하지 않는 로컬 예약 편집 기능이므로 Redo도 그 동작 범위를 그대로 따른다. 이번 변경에서는 네트워크 동기화 프로토콜이나 호스트 승인 경로를 새로 추가하지 않으며, Steam 멀티플레이에서 Undo/Redo 히스토리를 동기화하는 작업은 비범위다.

## 완료 조건

- Undo 후 Redo하면 동일 명령이 동일 슬롯의 동일 순서로 돌아온다.
- 여러 번 Undo한 뒤 같은 횟수만큼 Redo할 수 있다.
- Undo 후 새 예약을 추가하면 이전 Redo는 불가능하다.
- 복원 조건이 더 이상 유효하지 않으면 상태를 훼손하지 않고 Redo가 실패한다.
- 기존 Undo 동작과 선택 슬롯이 유지된다.
- 슬롯 이동 직후 Undo는 예약을 삭제하지 않고 직전 위치로 되돌린다.
- 이동 Undo 직후 Redo는 다시 이동 후 위치로 보낸다.
- 이동 복원 목적지가 유효하지 않으면 명령과 비용 상태를 훼손하지 않는다.
