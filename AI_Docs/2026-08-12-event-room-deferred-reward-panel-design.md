# 이벤트룸 보상 패널 연동 설계

## 목표

이벤트룸 선택지 결과 중 버프, 디버프, 체력, 코스트 같은 즉시 효과는 기존처럼 텍스트와 함께 바로 적용한다. 재화, 기억, 유물 획득은 배틀룸 종료 보상과 같은 수령 UI를 사용하되, 다음 이벤트가 이어지는 선택지는 보상을 보류하고 마지막 이벤트 선택 직후 보상 패널을 연다.

## 권장 구조

- `EventChoiceExecutionService`는 선택지 판정, 비용, 즉시 상태 변경, 결과 메시지를 계속 담당한다.
- 이벤트룸 컨트롤러는 기억/유물/재화 보상 콜백에서 실제 지급 대신 `BattleRewardData`를 생성해 `pendingEventRewards`에 보관한다.
- 선택 결과에 `NextEventId`가 있으면 결과 텍스트를 표시하고 다음 이벤트를 로드한다. 보상 패널은 열지 않는다.
- 선택 결과에 `NextEventId`가 없으면 결과 텍스트를 표시한 뒤, 보류 보상이 있으면 `BattleRewardPanelUI.Open`을 즉시 호출한다.
- 보상 패널 완료 콜백에서 현재 이벤트 노드를 클리어하고 맵으로 복귀한다.
- 보류 보상이 없으면 기존처럼 `NextButton`을 표시하고, 사용자가 눌렀을 때 노드를 클리어하고 맵으로 복귀한다.

## 데이터 흐름

1. 사용자가 이벤트 선택지를 클릭한다.
2. `EventChoiceExecutionService.Execute`가 선택지를 판정한다.
3. 재화/기억/유물 획득 결과는 컨트롤러 콜백을 통해 `pendingEventRewards`에 추가된다.
4. 다음 이벤트가 있으면 다음 이벤트 화면으로 이동하고 보상은 계속 보류한다.
5. 다음 이벤트가 없고 보류 보상이 있으면 선택지 슬롯을 잠그고 보상 패널을 연다.
6. 보상 패널에서 재화는 클릭 수령, 기억/유물은 기존 `Equip_panel`로 장착 또는 삭제 처리한다.
7. 보상 흐름이 끝나면 이벤트 노드를 클리어하고 맵으로 복귀한다.

## 예외 처리

- 보상 패널을 찾지 못하면 기존처럼 결과 텍스트와 `NextButton`을 사용해 방을 닫을 수 있게 한다.
- 다음 이벤트가 있는 동안 누적된 보상은 새 이벤트 로드로 사라지지 않는다.
- 이벤트룸이 비활성화되면 보류 보상 목록을 비워 다음 입장에 섞이지 않게 한다.

## 멀티플레이 경계

전투 결과 계산은 `EventChoiceExecutionService`와 런타임 데이터 변경에 남긴다. UI는 보상 결과를 수령/표시하고 콜백 이후 상태를 갱신하는 역할만 담당한다. 새 네트워크 프레임워크나 Scene Object 기반 동기화 대상은 추가하지 않는다.
