# 룬 효과 회귀 수정 설계

## 목적

Rune_04, 11~15, 51~53, 56~58, 61의 실제 전투 결과와 툴팁을 현재 룬 설명에 맞춘다.

## 원인

- 전투 종료 회복이 `BattleFinished` 이벤트 이후 실행되어 저장·화면 전환과 순서가 충돌한다.
- 일반 룬 수치 증가 효과가 유물 전용 조회 경로에 연결되어 있다.
- 전용 룬 일부가 슬롯 번호나 대상 칸 수를 실제 조건 대신 사용한다.
- Rune_53의 장막이 `E_Ward`(가시)로 잘못 매핑되어 있다.
- Rune_61의 다음 턴 무료 상태는 생성되지만 첫 예약 기억 기준으로 소비되지 않는다.
- 저체력 피해 증가가 실행 피해에만 있고 툴팁 계산에는 없다.

## 선택 설계

- 룬 수치 보정과 조건 판정을 `BattleEquipmentEffectService`의 공용 계산 경로에 둔다.
- Rune_04 회복 상태 변경을 전투 종료 이벤트보다 먼저 확정한다.
- Rune_11~15는 룬 보정을 먼저, 유물 보정을 다음에 적용한다.
- Rune_51은 실제 피해와 툴팁이 같은 저체력 배율 규칙을 사용한다.
- Rune_52는 턴 종료 시 방어도 10 이상이면 강타 1을 획득한다.
- Rune_53은 첫 턴에 `E_Barrier`를 부여한다.
- Rune_56은 실행 시점의 생존 적이 전투 전체에서 정확히 1명일 때 공격 수치 +1을 적용한다.
- Rune_57은 확정된 해당 공격 효과의 공격 횟수가 3회 이상일 때 각 피해 수치 +1을 적용한다.
- Rune_58은 슬롯 번호가 아니라 해당 턴에서 첫 번째로 예약된 공격 기억에 공격 횟수 +1을 적용한다.
- Rune_61은 마나 0으로 턴을 종료하면 다음 턴의 첫 비이동 예약 기억 비용을 0으로 만들고 즉시 상태를 소비한다.

## 제약과 비목표

- UI/VFX는 결과를 계산하지 않는다.
- 룬 이외의 유물 계산 순서는 변경하지 않는다.
- 네트워크 프레임워크는 추가하지 않는다.
- 판정 입력은 가능한 한 명령과 RuntimeData에 확정된 값·ID를 사용한다.

## 검증

- 각 룬 조건을 독립적으로 재현하는 EditMode 테스트를 추가한다.
- 새 테스트 소스를 포함해 `Assembly-CSharp-Editor`를 컴파일한다.
- CSV와 Excel 원본의 룬 설명·효과 ID 일치를 검사한다.
