# 로비 캐릭터 라이트 프리팹 편집 전환 설계 및 구현 계획

## 문제

로비 캐릭터의 `light` 오브젝트와 `Light2D` 설정을 `LobbyWorldCharacterSpawner`가 런타임에 생성하고 캐릭터 ID별 상수로 덮어쓴다. 이 때문에 플레이 중 Inspector에서 조정한 값을 원본 프리팹에 저장할 수 없다.

## 권장 설계

- `Cha_01_idle_0`~`Cha_04_idle_0` 로비 프리팹에 `light` 자식과 `Light2D`, `DBAudioSource`를 직렬화한다.
- 캐릭터 Collider의 `UIHoverLight2DFalloff`가 프리팹 내부 `Light2D`를 참조하도록 직렬화한다.
- 스포너는 라이트를 생성하거나 수치를 결정하지 않고, 프리팹에 구성된 라이트를 그대로 사용한다.
- 기존 캐릭터 위치, 렌더러 좌우 반전과 정렬, 이름 호버 및 클릭 연결은 유지한다.
- 라이트가 없는 프리팹도 캐릭터 생성 자체는 유지하고 라이트 호버 연결만 생략한다.

## 구현 계획

1. 스폰 결과에 프리팹 라이트가 하나만 남고 직렬화 값이 보존되는 회귀 테스트를 먼저 작성한다.
2. 스포너의 런타임 라이트 생성 및 캐릭터별 라이트 상수를 제거한다.
3. 네 로비 프리팹에 기존 런타임 설정값을 이전한다.
4. EditMode 테스트, 런타임 어셈블리와 Editor 어셈블리 컴파일을 확인한다.
5. 열린 Unity 에디터에서 네 캐릭터의 라이트와 호버 동작을 수동 확인 항목으로 남긴다.

## 멀티플레이 영향

로비 표현 데이터의 저장 위치만 코드에서 프리팹으로 이동한다. 전투 상태, 명령, 결과 이벤트, 네트워크 동기화 데이터에는 영향이 없다.
