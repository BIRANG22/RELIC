# 런타임 GameData 로컬라이제이션 전수 보정

## 조사 결과

- 런타임 UI가 `Name`, `Desc`, `EffectDesc`, `ToolTip`을 직접 TMP에 대입하는 경로가 다수 존재한다.
- 공통 진입점인 `GameDataLocalization`도 룬 이름, 아이템 이름/설명, 효과 이름/툴팁을 일부 원문으로 우회하고 있었다.
- `DebugBattle` 장면은 효과 데이터의 번역을 의도적으로 우회하므로, 언어가 영어여도 원문이 표시될 수 있었다.
- GameData 스캐너가 `효과설명`을 일반 `description` 키로 만들 수 있어 런타임의 `effect_description` 조회 키와 불일치할 수 있었다.
- `UIManager`가 메뉴 표시 직후 직렬화된 한국어 문자열을 TMP에 직접 다시 대입해, 정상 연결된 컴포넌트의 번역 결과를 덮어쓰고 있었다.

## 권장 구조

1. 모든 GameData 표시 문자열은 `GameDataLocalization`에서 키 기반으로 조회한다.
2. UI는 데이터 필드를 직접 대입하지 않고 해당 공통 메서드를 사용한다.
3. 스캐너의 키 생성 규칙을 런타임 조회 규칙과 동일하게 맞춘다.
4. 언어 칸이 비어 있는 경우에만 선택 언어의 단일 미번역 표기를 반환한다.
5. 정적 TMP는 하나의 표시 소유자(`LocalizedTMPText`)만 유지하고, 런타임 TMP는 원문-키 매핑으로 자동 연결한다.

## 검증 범위

- Editor 어셈블리 컴파일
- 공통 데이터 로컬라이저 단위 테스트
- 정적 바인딩 중복 소유자 방지 테스트
- Unity 에디터에서 전체 검사 및 적용 후, 영어 전환 시 런타임 보상/상점/툴팁 화면 확인
