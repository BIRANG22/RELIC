# 몬스터 정보 재활용 텍스트 갱신 설계

## 목적

몬스터 정보 패널의 스킬·상태 항목을 재활용하면서도 다른 몬스터를 표시할 때 이름과 설명이 즉시 새 데이터로 갱신되게 한다.

## 조사 결과

- `MonsterInfoSkillItemUI.Bind`와 `MonsterInfoStatusItemUI.Bind`는 재사용 항목의 텍스트를 새 데이터로 다시 설정한다.
- 블러 복제본도 `SyncNow`에서 원본 TMP의 `text`를 복사할 수 있다.
- 그러나 `BattleMonsterInfoCanvasUI`는 풀이 확장되어 계층이 증가한 경우에만 `RefreshBlurReplica`를 호출한다.
- 같은 수량의 항목을 재사용하면 계층이 증가하지 않으므로 재바인딩 직후의 복제 동기화가 생략되고 이전 몬스터의 표시가 남을 수 있다.

## 접근 방식

1. 패널을 열 때마다 블러 복제 트리를 폐기하고 다시 만든다. 표시 정확성은 확보되지만 기존 반복 개폐 프리징을 되살릴 수 있어 제외한다.
2. 패널을 닫을 때 모든 텍스트를 비운다. 일시적인 이전 표시만 완화하며 재바인딩 결과의 동기화 누락을 해결하지 못해 제외한다.
3. **선택:** 풀이 확장된 경우에만 복제 트리를 무효화하고, 재바인딩 후에는 확장 여부와 무관하게 현재 복제본을 즉시 동기화한다.

## 변경 범위

- `BattleMonsterInfoCanvasUI`의 블러 갱신을 계층 무효화와 프레젠테이션 동기화로 분리한다.
- 몬스터 표시, 상태 변경, 로케일 변경 뒤에는 항상 동기화를 요청하되 계층 재생성은 실제 풀 확장 때만 수행한다.
- 재사용된 원본 TMP와 기존 블러 복제 TMP 사이의 텍스트 동기화 회귀 테스트를 추가한다.

## 2026-11-23 보완 설계

- 패널을 열 때 선택된 몬스터의 이름, 미리보기, 스킬, 상태효과를 조건 없이 전체 재바인딩한다.
- 풀은 GameObject 재사용에만 사용하고 기존 표시값은 재사용하지 않는다.
- 몬스터 이름과 스킬·상태의 모든 동적 TMP는 `LocalizedTMPText.ProtectDynamicOwnership`으로 정적 로컬라이저의 후속 덮어쓰기를 차단한다.
- 전체 바인딩 완료 후 블러 프레젠테이션을 한 번 동기화한다.

## 2026-11-23 활성화 순서 보완

- `MonsterInfoPanel`이 비활성화된 동안 먼저 바인딩하지 않는다.
- 패널을 먼저 활성화해 자식 컴포넌트의 `OnEnable` 및 로컬라이즈 갱신을 완료시킨다.
- 그 다음 현재 선택된 몬스터의 이름, 미리보기, 행동, 상태를 조건 없이 다시 바인딩한다.
- 최종 바인딩 이후 캔버스와 블러 복제본을 동기화하여 활성화 콜백이 이전 행동 이름을 되살릴 수 없게 한다.

## 비범위

- 몬스터 데이터, 전투 상태, 풀의 생명주기 및 프리팹 구조는 변경하지 않는다.
- 블러 시스템 전체 구조를 재설계하지 않는다.

## 멀티플레이 경계

RuntimeData는 읽기만 하며 Command, State Change, Result/Event 및 네트워크 Snapshot에는 영향을 주지 않는다. 변경은 로컬 UI 프레젠테이션에 한정한다.
