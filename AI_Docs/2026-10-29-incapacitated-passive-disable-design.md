# 전투불능 캐릭터 패시브 비활성화 설계

## 의도

전투불능 캐릭터가 소유한 패시브가 턴 갱신 과정에서 다시 적용되는 문제를 수정한다. 패시브 갱신은 생존 캐릭터만 효과의 소유자가 될 수 있어야 한다.

## 현재 원인

- `RefreshAllPlayerPassives()`는 씬의 모든 `BattleCharacter`를 갱신한다.
- `RefreshRuntimePassiveEffects()`는 기존 패시브 상태를 제거한 뒤 `ShouldApplyPassive()` 결과에 따라 효과를 재적용한다.
- `ShouldApplyPassive()`가 패시브 데이터와 런타임 데이터의 존재만 검사하고 `runtime.IsDead`를 검사하지 않는다.
- 따라서 전투불능 캐릭터의 자기 대상·아군 대상·적 대상 패시브와 장비 패시브 추가 효과가 갱신 시 다시 적용될 수 있다.

## 권장 설계

1. 갱신 진입 시 기존 패시브 상태 제거는 유지한다.
2. `ShouldApplyPassive()`가 전투불능 런타임에 `false`를 반환하도록 한다.
3. 전투불능 캐릭터에는 `BattleEquipmentEffectService.ApplyPassiveExtras()`도 호출하지 않고 종료한다.
4. 생존 캐릭터의 카르마 수치와 무관한 기존 패시브 적용 규칙은 유지한다.

## 고려한 접근

- 선택: 패시브 서비스의 공통 런타임 갱신 경계에서 전투불능을 차단한다. 모든 호출 경로에 동일한 규칙이 적용되고 수정 범위가 작다.
- 제외: `RefreshAllPlayerPassives()` 순회 단계에서만 전투불능 캐릭터를 제외한다. 개별 `RefreshPassiveEffects()`와 초기 예약 콜백 같은 다른 진입점에서 재발할 수 있다.
- 제외: 사망 처리 시점에 소유자가 부여한 모든 외부 효과를 즉시 역추적해 제거한다. 현재 턴 갱신 구조보다 범위가 크고 별도 소유권 모델이 필요하다.

## 목표와 비목표

- 목표: 다음 패시브 갱신부터 전투불능 소유자의 패시브 및 장비 패시브 추가 효과를 적용하지 않는다.
- 목표: 전투불능 런타임에 남은 패시브 상태를 갱신 시 제거한다.
- 비목표: 사망 순간에 파티원·몬스터에게 이미 부여된 효과를 즉시 제거하는 신규 이벤트 시스템은 추가하지 않는다.
- 비목표: 패시브 데이터, 대상 정책, 사망 판정 구조를 재설계하지 않는다.

## 검증

- EditMode 테스트로 생존/전투불능 조건의 `ShouldApplyPassive()` 결과를 검증한다.
- 전투불능 런타임 갱신 시 기존 패시브 상태가 제거되고 비패시브 상태는 보존되는지 검증한다.
- 프로젝트 C# 컴파일로 코드와 테스트의 컴파일 오류가 없는지 검증한다.

## 멀티플레이 경계

런타임 데이터의 `IsDead` 상태를 기준으로 결정하므로 Scene Object나 UI 상태에 의존하지 않는다. 별도 네트워크 프레임워크는 추가하지 않으며, 향후 동일 런타임 스냅샷에서 결정적으로 같은 패시브 활성 여부를 얻을 수 있다.
