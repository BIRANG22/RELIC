# 전투 프레임 드랍 최적화 설계

## 목적

저사양 환경에서 전투 중 지속적으로 누적되는 CPU 비용을 줄인다. 전투 결과 계산은 변경하지 않고 캐릭터 하이라이트와 타임라인 UI의 표시 갱신만 최적화한다.

## 조사 결과

- `BattleCharacter.LateUpdate()`는 캐릭터마다 매 프레임 `FindFirstObjectByType`를 여러 번 호출한다.
- 같은 프레임에 동일한 튜토리얼/전투 실행 상태를 렌더러 반복문 안에서 다시 조회한다.
- 하이라이트가 보이지 않는 상태에도 애니메이터 상태 동기화와 `Animator.Update(0f)`가 수행된다.
- `BattleTimelineGroupUI.Update()`는 실행 중 각 예약 항목마다 `Transform`과 `TMP_Text`를 재귀 검색한다.

## 선택한 접근

1. 이벤트 구조 전체 개편: 장기적으로 가장 효율적이지만 변경 범위와 회귀 위험이 크다.
2. 프레임 간격 폴링: 구현은 작지만 UI 반응 지연과 불규칙한 갱신을 만든다.
3. **참조·계층 캐시와 상태 기반 조기 종료**: 기존 동작을 유지하면서 반복 검색과 불필요한 애니메이터 갱신을 제거한다.

이번 작업은 3번을 적용한다.

## 설계

- `BattleCharacter`는 전투 실행기, 이동 예약 컨트롤러, 튜토리얼 전환 프레젠터를 활성화 시 한 번 찾아 캐시한다.
- 한 프레임의 실행/튜토리얼/종료 상태를 한 번만 계산해 하이라이트 알파 처리에 전달한다.
- 선택 또는 호버 하이라이트가 실제로 보일 때만 애니메이터 시간 동기화를 수행한다.
- 하이라이트 표시 상태와 알파가 바뀌지 않았으면 렌더러 색상 재기록을 생략한다.
- `BattleTimelineGroupUI`는 `(orderIndex, size)`별 루트와 루트별 값 텍스트를 첫 조회 시 캐시한다.
- 캐시는 UI 초기화/재구성 시 비우고, 전투 데이터와 명령 구조는 변경하지 않는다.

## 비목표

- VFX 파티클, 셰이더, RenderTexture 해상도 조정
- 전투 규칙, 피해 계산, 예약 명령 및 네트워크 데이터 변경
- 전체 전투 UI의 이벤트 기반 구조 개편

## 검증

- 하이라이트 동기화 필요 조건 단위 테스트
- 타임라인 계층 조회 캐시 단위 테스트
- 런타임 및 Editor 어셈블리 컴파일
- 실제 저사양 기기 및 Unity Profiler 수치는 에디터/기기에서 별도 확인
