# 로컬라이징 영어·일본어 공란 보완 설계

## 목적

`Assets/ExcelSource/Localization.xlsx`의 `Text` 시트에서 한국어 원문이 존재하지만 영어 또는 일본어 번역이 비어 있는 셀을 보완한다.

## 조사 결과

- 한국어 원문이 있는 행: 1,741개
- 영어 공란: 147개
- 일본어 공란: 1,382개
- 중복 Key: 없음
- 기존 영어 번역: 1,594개
- 기존 일본어 번역: 359개

## 접근 방법

1. **전체 공란 보완(선택)**: 영어 147개와 일본어 1,382개를 모두 채운다. 요청 범위를 완전히 충족하며 이후 로케일 누락을 한 번에 제거한다.
2. 영어 우선 보완: 영어만 먼저 채운다. 작업량은 작지만 일본어 요청을 충족하지 못한다.
3. 화면 노출 항목만 선별 보완: 현재 사용되는 키만 채운다. 번역량은 줄지만 향후 콘텐츠에서 공란이 다시 노출될 위험이 있다.

전체 공란 보완을 적용한다.

## 번역 원칙

- 기존 영어·일본어 번역은 변경하지 않는다.
- 같은 한국어 원문이나 게임 용어의 기존 번역을 우선 재사용한다.
- 기존 영어 번역이 있는 행의 일본어는 영어와 한국어 문맥을 함께 사용한다.
- `{ValueRate1}`, `{Party1Name}`, `{E_Strike}` 같은 런타임 토큰과 리치 텍스트 태그를 원문과 동일하게 보존한다.
- 줄바꿈, 숫자, 부호 및 문장 역할을 유지한다.
- Key, Id, 한국어·중국어·스페인어 열, 행 순서, 시트 구조와 셀 서식을 변경하지 않는다.
- 원본 워크북을 같은 경로에 저장한다.

## 검증

- 한국어 원문이 있는 행의 영어·일본어 공란이 각각 0개인지 검사한다.
- 수정 전 존재하던 모든 셀 값이 그대로인지 비교한다.
- 한국어 원문과 각 번역의 중괄호 토큰 및 리치 텍스트 태그 집합이 일치하는지 검사한다.
- Key 중복, 수식 오류 및 시트 구조 변경 여부를 검사한다.
- 저장된 XLSX를 다시 열고 변경 범위를 렌더링하여 표시 상태를 확인한다.

## 비목표

- Unity String Table 가져오기 또는 코드 변경은 수행하지 않는다.
- 기존 번역의 문체 교정이나 전면 재번역은 수행하지 않는다.

## 멀티플레이 영향

표시용 번역 데이터만 변경한다. 전투 Command, 상태, 결과 이벤트, 랜덤 및 동기화 데이터에는 영향이 없다.
