# 전역 언어 폰트 일관성 설계

## 의도

언어별 폰트 Database에서 선택한 폰트가 같은 화면의 일반 TMP 전체에 일관되게 적용되도록 한다. 현재처럼 Localization 컴포넌트 유무나 표시 문자열의 문자권으로 적용 대상을 추측하면 새 DB 폰트와 씬·프리팹의 기존 직렬화 폰트가 섞이므로 이 추론을 제거한다.

## 목표

- 다국어 드롭다운과 Blur 복제본을 제외한 일반 TMP는 현재 Locale의 Database 폰트를 사용한다.
- 숫자 중심 텍스트는 `commonNumberFont`를 사용한다.
- 특수 연출 폰트는 `sourceFontRoles.preserveSourceFont`에 등록된 경우에만 원본을 유지한다.
- 명시적 `LocalizedTMPFont`의 역할 소유권은 유지한다.
- 언어 변경, 동적 텍스트 변경, 런타임 생성 TMP에도 같은 규칙을 적용한다.

## 비목표

- TMP Font Asset 자체의 glyph/atlas를 재생성하지 않는다.
- 씬과 프리팹의 모든 직렬화 폰트 참조를 대량 치환하지 않는다.
- 언어 선택 드롭다운처럼 한 화면에 여러 Locale을 동시에 표시하는 UI의 폰트 소유권을 변경하지 않는다.
- 전투 결과나 네트워크 상태를 변경하지 않는다.

## 고려한 접근

### 1. 모든 씬·프리팹의 폰트를 직접 치환

즉시 보이는 결과는 단순하지만 새 UI가 추가될 때 다시 누락되고, 씬 충돌과 대량 YAML 변경이 발생한다. 런타임 생성 TMP도 해결하지 못하므로 채택하지 않는다.

### 2. 기존 Localization/CJK 판정을 확대

예외를 조금씩 추가할 수 있지만 라틴어 동적 번역, 고정 문자열, 재사용 TMP에 따라 계속 오판한다. 현재 혼합 문제의 원인인 추론 구조를 유지하므로 채택하지 않는다.

### 3. 전역 기본 적용 + 명시적 예외

일반 TMP는 DB 폰트를 기본으로 적용하고, 다국어 드롭다운·Blur 복제·`preserveSourceFont`만 예외로 둔다. 새 UI도 기본 동작이 통일되며 특수 폰트만 데이터로 선언할 수 있어 이 방식을 채택한다.

## 적용 규칙

1. `DirectTemplateDropdown`이 소유한 TMP는 드롭다운이 항목 Locale 또는 공통 숫자 폰트를 적용한다.
2. `BlurReplicaRoot` 아래 TMP는 원본 결과를 복제하므로 전역 적용에서 제외한다.
3. `LocalizedTMPFont`가 있으면 해당 컴포넌트의 역할을 적용한다.
4. 원본 폰트가 `sourceFontRoles`에서 `preserveSourceFont`로 등록되어 있으면 원본을 유지한다.
5. 독립 TMP가 숫자 중심 문자열이면 `number`, 그 외에는 원본 폰트의 역할 매핑 또는 `body`를 사용한다.
6. DB 또는 Locale 매핑이 없으면 현재 폰트를 유지한다.

## 회귀 방지

- Localization 컴포넌트가 없는 라틴 문자열도 DB 본문 폰트로 변경되는 테스트를 추가한다.
- 숫자 문자열은 공통 숫자 폰트를 사용하는 테스트를 추가한다.
- 명시적 보존 폰트, 명시적 역할 소유자, 누락 Locale 유지 테스트는 기존 테스트를 유지한다.

## 멀티플레이 영향

클라이언트 TMP 표시 규칙만 변경한다. Command, State Change, Result/Event, Snapshot 및 네트워크 동기화에는 영향이 없다.
