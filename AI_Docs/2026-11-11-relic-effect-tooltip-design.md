# 유물 설명 효과 툴팁 설계

## 목적

모든 유물 설명에서 `{E_*}` 효과 토큰을 스킬 설명과 동일한 효과명 링크 및 밑줄로 표시하고, 설명 영역을 호버하면 포함된 효과의 정보 텍스트를 기존 상태효과 툴팁 UI로 보여준다.

## 범위

- 전투, 보상, 이벤트, 상점, 시작방, 가방, 로비 등 `RelicData`의 효과 설명을 표시하는 전체 UI에 적용한다.
- 중복 효과는 설명에 처음 등장한 순서로 한 번만 표시한다.
- 효과 토큰이 없거나 DB에 없는 효과는 정보 툴팁을 만들지 않는다.
- 전투 상태 계산과 유물 효과 실행 로직은 변경하지 않는다.

## 접근 방식

1. 화면별 구현: 각 UI 컨트롤러에서 토큰 변환과 툴팁을 개별 구현한다. 명시적이지만 누락과 중복이 크다.
2. 문자열만 공통 변환: 지역화 진입점에서 링크·밑줄만 적용한다. 시각 표시는 통일되지만 호버 정보가 없다.
3. 공통 포맷터와 공용 TMP 호버 컴포넌트: 지역화 진입점에서 형식을 통일하고, 재사용 가능한 컴포넌트가 기존 `UnitStatusEffectTooltipUI`를 호출한다.

3안을 채택한다. 설명 데이터와 효과 정보 UI를 재사용해 화면별 로직을 최소화하고, 향후 유물 표시 화면이 추가되어도 동일한 바인딩 API로 적용할 수 있기 때문이다.

## 구현 경계

- `RelicDescriptionFormatter`: 지역화된 설명의 효과 토큰을 링크로 바꾸고 링크 텍스트에 밑줄을 추가한다.
- `RelicEffectTooltipText`: TMP 텍스트와 결합해 링크된 효과 ID를 추출하고, 포인터 진입/이탈에 맞춰 기존 효과 정보 목록을 표시/숨긴다.
- `RelicDescriptionPresenter`: 유물 설명을 TMP에 설정하고 필요한 렌더러/호버 동작을 바인딩하는 단일 진입점이다.
- `GameDataLocalization.RelicEffectDescription`: 데이터만 필요한 호출도 일관된 포맷 문자열을 받도록 공통 포맷터를 사용한다.

## 제약 및 비목표

- 기존 효과 DB, 아이콘 DB, 지역화 문자열을 그대로 사용한다.
- 유물의 수치 플레이스홀더 처리 방식은 변경하지 않는다.
- 툴팁 프리팹이나 씬 계층을 새로 만들지 않는다.
- UI 표시 기능이므로 멀티플레이 동기화 대상과 전투 결과에는 영향이 없다.
