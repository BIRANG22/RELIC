# Undo/Redo 피드백·플립 무결성·아라벨라 2페이즈 BGM 설계

## 의도

키보드와 마우스의 Undo/Redo 피드백을 일치시키고, 실행 가능한 히스토리가 없는 버튼을 명확히 비활성화한다. 후속 행동이 없는 플립 예약은 다른 편집이 시작될 때 자동 제거하며, 아라벨라 2페이즈에 전용 BGM 상태를 제공한다.

## 목표

- Z/X 입력에도 Undo/Redo 버튼의 클릭 피드백을 재생한다.
- Undo/Redo 가능 여부에 따라 버튼 상호작용과 어두운 비활성 시각 상태를 즉시 갱신한다.
- 슬롯 변경, 예약 이동·재정렬, 행동 취소 시 후속 행동과 병합되지 않은 플립을 제거한다.
- 아라벨라 2페이즈 시작 후 전용 BGM 상태를 우선 적용하고, 클립 미연결 시 기존 보스 BGM을 유지한다.

## 비목표

- BGM 음원 제작 또는 임의 음원 연결
- Undo/Redo 히스토리 구조의 전면 재작성
- 네트워크 프레임워크 추가
- 플립이 이미 후속 행동의 `FlipBeforeAction`으로 병합된 경우의 제거

## 제약

- UI는 상태를 계산하지 않고 `BattleTimelineController`의 가능 여부와 결과 이벤트만 표현한다.
- 플립 정리는 안정적인 캐릭터 런타임 데이터와 예약 명령을 기준으로 수행한다.
- 씬/프리팹 참조는 기존 직렬화 구조를 유지하며 자동 생성 의존성을 늘리지 않는다.
- 테스트는 `Assets/Tests/EditMode~/` 아래에만 추가한다.
- Unity batchmode와 에디터 직접 제어는 사용하지 않는다.

## 검토한 접근

1. 각 키보드·버튼·드래그 진입점에서 개별 시각/정리 처리: 변경은 국소적이나 누락과 동작 불일치 위험이 크다.
2. 매 프레임 UI가 히스토리를 조회하고 모든 편집 뒤 전체 플립을 정리: 구현은 단순하지만 불필요한 폴링과 과도한 정리가 발생한다.
3. 상태 소유자인 타임라인 컨트롤러가 가능 여부·결과 이벤트와 미병합 플립 무결성을 관리하고 UI는 이벤트를 표현: 단일 기준을 유지하며 네트워크 적용 경계에도 동일 규칙을 적용할 수 있다.

선택: 3번. 전투 상태와 표현의 경계를 유지하고 모든 입력 경로에서 같은 결과를 보장한다.

## 설계

### Undo/Redo

`BattleTimelineController`가 정리된 히스토리를 기준으로 Undo/Redo 가능 여부를 공개하고, 상태 변경 및 성공한 실행 결과를 알린다. `BattleCharacterPanelUI`는 이를 구독해 버튼 `interactable`, 하위 그래픽의 비활성 색, 키보드/마우스 공통 클릭 피드백을 갱신한다. 실패한 명령은 클릭 피드백과 효과음을 재생하지 않는다.

### 미병합 플립

미병합 플립은 `IsFacingFlipCommand`인 독립 예약 명령이다. 동일 슬롯에서 바로 뒤에 같은 캐릭터 행동이 추가되면 기존처럼 `FlipBeforeAction`으로 병합된다. 그 전에 활성 슬롯을 바꾸거나, 예약 행동을 이동·재정렬하거나, 행동을 직접 취소하면 해당 편집으로 고립된 독립 플립을 제거한다. 제거 후 비용·시뮬레이션·타임라인·HUD·고스트를 한 번 갱신하고 히스토리에서도 제거된 플립 참조를 정리한다.

### 아라벨라 2페이즈 BGM

`BgmState.ArabellaPhase2`를 명시적인 새 값으로 추가한다. `ArabellaPhaseTransition`은 2페이즈 데이터가 실제 적용되는 시점에 프레젠테이션 이벤트를 발행한다. `BattleBgmDirector`는 이벤트를 구독해 전용 상태를 최우선 후보(패배 다음)로 평가한다. `SoundDatabase`에 클립이 연결되지 않았으면 후보 해석이 기존 보스 방 상태로 폴백한다.

- EditMode 테스트로 히스토리 가능 여부/이벤트, 플립 자동 정리 경계, BGM 우선순위와 미설정 폴백을 검증한다.
- `Assembly-CSharp.csproj`와 `Assembly-CSharp-Editor.csproj`를 빌드한다.
- 에디터 화면상의 실제 색·애니메이션·음원 청취는 수동 검증 항목으로 남긴다.
