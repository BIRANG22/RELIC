# 튜토리얼 이동 버튼 연속 클릭 방어 설계

## 의도

이동 버튼 안내 직후 사용자가 버튼을 빠르게 연속 클릭해도 이동 선택이 취소되지 않고, 다음 그리드 선택 단계를 정상적으로 진행할 수 있게 한다.

## 목표와 비목표

- 튜토리얼 표현이 진행 중일 때 동일 이동 버튼 재클릭을 멱등 처리한다.
- 일반 전투에서는 기존의 동일 이동 버튼 재클릭 취소 동작을 유지한다.
- 튜토리얼 데이터 순서, 이동 예약 결과, 전투 명령, 네트워크 동기화는 변경하지 않는다.

## 조사 결과

`BattleCharacterPanelUI`는 이동 버튼 클릭마다 `BattleTimelineController.ToggleMoveSkillSelection`을 호출한다. 이 메서드는 동일 캐릭터와 동일 이동 스킬이 이미 선택된 경우 선택 및 프리뷰를 취소한다. 튜토리얼의 이동 선택 단계가 첫 클릭으로 완료되고 그리드 선택 단계로 넘어가는 경계에서 두 번째 클릭이 들어오면 이 일반 전투용 토글 취소가 실행된다. 다음 단계의 포커스 방어막은 그리드만 허용하므로 사용자가 이동 스킬을 다시 선택할 수 없어 진행이 막힌다.

## 고려한 접근

1. 클릭 시간 디바운스: 간단하지만 프레임 속도와 입력 장치에 의존하고 정상적인 재입력까지 지연시킬 수 있어 제외한다.
2. 튜토리얼 단계 번호별 예외: 현재 데이터에는 맞지만 튜토리얼 순서와 입력 코드가 결합되어 제외한다.
3. 토글 호출에서 재클릭 취소 허용 여부를 명시: 일반 전투 동작을 보존하면서 튜토리얼 입력만 멱등 처리할 수 있어 채택한다.

## 설계

`BattleTimelineController.ToggleMoveSkillSelection`에 `allowDeselect` 선택 인자를 추가한다. 동일 선택 상태에서 이 값이 `false`이면 현재 선택을 유지하고 성공을 반환하며, `true`이면 기존처럼 취소한다. `BattleCharacterPanelUI`는 튜토리얼 표현 중 이동 버튼을 처리할 때만 `allowDeselect: false`를 전달한다.

회귀 테스트는 실제 `BattleTimelineController`에 동일 캐릭터와 이동 스킬 선택 상태를 구성하고, 취소 비허용 호출 후 선택이 유지되는지 확인한다. 기존 기본 인자 호출에서는 선택이 취소되는지도 함께 확인해 일반 전투 동작을 보호한다.

## 멀티플레이 경계

변경 대상은 로컬 입력의 선택/프리뷰 상태뿐이다. `PlayerReservedCommand`, 슬롯 상태, RuntimeId/CharacterId 기반 동기화, 전투 결과 계산은 변경하지 않으며 네트워크 프레임워크에도 영향이 없다.
