# 베스파 방향·그리드 효과 소유자·아라벨라 카메라 복구 구현 계획

**목표:** 실행 시점 베스파 공격 방향, 소환 그리드 효과의 소유자 면역, 아라벨라 카메라 복귀 순서를 수정한다.

**설계:** `AI_Docs/2026-11-15-vespa-grid-owner-arabella-camera-design.md`

**기술:** Unity C#, Text/YAML prefab, NUnit EditMode 테스트

## 제약

- 현재 작업 공간에서 작업하고 커밋·Push·PR은 수행하지 않는다.
- 테스트는 `Assets/Tests/EditMode~/`에만 작성한다.
- Unity 에디터 직접 제어와 batchmode 테스트는 수행하지 않는다.
- 전투 상태 결정은 UI/VFX와 분리하고 ID 기반으로 처리한다.

## 작업 1: 실패 테스트

- [ ] 베스파 예약 방향이 비고 반대 방향에 대상이 있을 때만 반전되는 정책 테스트를 추가한다.
- [ ] 그리드 효과 소유자가 배치·만료·제거 과정에서 보존 또는 정리되는 테스트를 추가한다.
- [ ] 동일 RuntimeId 생성자의 피해만 거부하는 테스트를 추가한다.
- [ ] 아라벨라 프리팹의 종료 카메라 복귀 설정 테스트를 갱신한다.

## 작업 2: 상태 및 실행 로직

- [ ] `BattleGridEffectState`에 소유자 ID 저장과 조회를 추가한다.
- [ ] 거미알 배치 시 아라벨라 RuntimeId/MonsterId를 기록한다.
- [ ] 저장 캡처·복원·복제에서 소유자 ID를 보존한다.
- [ ] 몬스터의 그리드 효과 피해에 생성자 면역 정책을 적용한다.
- [ ] 베스파 공격 실행 직전 양방향 유효 대상 여부로 방향을 보정하고 범위를 재계산한다.

## 작업 3: 카메라 및 검증

- [ ] 아라벨라 프리팹의 종료 카메라 복귀 옵션을 활성화한다.
- [ ] 에셋 불변조건과 C# 어셈블리 컴파일을 검증한다.
- [ ] Unity 화면 확인 및 EditMode 실행 불가 항목을 보고한다.

## 검토 초점

- 예약 방향에 대상이 있으면 불필요하게 반전하지 않는가
- 양방향 모두 비었을 때 기존 예약 방향을 유지하는가
- 소유자 없는 기존 그리드 효과와 이전 저장 데이터가 정상 동작하는가
- 효과 제거 후 소유자 정보가 남지 않는가
- 카메라 복귀가 입력 활성화 이전에 완료되는가
