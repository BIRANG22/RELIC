# 배틀 카메라 명시적 이동 포커스 설계

## 의도

Transform 위치 변화로 이동 유닛을 추측하는 방식을 제거하고, 실행 중인 행동이 카메라 포커스의 시작·전환·종료를 명시적으로 지휘한다. 돌진 넉백 공격은 `돌진자 추적 -> 충돌 -> 피격자 추적 -> 다음 행동/기본 구도`의 흐름을 보장한다.

## 목표

- 일반 Move 행동은 실제 이동 유닛을 부드럽게 추적한다.
- 돌진 공격은 돌진 중 공격자를 추적하고, 충돌 뒤 넉백되는 피격자에게 포커스를 한 번만 넘긴다.
- 넉백 종료 뒤에는 피격자 위치를 유지하고 다음 행동 또는 턴 종료 복귀에 카메라 소유권을 넘긴다.
- 복수 유닛의 우연한 Transform 변화가 카메라 포커스를 빼앗지 못하게 한다.

## 비목표

- 이동, 충돌, 피해, 넉백 판정은 변경하지 않는다.
- 네트워크 프레임워크나 전투 상태 동기화 구조를 추가하지 않는다.
- 이번 범위에서 복수 대상 전체 프레이밍 기능은 추가하지 않는다.

## 접근 방식

1. Transform 감지 유지 + 예외 추가: 수정량은 작지만 새로운 복합 이동마다 예외가 늘어나 제외했다.
2. 마지막 Transform 이동자 선택: 프레임 순서 의존성이 남아 제외했다.
3. 행동별 명시적 포커스 이벤트: 일반 이동과 돌진 넉백의 연출 의도를 정확히 표현할 수 있어 채택했다.

## 설계

- `BattleCameraController`에서 유닛 목록 검색, 위치 누적, 동시 이동 지연 선택을 제거한다.
- 직접 이동은 `BeginDirectGridMovement(Transform)`과 `EndDirectGridMovement(Transform)`으로 추적 범위를 명시한다.
- 돌진 공격은 기존 공격자 추적을 유지하며, 넉백 시점에 피격자의 강제 이동 애니메이션이 끝날 때까지 명시적으로 추적한다.
- 포커스 전환은 기존 카메라 이동 코루틴을 정리한 뒤 새 대상에게 한 번만 수행한다.
- 넉백 종료는 실시간 follow만 해제하며 즉시 기본 구도로 복귀하지 않는다. 다음 행동 카메라가 소유권을 가져가거나 턴 종료 시 기존 복귀 로직이 처리한다.

## 제약

- 문서와 계획은 `AI_Docs`에만 둔다.
- 테스트는 `Assets/Tests/EditMode~/` 아래에 둔다.
- Unity 에디터 직접 제어 및 batchmode 테스트는 하지 않는다.
- UI/VFX/카메라는 전투 결과를 계산하거나 변경하지 않는다.

## 멀티플레이 경계

카메라는 이미 결정된 이동·넉백 결과의 Transform을 연출 목적으로 추적할 뿐이다. Command, 전투 State Change, Result/Event에는 영향을 주지 않는다.
