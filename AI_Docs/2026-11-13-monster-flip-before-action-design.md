# 몬스터 행동 플립 병합 설계

## 의도

몬스터가 플레이어에게서 멀어지는 방향으로 이동한 뒤 공격하면 이동으로 바뀐 방향을 그대로 사용해 반대쪽을 공격하는 문제를 해결한다. 몬스터도 플레이어와 동일하게 다음 행동에 플립을 병합하고, 별도 타임라인 칸은 사용하지 않는다.

## 목표

- 몬스터 계획의 예상 방향과 행동의 목표 방향이 다르면 해당 행동에 `FlipBeforeAction`을 기록한다.
- 플립은 실행 직전에 몬스터의 방향 상태와 표시 방향을 함께 변경한다.
- 시뮬레이션, 실제 실행, 타임라인 하이라이트, 저장 복원, 멀티플레이 스냅샷이 같은 값을 사용한다.
- 계획 생성 중 실제 `RuntimeData.Direction`이나 `BattleUnitFacing`을 변경하지 않는다.

## 비목표

- 플립을 독립적인 몬스터 스킬이나 별도 타임라인 엔트리로 만들지 않는다.
- 몬스터별 이동·공격 선택 알고리즘이나 스킬 범위 규칙은 바꾸지 않는다.
- 플레이어 플립의 언두/리두 동작은 변경하지 않는다.

## 검토한 접근

1. 각 AI가 별도 플립 행동을 추가: 몬스터별 누락 가능성이 높고 칸을 차지하지 않는 병합 로직이 중복되므로 제외한다.
2. 공격 실행 시 항상 목표 쪽으로 자동 회전: 타임라인 계획에 방향 변경이 드러나지 않고 예약 결과와 실행 결과가 분리되어 제외한다.
3. 공통 몬스터 명령에 `FlipBeforeAction` 기록: 명령 데이터가 상태 변경 의도를 명시하고 플레이어 구조와 일치하므로 채택한다.

## 명령 및 계획

`MonsterReservedCommand`에 `FlipBeforeAction`과 설정 메서드를 추가한다. `BattleMonsterTurnPlanner`는 몬스터별 예상 방향을 현재 런타임 방향에서 시작해 행동 순서대로 갱신한다. 수평 이동은 예상 방향을 이동 방향으로 바꾸고, 강제 방향을 가진 비이동 행동의 방향이 예상 방향과 다르면 명령에 플립을 병합한 뒤 예상 방향도 갱신한다.

기존 개별 AI가 예약 계획을 만들면서 실제 방향을 변경하는 코드는 제거하고 `HasForcedDirection/ForcedDirection`으로만 의도를 전달한다.

## 실행과 시뮬레이션

실제 실행은 몬스터 명령 시작 직전에 플립을 적용한다. 시뮬레이션도 같은 순서로 예상 방향을 뒤집어 이후 공격 범위와 이동 계획에 반영한다. 플립은 행동에 병합되므로 `TimelineEntryCost`는 기존 행동 비용 그대로이며 별도 명령을 만들지 않는다.

## 표시

몬스터 타임라인 엔트리가 `FlipBeforeAction`을 가지면 플레이어 병합 플립과 동일한 하이라이트 색을 적용한다. 행동 아이콘과 이름은 원래 몬스터 행동을 유지한다.

## 저장 및 멀티플레이

몬스터 명령 저장/복원 데이터와 `BattleNetworkMonsterCommandSnapshot`에 `flipBeforeAction`을 포함한다. 동기화 단위는 런타임 오브젝트가 아닌 기존 `runtimeId` 기반 명령 스냅샷을 유지한다.

## 검증

- 이동 방향과 공격 방향이 반대면 플립 병합
- 같은 방향이면 플립 없음
- 플립 실행 시 런타임 방향과 표시 방향 변경
- 시뮬레이션과 실제 실행의 방향 일치
- 타임라인 비용 불변 및 몬스터 하이라이트
- 저장 및 네트워크 스냅샷 왕복 보존
