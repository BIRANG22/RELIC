# 전투 최대 자원 표시 기준 통합 설계

## 목적

중간 이벤트로 증가한 최대 마나와 최대 체력이 전투 파티 HUD에서 중복 합산되어, 실제 회복 상한보다 크게 표시되는 문제를 수정한다.

## 조사 결과

- 이벤트는 `RunMaxCostBonus`/`RunMaxHPBonus`를 누적하는 동시에 현재 런타임의 `MaxCost`/`MaxHP`도 즉시 갱신한다.
- 전투 시작 효과는 마스터 데이터와 런 보너스를 사용해 `MaxCost`/`MaxHP`를 최종 전투값으로 확정한다.
- 턴 종료 회복 및 개별 회복 경로는 최종값인 `MaxCost`를 상한으로 사용한다.
- 파티 HUD 두 구현만 `MaxCost + RunMaxCostBonus`, `MaxHP + RunMaxHPBonus`를 사용해 런 보너스를 다시 더한다.

## 선택한 설계

- `CharacterRuntimeData.MaxCost`와 `MaxHP`를 전투 중 최종 최대값의 단일 기준으로 유지한다.
- 파티 HUD 표시 및 변경 감지 해시는 런 보너스를 다시 더하지 않는다.
- 두 HUD가 동일한 규칙을 사용하도록 테스트 가능한 정적 해석 함수를 `BattleCharacterPanelUI`에 둔다.

## 고려한 대안

- 회복 상한에 `RunMaxCostBonus`를 추가하는 방식은 이미 포함된 보너스를 다시 더해 실제 자원 상태까지 잘못 확장하므로 제외한다.
- 이벤트에서 `MaxCost`를 갱신하지 않고 보너스만 저장하는 방식은 이벤트 직후 UI와 현재 마나 증가 동작을 광범위하게 바꾸므로 이번 수정 범위에서 제외한다.

## 검증

- 기본 최대값 10, 런 보너스 2, 최종 `MaxCost` 12인 런타임이 HUD에서도 12로 해석되는 테스트를 추가한다.
- 최대 체력도 같은 구조로 검증한다.
- 런타임 및 EditMode 테스트 어셈블리 컴파일을 확인한다.
