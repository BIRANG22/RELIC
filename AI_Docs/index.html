1. 프로젝트 개요

RELIC은 Unity 6 기반의 로그라이크 전술 RPG 프로젝트입니다. 핵심 코드는 Assets/Project/Scripts 아래에 집중되어 있고, 외부 VFX/GUI/TextMesh Pro 예제 에셋과 실제 프로젝트 에셋이 함께 존재합니다.

항목내용
엔진Unity 6000.0.68f1
렌더링Universal Render Pipeline, ShaderGraph, Post Processing
주요 패키지Input System, Localization, Cinemachine, AI Navigation, Timeline, UGUI, TextMesh Pro
데이터 원천Assets/ExcelSource/GameData.xlsx 및 런타임 Resources/Data/GameData 로딩 구조
주요 씬Bootstrap, Title, Lobby, Battle 중심

4. 실행 초기화 흐름

진입점은 Bootstrap이며, 각 전역 매니저를 순서대로 초기화한 뒤 상태 머신을 통해 첫 상태로 이동합니다.

Bootstrap.Start
Settings.Load
SaveSystem.Initialize
EventBus.Initialize
DataManager.Initialize
Audio/Input/UI Init
GameManager.Initialize
Localization Init
StateMachine.ChangeState

주요 파일

  • Assets/Project/Scripts/Core/Bootstrap.cs: 전역 초기화 순서 정의
  • Assets/Project/Scripts/Core/Managers/GameManager.cs: GameStateMachine과 GameStateContext 생성
  • Assets/Project/Scripts/Core/GameState/GameStateMachine.cs: 상태 등록/전환 처리
  • Assets/Project/Scripts/Core/GameState/SceneFlow/SceneFlowManager.cs: 씬 로딩 및 전환 연출 연결

8. 로비와 선택 흐름

로비는 캐릭터 선택, 파티 슬롯, 스킬/룬 세팅, 보상/성장 표시를 담당합니다. 선택 결과는 런타임 스토어에 저장되어 배틀 진입 시 사용됩니다.

  • Gameplay/Scene/Lobby: 캐릭터 선택, 파티 슬롯, 정보 툴팁, 스킬/룬 설정 패널
  • UI/Lobby: 로비 버튼, 스폰 그리드, 스킬 슬롯, 룬 슬롯, 보상 슬롯 UI
  • Gameplay/Runtime/Selection/PlayerSelectionData.cs: 플레이어 선택 상태 보관
  • Gameplay/Data/Managers: 캐릭터 선택, 장비, 성장, 파티, 보상, 퀘스트 관련 서비스

11. 몬스터 AI

몬스터 AI는 MonsterAIBase를 기반으로 몬스터별 파생 클래스를 두고, MonsterAIFactory에서 생성하는 구조입니다.

  • 기본 AI: DefaultMonsterAI
  • 개별 AI: BlobAI, BlightAI, EliseAI, MuckAI, RancorAI, VespaAI
  • 행동 결과: MonsterAIAction, MonsterAIPlan, MonsterAISlotPreference
  • 전투 실행 시 몬스터 명령은 MonsterReservedCommand와 BattleActionRunner로 연결됩니다.

13. 에셋과 데이터베이스

에셋 매핑은 런타임 데이터와 Unity 오브젝트를 분리하기 위한 ScriptableObject DB로 구성되어 있습니다.

  • Assets/DB: 캐릭터/몬스터 프리팹, 아이콘, 스킬 아이콘, 범위 아이콘, 유물/룬/아이템/상태효과 아이콘 DB
  • Assets/Project: 실제 프로젝트 씬, 스크립트, 프리팹, 리소스가 모이는 영역
  • Assets/TextMesh Pro, Assets/Fonts: 한국어/중국어/일본어 폰트와 TMP 설정
  • Assets/Vefects, VFXPACK_*: 전투 VFX와 데모 리소스
  • Assets/Test_asset_DJ: 테스트 또는 외부 GUI/배경 에셋

15. 리스크와 개선 포인트

  • 싱글톤 의존도: 전역 매니저가 많아 테스트와 멀티 세션 확장 시 결합도가 높아질 수 있습니다.
  • 씬 전환 결합: 상태 전환이 씬 로딩과 직접 연결되어 있어 멀티플레이나 비동기 로딩 정책을 넣을 때 별도 오케스트레이션 계층이 필요합니다.
  • 전투 실행 클래스 비대화: BattleActionRunner는 이동, 스킬, 몬스터 특수공격, 효과 적용까지 많은 책임을 가집니다. 기능 추가가 많아지면 플레이어/몬스터 실행기를 분리하는 것이 좋습니다.
  • 외부 에셋 혼재: 실제 프로젝트 에셋과 데모 에셋이 같은 Assets 아래에 많아 빌드 포함/참조 관리가 중요합니다.
  • 문자 인코딩: 일부 기존 문서와 로그 문자열이 깨져 보입니다. 문서/소스 파일의 UTF-8 통일이 필요합니다.
이 문서는 로컬 파일 구조와 주요 C# 소스 분석을 바탕으로 생성되었습니다. Unity 에디터 내 프리팹 연결 상태와 씬 Hierarchy의 세부 값은 별도 에디터 검증이 필요합니다.
