# 튜토리얼/UI 후속 수정 설계

## 조사 결과

- 메뉴 정렬값 `30002/30003`이 튜토리얼 설명창 `30120` 및 전투 튜토리얼 `32765`보다 낮다.
- 타임라인 스킬 툴팁은 부모 Canvas 기준 `+20`으로 정렬값을 다시 쓰므로 프리팹의 `30130`만으로는 보장되지 않는다.
- 공명 새로고침의 커스텀 애니메이션 초기화는 클릭 콜백 중 실행되어 Unity Button의 최종 Selected 상태보다 빠르다.
- 둥근모 TMP의 `?` 글리프는 잘못된 `ㅂ` 모양이라 제거되었고, 현재 `qus` 텍스트는 LiberationSans를 직접 사용한다. 프로젝트에 전용 `FontImage/question.png`가 존재한다.
- 거미줄 그리드의 배율 2가 상태 Stack에도 저장되지만 이동 코스트 계산은 별도 상수 2를 사용한다.
- 신규 몬스터 스킬 슬롯은 효과 링크에 밑줄을 넣지만 실제 몬스터 상세 패널 경로는 같은 후처리를 호출하지 않는다.

## 권장 설계

1. 튜토리얼 중 메뉴 루트/패널을 `32766/32767`로 올린다.
2. 스킬/효과 툴팁 루트에 명시적 `TutorialForegroundTooltipCanvas`를 배치하여 튜토리얼 중 `32765`를 사용한다.
3. 새로고침 클릭 완료 프레임 말에 EventSystem 선택과 Button 포인터 상태를 초기화한다.
4. 연성 슬롯의 네 `qus` TMP를 전용 question Sprite Image로 교체한다.
5. 거미줄 상태 Stack은 1로 저장하고 이동 코스트 2배는 기존 별도 규칙을 유지한다.
6. 몬스터 현재 상태명은 일반 표기로 되돌리고, 몬스터 스킬 설명의 effect 링크만 밑줄 처리한다.

## 멀티플레이 경계

거미줄 상태 데이터의 Stack 표현만 1로 정규화한다. 이동 비용 결과는 기존 Command 비용 계산에서 동일하게 2배이며, UI 정렬·폰트·밑줄·버튼 초기화는 전투 결과에 관여하지 않는다.
