# 전투 예약·튜토리얼·아라벨라 안정화 설계

## 의도

유물 제한 경고의 번역 누락, 튜토리얼 중 비허용 키 입력, 같은 슬롯의 연속 이동 분산, 실패한 예약 상태 잔존, 각성 아라벨라 전투 중 턴 실행 무한 대기를 함께 수정한다. 전투 핵심 상태는 UI 상태와 분리하고 기존 `Command -> State Change -> Result/Event` 흐름을 유지한다.

## 목표

- 봉인된 팔찌(`Relic_P_17`)의 슬롯 제한 경고를 현재 언어로 표시한다.
- 튜토리얼 중 현재 단계가 허용하지 않은 전투 키보드 입력을 차단한다.
- 같은 캐릭터가 같은 슬롯에 중간 행동 없이 연속 예약한 이동을 하나의 이동 명령으로 합친다.
- 슬롯 용량 초과 등 확정 거절된 행동의 선택·프리뷰·삽입 상태를 즉시 폐기한다.
- 겹쳐 실행되는 몬스터 후속 행동이 예외·중단되어도 턴 실행이 무한 대기하지 않도록 한다.

## 비목표

- 네트워크 프레임워크 변경
- 아라벨라 스킬 수치·AI 패턴 변경
- 튜토리얼 데이터나 진행 순서 변경
- 서로 다른 슬롯 또는 중간 행동을 사이에 둔 이동 병합

## 조사 결과

1. `battle.skill_slot_blocked`, `battle.skill_slot_limit` 키가 로컬라이제이션 테이블에 없어 `common.untranslated`로 대체된다.
2. `BattleActionRunner.RunSequential`의 겹침 후속 코루틴 대기는 제한시간과 예외 안전 완료 처리가 없다. 완료 콜백이 호출되지 않으면 `BattleTurnExecutor`가 종료되지 않아 HUD와 ESC 입력이 계속 잠긴다.
3. 튜토리얼은 마우스 레이캐스트 방어막은 제공하지만 키보드 입력은 여러 컴포넌트가 서로 다른 조건으로 검사한다.
4. `PlayerReservedCommand.MergeMoveReservation`은 이미 존재하지만 현재 병합 진입 조건은 제자리 방향 전환에 한정된다.
5. 예약 시작 단계의 용량 거절은 `selectedSkill`만 해제하고 `PlayerSkillReservationController` 프리뷰와 pending insertion을 일관되게 정리하지 않는다.

## 고려한 접근

### 접근 A: 각 증상 발생 지점에 개별 조건 추가

변경량은 작지만 입력·예약 상태 정리가 여러 호출부에 다시 분산되고 같은 누락이 재발하기 쉽다.

### 접근 B: 공통 정책과 종료 경로로 수렴 — 채택

튜토리얼 키 입력은 단일 허용 정책을 사용하고, 예약 거절은 공통 정리 경로를 사용한다. 겹침 행동은 제한시간과 `finally` 기반 완료 보장을 갖는다. 기존 구조를 크게 바꾸지 않으면서 상태 일관성을 테스트할 수 있다.

### 접근 C: 전투 입력·예약 시스템 전체 상태 머신 재작성

장기적으로 명확할 수 있지만 이번 버그 범위를 크게 벗어나며 회귀 위험이 높아 제외한다.

## 상세 설계

### 로컬라이제이션

장비 슬롯 차단과 최대 사용 슬롯 수 제한을 `LocalizationKeys`에 정의하고 공용/한국어/영어 테이블에 추가한다. 현재 사용자 변경이 있는 로컬라이제이션 파일은 해당 엔트리만 추가해 보존한다.

### 아라벨라 및 턴 실행 안전성

겹쳐 실행되는 후속 행동도 기존 `actionRoutineTimeout`을 사용한다. 래퍼 열거자는 `finally`에서 완료 신호를 보장하고, 대기 측은 제한시간 초과 시 후속 코루틴을 중단한 뒤 행동 라벨과 몬스터 안정 ID/스킬 ID를 로그로 남긴다. `BattleTurnExecutor`의 기존 `finally`가 실행되어 HUD·입력 상태를 복구할 수 있게 한다. 페이즈 연출 잠금도 중단 경로에서 해제되도록 방어한다.

### 튜토리얼 키 입력

`TutorialBattleSequence`가 현재 튜토리얼 표현 상태와 포커스 가이드의 허용 정보를 바탕으로 전투 단축키 허용 여부를 단일 메서드로 제공한다. 타임라인 숫자/방향/Undo·Redo, 캐릭터 행동 단축키, 턴 종료 입력이 이 정책을 사용한다. ESC는 기존 메뉴 동작을 유지한다.

### 연속 이동 병합

병합 대상은 같은 슬롯의 마지막 실질 명령이 같은 `CharacterId`의 일반 이동이고 새 명령도 일반 이동일 때로 제한한다. 명시적 중간 삽입, 방향 전환 명령, 다른 행동 뒤의 이동은 병합하지 않는다. 병합 시 이동 경로, 최종 `GridIndex`, 방향, 거리 기반 비용을 기존 `MergeMoveReservation`으로 갱신하며 타임라인 점유는 하나로 유지한다.

### 거절된 예약 폐기

예약 시작 또는 확정 단계에서 용량·장비 제한 등 재시도 불가능한 거절이 발생하면 선택된 스킬, 그리드 프리뷰, pending insertion을 함께 정리한다. 이미 만들어진 명령을 보류하거나 용량이 생겼을 때 자동 재시도하지 않는다. 복수 명령 등록 실패는 기존 롤백과 함께 선택 상태도 폐기한다.

## 검증

- 새 테스트는 `Assets/Tests/EditMode~/` 아래에만 작성한다.
- 로컬라이제이션 키 존재 및 한국어 값, 이동 병합 조건, 예약 거절 정리 정책, 튜토리얼 키 허용 정책, 겹침 행동 완료/시간 초과 정책을 회귀 테스트한다.
- Unity batchmode는 사용하지 않는다. 코드·YAML 정적 검사와 사용 가능한 프로젝트 컴파일 명령을 수행하고, 에디터 화면 재현이 필요한 항목은 미검증으로 보고한다.

## 멀티플레이 경계

병합 결과는 기존 `PlayerReservedCommand` 하나로 스냅샷/동기화되며 Scene Object가 아닌 `CharacterId`, 슬롯 인덱스, GridIndex를 사용한다. UI는 결과를 계산하지 않고 예약 상태 결과만 표시한다. 네트워크 프레임워크 변경은 없다.
