# 아라벨라 하강 및 복합 이동 스킬 연출 수정 설계

## 조사 결과

- 아라벨라 `S_Monster_39`는 상승 준비 상태 `AttackAction5_b_1`과 하강·착지 상태 `AttackAction5_b_2`가 프리팹에 모두 연결되어 있다.
- 현재 실행기는 상승과 하강 위치 보간을 모두 끝낸 뒤 `PlayMonsterSkillActionPhase`를 호출한다. 따라서 하강 중에는 상승 상태가 유지되고 착지 뒤에 하강·착지 상태가 늦게 시작된다.
- 플레이어 공격 스킬에 포함된 `E_Move`는 `ExecutePlayerDirectionalMoveEffect`에서 `PlayMove()`를 직접 호출한다. `PlayMove()`는 공통 이동 상태와 `moveVfx`를 동시에 재생하므로 스킬 고유 연출과 중복된다.

## 권장 설계

1. 아라벨라 도약 위치 보간 루틴에 하강 시작 콜백을 전달한다.
2. 상승 종료 후 착지점 상공으로 위치를 옮긴 직후, 하강 보간 전에 `PlayMonsterSkillActionPhase`를 호출한다.
3. 착지 완료 뒤의 기존 Action Phase 호출은 제거하여 애니메이션과 VFX가 중복되지 않게 한다.
4. 공통 이동 연출은 독립 이동 명령에서만 허용한다.
5. 공격·버프·디버프 스킬 내부의 방향 이동 효과는 위치, 점유, 충돌, 출혈, 그리드 효과를 그대로 처리하되 `PlayMove()`를 호출하지 않는다.

## 전투 및 멀티플레이 경계

- 위치 및 점유 상태 변경 순서는 유지한다.
- 연출 호출 시점과 연출 선택만 변경하므로 전투 결과 데이터에는 영향이 없다.
- 네트워크 동기화 대상이 될 Command, RuntimeId, GridIndex 기반 상태에는 새 의존성을 추가하지 않는다.
