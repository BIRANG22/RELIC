# 예약 이동 경로 우선 실행 설계

## 목표

플레이어 이동은 실행 시점의 목표 위치 재탐색보다 예약 시 저장된 `VisualMoveSteps` 순서를 우선한다.

## 실행 규칙

- 같은 축·같은 방향으로 연속된 스텝은 하나의 이동 구간으로 묶는다.
- 축 또는 방향이 바뀌면 새 이동 구간을 시작한다.
- 한 구간이 유닛, 막힌 그리드 또는 맵 경계에 막히면 그 구간의 남은 이동만 중단한다.
- 막힌 구간에서 충돌 결과는 한 번만 발생한다.
- 이후 구간은 실제 도착 위치에서 계속 시도한다.
- 실행 시 목표 위치를 기준으로 경로를 다시 탐색하지 않는다.
- 예약 시 확정된 이동 코스트를 그대로 소비하며 실제 이동 거리로 다시 계산하거나 환급하지 않는다.

## 예시

- `오른쪽 1, 아래 1`: 오른쪽이 막히면 충돌을 한 번 처리하고 현재 위치에서 아래 1칸을 시도한다.
- `오른쪽 2`: 첫 칸의 몬스터에 막혀도 같은 오른쪽 구간에서 충돌은 한 번만 처리한다.
- `오른쪽 2, 아래 1`: 오른쪽으로 1칸 이동한 뒤 두 번째 칸이 막히면 그 위치에서 아래 1칸을 시도한다.

## 구조

`PlayerReservedCommand`가 예약 경로를 결정론적인 이동 구간으로 변환한다. 예약 시뮬레이션과 실제 실행기가 동일한 구간 데이터를 소비한다.

전투 상태 변경은 예약 명령의 안정적인 `CharacterId`, 그리드 인덱스와 경로 스텝을 기준으로 수행한다. 카메라, VFX, 애니메이션은 계산 결과를 재생할 뿐 이동 결과를 결정하지 않는다.
