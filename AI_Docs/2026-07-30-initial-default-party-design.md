# 최초 기본 파티 구성 설계

## 목표

게임 실행 후 데이터와 저장 정보 로드가 끝났을 때 파티가 완전히 비어 있으면
`Char_01`, `Char_02`, `Char_03`을 파티 슬롯 0~2에 기본 편성한다.
기존 저장 또는 사용자가 구성한 파티가 하나라도 있으면 변경하지 않는다.

## 조사 결과

- `Bootstrap.Start()`는 마스터 데이터를 불러온 뒤 `SaveSystem.TryLoadProgress()`를 호출한다.
- 신규 실행에서 저장 데이터가 없으면 `PartyRuntimeStore`와 `CharacterRuntimeStore`는 비어 있다.
- `StartModeButton`은 새 탐사 데이터를 정리하지만 로비 파티 구성은 유지한다.
- 로비 캐릭터 선택 UI의 기본 배치칸은 슬롯 순서대로 그리드 인덱스 6, 7, 8이다.
- Steam 로비 호스트는 현재 `PartyRuntimeStore`를 최초 권한 스냅샷으로 사용한다.

## 접근 방식

1. **Bootstrap 데이터 초기화 방식 — 채택**
   저장 로드 직후 독립된 초기화 서비스로 빈 파티만 구성한다.
   씬 UI 생성 순서에 의존하지 않고 싱글 및 Steam 호스트의 최초 파티가 동일하다.
2. LobbyState 진입 방식
   로비에 들어갈 때마다 검사할 수 있지만 사용자가 파티를 모두 비운 뒤 로비에 재진입하면
   의도치 않게 기본 파티가 다시 생길 수 있다.
3. Lobby UI 초기화 방식
   구현은 간단하지만 파티 핵심 데이터가 특정 씬 오브젝트와 실행 순서에 의존하게 된다.

## 구성

- `InitialDefaultPartySetup`
  - 파티가 완전히 비어 있는지 확인한다.
  - 세 기본 캐릭터 마스터 데이터가 모두 존재하는지 먼저 검증한다.
  - 누락된 캐릭터 런타임을 마스터 데이터 기준으로 생성한다.
  - 파티 슬롯 0~2에 캐릭터 ID와 배치 그리드 6~8을 저장한다.
  - 검증 실패 시 파티를 부분 변경하지 않는다.
- `Bootstrap`
  - `DataManager.Initialize()`와 `SaveSystem.TryLoadProgress()` 다음에 초기화 서비스를 호출한다.

## 데이터 및 멀티플레이 경계

초기 상태는 Scene Object가 아닌 `CharacterId`, 슬롯 인덱스, 그리드 인덱스로 저장한다.
Steam 로비가 만들어지기 전에 로컬 런타임에만 적용되고, 이후 기존 호스트 권한 스냅샷
흐름이 이 상태를 동기화한다. 네트워크 명령, 전투 상태, 결과 계산은 변경하지 않는다.

## 검증

- 빈 파티에는 `Char_01~03`과 그리드 6~8이 생성된다.
- 기존 파티가 하나라도 있으면 파티와 캐릭터 런타임을 변경하지 않는다.
- 기본 캐릭터 마스터 데이터가 누락되면 부분 파티를 만들지 않는다.
- 런타임 및 Editor 어셈블리 빌드와 관련 EditMode 테스트 소스 컴파일을 확인한다.
