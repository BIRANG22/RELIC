# 아라벨라 2페이즈 전환 설계

## 목표

- 보스 맵의 기본 아라벨라를 `Mon_12_1`로 스폰한다.
- `Mon_12_1`의 HP가 0이 되면 일반 사망으로 처리하지 않고 같은 전투 개체를 `Mon_12_2` 데이터로 전환한다.
- 전환 시 `Mon_12_2`의 최대 HP, 방어도, 스킬, 특성 등 마스터 데이터를 새로 적용한다.
- `Mon_12_2`가 사망할 때만 기존 최종 사망, 보상, 전투 종료 흐름을 실행한다.
- 두 페이즈 모두 기존 `Arabella.prefab` 하나를 사용한다.

## 구조

전투 핵심 상태는 다음 순서로 처리한다.

`HP 0 결과 -> 아라벨라 페이즈 전환 판정 -> Mon_12_2 상태 생성/교체 -> 페이즈 전환 연출`

- `ArabellaPhaseTransition`은 ID 기반으로 전환 가능 여부를 판정하고, 기존 `RuntimeId`와 방향을 유지한 `Mon_12_2` 런타임 데이터를 생성한다.
- `BattleDeathService`는 일반 사망 처리보다 먼저 전환을 시도한다. 성공하면 보상 수집, 런타임 등록 해제, 오브젝트 제거를 수행하지 않는다.
- `MonsterUnit`은 새 런타임 데이터로 다시 초기화하여 2페이즈 AI와 표시 이름을 갱신한다.
- `BattleUnitAnimator`는 `2phase` 상태를 재생한다. 애니메이션 완료 여부는 상태 전환 성공이나 전투 결과를 결정하지 않는다.
- `2phase` 연출 시간이 끝나면 `Idle_b`로 복귀한다. 반복 설정된 클립이나 애니메이션 이벤트에 전투 진행을 의존하지 않는다.
- K 디버그 처치는 2페이즈로 전환된 생존 몬스터가 있으면 전투 실행기를 종료하지 않는다.
- 아라벨라 AI는 현재 페이즈 런타임 데이터의 `PossSkillIds`에 포함된 스킬만 예약한다. CSV의 기존 페이즈별 스킬 구성은 변경하지 않는다.

## 애니메이션 선택

아라벨라 2페이즈에서는 같은 Animator Controller 안의 `_b` 상태를 사용한다.

- `Idle -> Idle_b`
- `Move -> Move_b`
- `Guard -> Guard_b`
- `Hit -> Hit_b`
- `Dead -> Dead_b`
- `AttackActionN -> AttackActionN_b` (해당 상태가 실제로 존재할 때만 사용)

상태가 존재하지 않으면 기존 상태명으로 폴백하여 다른 몬스터와 기존 프리팹 동작에 영향을 주지 않는다.

## 데이터와 프리팹

- `Battlemap_16`의 몬스터 ID를 `Mon_12_1`로 변경한다.
- `MonsterPrefabDatabase`의 `Mon_12_1`, `Mon_12_2`가 같은 `Arabella.prefab`을 가리키는 현재 구성을 유지한다.
- 씬이나 프리팹을 새로 생성하지 않는다.

## 검증

- 1페이즈 사망 시 2페이즈 데이터가 생성되고 HP가 완전히 회복되는지 확인한다.
- `RuntimeId`, 방향, 그리드 점유와 게임 오브젝트가 유지되는지 확인한다.
- 2페이즈 사망은 다시 전환되지 않는지 확인한다.
- 2페이즈 애니메이션 상태명이 `_b` 상태로 해석되는지 확인한다.
- `2phase` 연출 후 `Idle_b`로 복귀하고 K 디버그 이후 전투가 계속되는지 확인한다.
- AI가 다른 몬스터의 구형 스킬 ID를 예약하지 않는지 확인한다.
- 프로젝트 컴파일과 관련 EditMode 테스트를 실행한다.
