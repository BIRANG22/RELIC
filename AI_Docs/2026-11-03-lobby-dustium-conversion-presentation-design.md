# 로비 더스티움 전환 연출 개편 설계

## 의도

전투 종료 후 로비에서 표시하던 연구 결과 패널과 복합 환산 정보를 제거한다. 전투 중 최종 보유한 레드 더스티움만 같은 수량의 블루 더스티움으로 1:1 전환하고, 별도 확인 없이 로비 화면 위에서 전환 과정을 짧은 비모달 연출로 보여준다.

전투 종료에 필요한 경험치 반영, 가방 아이템 이전, 전투 런타임 정리, 장비 복원, 저장과 로비 전환은 유지한다.

## 목표

- 레드 더스티움 `N`을 블루 더스티움 `N`으로 1:1 전환한다.
- 유물과 기억은 블루 더스티움으로 환산하지 않는다.
- 기존 연구 결과 패널, 결과 텍스트, 확인 버튼을 표시하지 않는다.
- 로비 중앙의 레드 더스티움 아이콘과 숫자가 감소하고, 붉은 원형 블러가 블루 더스티움 HUD로 이동하면서 파란색으로 변한다.
- 전환 진행에 맞춰 블루 더스티움 HUD 숫자가 이전 보유량에서 최종 보유량까지 증가해 보인다.
- 연출이 중단되어도 실제 보상과 가방 아이템이 유실되거나 중복 지급되지 않는다.

## 비목표

- 전투 중 레드 더스티움 획득 및 소비 구조는 변경하지 않는다.
- 경험치, 튜토리얼 완료, 전투 장비 복원, 탐사 런타임 정리 규칙은 변경하지 않는다.
- 연출 완료 여부로 실제 재화 지급을 결정하지 않는다.
- 네트워크 프레임워크나 신규 전투 동기화 데이터를 추가하지 않는다.

## 현재 구조

- `ExplorationResultPanelUI.ReturnToBase`가 전투 결과에서 pending 연구 결과를 만들고 전투 종료 정리를 수행한 뒤 로비로 이동한다.
- `ResearchConversionPolicy`는 레드 더스티움을 절반으로 줄이고 유물·기억 희귀도에 따라 블루 더스티움을 추가한다.
- 로비의 `ResearchResultPanelUI`가 pending 결과를 1회 적용하고 결과 패널과 확인 버튼을 표시한다.
- `PendingResearchSettlementService.ApplyOnce`는 블루 더스티움 지급과 가방 아이템 이전을 함께 처리한다.
- `LobbyBlueDustiumHudUI`는 실제 보유량을 읽어 숫자를 갱신한다.

## 검토한 방식

### 1. 데이터 선반영 후 표시값만 전환 연출 — 선택

로비 진입 시 pending 결과를 한 번만 적용하고 저장한다. 실제 블루 더스티움은 즉시 최종값이 되지만 HUD 표시값은 이전 보유량에서 시작해 연출 진행률에 맞춰 증가한다.

장점은 씬 전환, 비활성화, 애플리케이션 종료 또는 VFX 누락이 발생해도 지급 결과가 안전하다는 점이다. UI와 VFX가 결과 계산에 관여하지 않아 프로젝트의 전투·멀티플레이 경계 규칙에도 맞는다.

### 2. 연출 프레임마다 실제 재화 순차 지급 — 제외

표시와 데이터가 항상 같은 값을 갖지만 연출 중단 복구, 저장 빈도, 호스트 동기화와 중복 방지가 복잡하다. VFX 진행이 재화 상태 변경을 결정하므로 채택하지 않는다.

### 3. 연출 완료 후 일괄 지급 — 제외

구현은 단순하지만 연출 중 로비를 벗어나거나 오브젝트가 비활성화되면 보상이 누락될 수 있다. 안전한 정산보다 연출 완료에 의존하므로 채택하지 않는다.

## 데이터 설계

### 전투 종료 시 pending 생성

- 기존 `ExplorationResultData`는 전투 결과 전달과 가방 아이템 이전을 위해 유지한다.
- pending 블루 보상은 `ExplorationResult.Remnant`의 음수 방지 값만 사용한다.
- `researchRewardMultiplier`, 레드 더스티움 `/ 2`, 유물 희귀도 환산, 기억 희귀도 환산은 제거한다.
- 기존 저장에 남아 있는 `RemnantBlue`, `RelicBlue`, `SkillBlue`, `TotalBlue` 값은 새 정산의 근거로 사용하지 않는다. 항상 `ExplorationResult.Remnant`를 기준으로 1:1 정산한다.

### 로비 진입 시 원자적 정산

1. pending 결과에서 레드 더스티움 수량과 가방 아이템 목록을 읽는다.
2. 정산 전 블루 더스티움 보유량을 연출 시작값으로 캡처한다.
3. 호스트 권한이 있는 로컬 인스턴스에서 블루 더스티움을 1회 증가시키고 가방 아이템을 이전한다.
4. 적용 상태와 로비 데이터를 저장하고 호스트 스냅샷을 발행한다.
5. 연출은 캡처한 이전 값과 최종 값을 사용하며 실제 데이터를 다시 변경하지 않는다.
6. 연출이 완료되거나 생략되면 pending 결과를 정리한다. 이미 적용된 pending은 다시 지급하지 않는다.

레드 더스티움이 0이어도 가방 아이템 이전과 pending 정리는 수행하고 전환 연출만 생략한다.

`ApplyOnce`는 UI가 정산식을 다시 계산하지 않도록 정산 전 블루 보유량, 정산 후 보유량, 전환된 레드 더스티움 수량과 적용 여부를 결과 구조체로 반환한다. 기존 저장 호환을 위해 `RemnantBlue`, `RelicBlue`, `SkillBlue`, `TotalBlue` 직렬화 필드는 즉시 삭제하지 않되 새 정산에서는 읽거나 쓰지 않는다.

지급 저장 후 애플리케이션이 연출 도중 종료된 경우 다음 실행에서는 `IsApplied` pending을 다시 지급하거나 재연출하지 않고 정리한다. 보상 안전성을 우선하며 중단된 장식 연출은 이어서 재생하지 않는다.

## UI 및 연출 설계

기존 `ResearchResultPanel` 씬 오브젝트는 결과 패널이 아니라 로비 전환 연출 루트로 재구성한다. 고정 UI 요소는 런타임 생성하지 않고 `Lobby.unity`에 직렬화하여 배치한다.

### 구성

- 전체 화면 투명 연출 루트: 레이캐스트를 막지 않는 비모달 CanvasGroup
- 중앙 레드 더스티움 그룹
  - 이동하지 않는 레드 더스티움 아이콘
  - 남은 전환량 텍스트
- 이동 연출 그룹
  - 고정 아이콘과 분리된 붉은 원형 소프트 블러 Image
  - 이동 중 색상을 빨강에서 파랑으로 보간
  - 시작은 중앙 그룹, 끝은 `BlueDustiumHUD` 아이콘 위치
- 블루 더스티움 HUD
  - 연출 중 일반 자동 갱신을 일시 중지하고 기존 `SetValueImmediate`로 표시값만 제어
  - 완료 시 컴포넌트를 복구하고 실제 데이터 값으로 동기화

기존 `ResearchResultPanel`의 부분 화면 앵커는 풀스크린 앵커로 변경한다. 고정 레드 더스티움 아이콘은 기존 아이콘 리소스를 유지하고, 이동체는 프로젝트에 포함된 소프트 원형 글로우 텍스처를 사용하는 별도 `RawImage`로 구성한다. 이후 아트가 텍스처를 교체할 수 있도록 명시적 직렬화 참조로 둔다. 이동 시간, 곡선 높이, 색 전환 시점과 도착 펄스 크기는 인스펙터 값으로 노출한다.

### 재생 순서

1. 로비 첫 렌더 전에 HUD 표시값을 정산 전 블루 보유량으로 고정한다.
2. 중앙에 고정 레드 아이콘과 전체 획득량을 페이드/스케일 인한다.
3. 전환 구간 동안 중앙 숫자를 `N → 0`, HUD 숫자를 `기존값 → 기존값 + N`으로 같은 진행률에서 보간한다.
4. 고정 아이콘 위치에서 별도 붉은 원형 블러가 출발해 곡선으로 HUD 아이콘을 향해 이동하며 중후반부터 파란색으로 전환된다. 고정 레드 아이콘은 이동하지 않는다.
5. 도착 시 HUD 아이콘에 짧은 펄스와 파란 잔광을 재생한다.
6. 남은 수량이 0이 되면 고정 레드 아이콘과 숫자를 함께 숨긴다. 이동 블러의 도착 연출 후 HUD 표시값을 실제 데이터에 다시 연결한다.

연출은 로비 입력을 막지 않는다. 누락된 아이콘, 효과 루트 또는 HUD 참조가 있으면 즉시 최종 표시값으로 복구하고 정산은 유지한다.

기존 `LobbyBlueDustiumHudUI`는 비 UTF-8 소스라 인코딩을 강제 변환하지 않는다. 연출 조정자가 HUD 컴포넌트의 일반 갱신을 일시 중지하고 기존 `SetValueImmediate`로 표시값을 제어한다. 연출 종료 또는 중단 시 원래 활성 상태를 복구하고 `Refresh`로 실제 저장값에 동기화한다.

## 코드 책임

- `ExplorationResearchService`: 레드 더스티움 1:1 pending 데이터 생성. 희귀도 DB 조회 및 환산 제거.
- `PendingResearchSettlementService`: 레드 더스티움 1:1 블루 지급과 가방 아이템 이전을 원자적으로 처리.
- `ResearchResultPanelUI`: 패널/확인 흐름을 제거하고 로비 전환 연출 조정자 역할로 축소 또는 역할에 맞게 이름 변경.
- `LobbyBlueDustiumHudUI`: 기존 코드는 보존하며, 연출 조정자가 컴포넌트 활성 상태와 `SetValueImmediate`를 이용해 표시값만 제어.
- `ExplorationResultPanelUI`: 기존 전투 종료 정리 흐름을 유지하며 새 pending 생성 방식을 사용.
- `Lobby.unity`: 기존 결과 패널 자식을 제거하고 중앙 레드 표시 및 이동 효과를 명시적으로 배치·연결.

## 멀티플레이 경계

- 블루 더스티움과 가방 아이템 변경은 기존처럼 호스트 권한 경계에서만 수행한다.
- 정산 결과는 기존 로비 스냅샷 발행 흐름을 사용한다.
- 비호스트는 전달받은 pending/스냅샷으로 연출만 재생하며 재화를 직접 변경하지 않는다.
- 연출 상태는 동기화 대상이 아니며 실제 보유량은 호스트 스냅샷을 기준으로 한다.

## 테스트 및 검증

- 레드 더스티움 `N`이 블루 더스티움 `N`으로 지급되는지 EditMode 테스트
- 유물과 기억이 블루 더스티움에 영향을 주지 않는지 테스트
- 가방 아이템 이전이 유지되는지 테스트
- 같은 pending을 두 번 적용해도 중복 지급되지 않는지 테스트
- 레드 더스티움 0일 때 재화 연출은 생략되지만 가방 아이템은 이전되는지 테스트
- HUD 외부 표시 모드가 실제 데이터 변경 없이 시작값, 중간값, 최종값을 표시하는지 테스트
- 런타임 및 에디터 어셈블리 컴파일
- 씬 YAML에서 연출 루트, 레드 아이콘, 숫자, 이동 효과, 블루 HUD 참조 확인

Unity 에디터 화면에서의 곡선 이동, 블러 강도, 색 전환 시점과 실제 연결감은 수동 확인 대상으로 남긴다.
