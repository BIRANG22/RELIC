# 전투 전멸 패배 연출 설계

## 목표

모든 아군 캐릭터의 HP가 0이 되어 전멸이 확정되면 기존 탐사 결과 패널을 즉시 표시하지 않고, 전장 위에서 패배 연출을 먼저 재생한다.

- 검은 안개가 화면 위에서 아래로 내려오며 전장과 전투 UI를 가린다.
- 쓰러진 아군 캐릭터 3명은 실제 전투 오브젝트를 유지한 채 화면 중앙으로 이동한다.
- 이동 직전 월드 `x` 좌표 순서를 보존하여 좌·중·우 위치에 배치한다.
- 캐릭터의 쓰러진 애니메이션 상태와 바라보는 방향은 변경하지 않는다.
- 캐릭터 3명을 완만한 포물선 형태로 가로 배치하고 `탐사 실패` 문구를 표시한다.
- 설정된 시간이 지나면 패배 연출을 유지한 채 기존 탐사 결과 패널을 그 위에 겹쳐 표시한다.

## 적용 범위

이번 연출은 `BattleResultChecker`가 모든 아군의 사망을 확인한 전멸 패배에만 적용한다.

침식도 100%로 발생하는 패배는 아군 전멸이 아니므로 캐릭터 집결 연출을 실행하지 않고 기존 패배 결과 흐름을 유지한다. 추후 침식 패배에도 별도 연출이 필요하면 같은 프레젠터에 다른 연출 진입점을 추가한다.

## 기존 흐름

현재 전멸 패배 흐름은 다음과 같다.

`전멸 확인 → 전투 종료 상태 확정 → 카메라 복귀 → BattleRoom 정리 → 탐사 결과 패널 표시`

`BattleRoomCleaner.Clean()`이 탐사 결과 패널을 열기 전에 실행되어 `BattleCharacter` 오브젝트를 제거하므로, 실제 캐릭터를 사용하는 패배 연출을 위해 정리 시점을 늦춰야 한다.

## 권장 구조

### BattleResultChecker

전투 결과 판정과 패배 연출 진입만 담당한다.

- 기존 전멸 판정과 `battleEnded` 확정 시점은 유지한다.
- 전멸 패배 시 카메라 복귀 후 `BattleDefeatPresentation`을 호출한다.
- 패배 프레젠터가 존재하지 않거나 연출을 시작할 수 없는 경우 기존 탐사 결과 패널 표시로 안전하게 대체한다.
- 침식 패배는 패배 프레젠터를 호출하지 않고 기존 흐름을 사용한다.
- 탐사 결과 데이터, 보상 배율, 전투 상태는 연출 컴포넌트가 변경하지 않는다.

### BattleDefeatPresentation

전멸 이후의 시각 연출 순서만 담당하는 신규 `MonoBehaviour`다.

- 현재 활성화된 아군 `BattleCharacter`를 수집한다.
- 이동 직전 각 캐릭터의 월드 `x` 값을 기준으로 오름차순 정렬한다.
- 정렬된 캐릭터를 좌·중·우 앵커에 대응시킨다.
- 검은 안개 하강, 캐릭터 이동, 문구 표시, 결과 패널 호출 시점을 제어한다.
- 캐릭터의 런타임 전투 데이터, HP, 사망 상태, Animator 상태, 방향은 변경하지 않는다.
- 연출 도중 입력과 전투 진행이 재개되지 않도록 기존 전투 종료 상태를 그대로 사용한다.

### 씬 배치 오브젝트

연출용 오브젝트는 런타임 생성하지 않고 `Battle` 씬에 미리 배치한다.

- 패배 연출 루트
- 화면을 덮을 수 있는 검은 안개 오브젝트
- 좌·중·우 캐릭터 도착 앵커 3개
- `탐사 실패` TMP 텍스트
- 필요 시 연출 전용 Canvas 또는 Sorting Group

아트 담당자가 위치, 크기, 속도, 곡선 구도를 조절할 수 있도록 관련 값과 참조를 인스펙터에 노출한다.

## 연출 순서

1. 마지막 아군의 사망 처리가 끝나고 전멸 결과가 확정된다.
2. 전투 입력과 진행은 기존 종료 처리로 중단한다.
3. 카메라가 기존 전투 종료 기본 위치로 복귀한다.
4. 활성 아군 캐릭터 3명의 이동 직전 월드 `x` 값을 기록하고 오름차순 정렬한다.
5. 전투 HUD와 선택 표시 등 불필요한 표시를 숨긴다.
6. 검은 안개가 화면 위에서 아래로 내려와 캐릭터를 제외한 전장을 가린다.
7. 캐릭터를 좌·중·우 앵커로 부드럽게 이동시킨다.
8. 캐릭터 이동과 함께 또는 직후 `탐사 실패` 문구를 표시한다.
9. 인스펙터에서 설정한 결과 대기 시간이 지난다.
10. 검은 안개, 문구, 캐릭터 배치를 유지한 채 기존 `ExplorationResultPanelUI.OpenDefeat`를 최상단에 표시한다.
11. 사용자가 거점 복귀를 선택하면 기존 전투방 정리와 런 전환 흐름을 수행한다.

안개 하강과 캐릭터 이동은 일부 겹쳐 재생할 수 있도록 각각 시작 지연과 지속 시간을 인스펙터 값으로 둔다.

## 캐릭터 정렬과 이동

### 순서 결정

캐릭터 순서는 연출 시작 직전에 결정한다.

```text
현재 월드 x 오름차순
→ 첫 번째 캐릭터: 왼쪽 앵커
→ 두 번째 캐릭터: 중앙 앵커
→ 세 번째 캐릭터: 오른쪽 앵커
```

동일하거나 매우 가까운 `x` 값에 대해서는 `CharacterId`를 보조 정렬 키로 사용해 결과를 안정적으로 유지한다. 전투 상태나 씬 검색 순서에 따라 좌우 배치가 달라지지 않게 한다.

### 포물선 배치

좌·중·우 앵커를 씬에 직접 배치한다. 기본 구도는 중앙 앵커의 `y` 값을 좌우보다 높게 둔 완만한 `∩` 형태다.

수학식으로 위치를 강제하지 않고 앵커를 사용하는 이유는 다음과 같다.

- 해상도와 카메라 구도에 맞춰 아트 담당자가 직접 조절할 수 있다.
- 캐릭터별 크기 차이를 씬에서 빠르게 보정할 수 있다.
- 코드 변경 없이 포물선의 폭과 높이를 조절할 수 있다.

### 애니메이션과 방향 보존

- Animator에 새로운 상태를 재생하지 않는다.
- 캐릭터 루트 또는 `SpriteRoot`의 좌우 반전 값을 변경하지 않는다.
- 이동은 캐릭터 월드 루트의 위치만 보간한다.
- 사망 애니메이션이 마지막 프레임에서 유지되는 기존 동작을 그대로 사용한다.
- 연출 중 Y 정렬이 위치 변화로 흔들리지 않도록 기존 Y 정렬 영향을 정지하거나, 연출 전용 고정 정렬 순서를 적용한다.

## 렌더링 및 가림 구조

화면의 깊이 순서는 아래와 같이 고정한다.

```text
기존 전장·몬스터·전투 HUD
→ 검은 안개
→ 쓰러진 아군 캐릭터 3명
→ 탐사 실패 문구
→ 탐사 결과 패널
```

- 안개는 전장과 몬스터를 가리되 캐릭터보다 낮은 정렬 순서를 사용한다.
- 캐릭터의 SpriteRenderer들은 연출 시작 시 기존 정렬 정보를 저장하고 패배 연출 전용 순서로 올린다.
- 월드 HUD, 선택 하이라이트, 타임라인 등은 연출 진입 시 숨긴다.
- 탐사 결과 패널은 기존 독립 Canvas의 높은 sorting order를 유지하여 패배 연출 위에 표시한다.
- 결과 패널 표시 전까지 `BattleRoomCleaner`를 호출하지 않아 실제 캐릭터 오브젝트를 보존한다.

검은 안개 리소스는 씬의 직렬화 참조로 연결한다. 리소스가 교체되어도 코드 변경이 필요 없도록 특정 이름 검색이나 런타임 `AddComponent`에 의존하지 않는다.

## 인스펙터 설정값

`BattleDefeatPresentation`에는 최소한 다음 항목을 노출한다.

- 검은 안개 루트
- 안개 시작 위치와 종료 위치 또는 대응 앵커
- 안개 시작 지연
- 안개 하강 시간
- 좌·중·우 캐릭터 앵커
- 캐릭터 이동 시작 지연
- 캐릭터 이동 시간
- 이동 보간 곡선 `AnimationCurve`
- `탐사 실패` 텍스트 루트
- 문구 표시 지연 및 페이드 시간
- 결과 패널 표시 전 대기 시간
- 패배 연출용 캐릭터 sorting order 기준값

시간 값은 음수가 되지 않도록 런타임에서 보정한다.

## 실패 및 예외 처리

- 패배 프레젠터가 없으면 기존 패배 결과 패널을 즉시 표시한다.
- 캐릭터가 3명보다 적으면 존재하는 캐릭터만 사용하고 중앙 우선으로 배치한다.
- 캐릭터가 3명보다 많으면 현재 파티의 안정적인 순서와 `x` 정렬 결과를 이용해 최대 3명만 표시하고 경고를 남긴다.
- 캐릭터 또는 앵커 참조가 일부 누락되면 가능한 캐릭터만 배치하고 결과 패널 표시 흐름은 계속한다.
- 안개나 텍스트 참조가 누락되어도 캐릭터 이동과 결과 패널 표시는 중단하지 않는다.
- 연출 코루틴이 중복 호출되지 않도록 실행 상태를 보관한다.
- 씬 전환 또는 오브젝트 비활성화 시 진행 중인 연출을 안전하게 종료한다.

## 데이터 흐름과 멀티플레이 경계

```text
전투 Command
→ HP/사망 State Change
→ 전멸 Result 확정
→ BattleDefeatPresentation 재생
→ ExplorationResultPanel 표시
```

- 전멸 여부는 기존 전투 상태에서만 계산한다.
- 패배 프레젠터는 확정된 결과와 `CharacterId`가 연결된 기존 캐릭터 오브젝트만 읽는다.
- 프레젠터는 HP, 사망 여부, 보상, 통계, 맵 진행도를 변경하지 않는다.
- 캐릭터 이동은 연출용 Transform 변경이며 전투 GridIndex나 런타임 위치 상태를 변경하지 않는다.
- 연출 완료 여부가 패배 결과를 결정하거나 되돌리지 않는다.
- 동기화가 필요한 전투 결과는 기존 네트워크 흐름을 유지하고, 각 클라이언트는 같은 확정 결과를 받아 로컬 연출만 재생한다.
- 연출에는 전투 결과에 영향을 주는 랜덤을 사용하지 않는다.

## 검증 계획

### EditMode 테스트

- 세 캐릭터의 입력 순서와 관계없이 월드 `x` 오름차순으로 좌·중·우 앵커가 결정되는지 검증한다.
- `x` 값이 같은 경우 `CharacterId` 보조 정렬로 안정적인 결과가 나오는지 검증한다.
- 전멸 패배만 캐릭터 집결 연출을 요청하고 침식 패배는 기존 흐름을 사용하는지 검증한다.
- 패배 연출 완료 전에는 결과 패널이 열리지 않고, 대기 시간이 지난 뒤 열리는지 검증한다.
- 연출 도중 캐릭터 런타임 HP, 사망 상태, GridIndex가 변경되지 않는지 검증한다.
- 일부 참조가 누락되어도 결과 패널 호출이 유지되는지 검증한다.

### Unity Editor 수동 검증

- Unity 에디터를 실행한 상태에서 아군 3명을 전멸시킨다.
- 검은 안개가 위에서 아래로 내려오며 전장과 HUD를 가리는지 확인한다.
- 실제 쓰러진 캐릭터 3명만 안개 앞에 남는지 확인한다.
- 캐릭터가 이동 전 좌우 순서를 유지하며 포물선 형태로 배치되는지 확인한다.
- 이동 전후로 쓰러진 애니메이션 프레임과 바라보는 방향이 바뀌지 않는지 확인한다.
- 설정 시간이 지난 뒤 기존 탐사 결과 패널이 연출 위에 겹쳐 표시되는지 확인한다.
- 결과 패널에서 거점 복귀가 정상 작동하고 전투 오브젝트가 정리되는지 확인한다.
- 침식도 100% 패배에서는 캐릭터 집결 연출 없이 기존 결과 흐름이 유지되는지 확인한다.

Unity 에디터가 열려 있는 환경을 전제로 하며 batchmode 테스트는 수행하지 않는다.

- 전투 결과 판정 방식 변경
- 보상과 탐사 결과 계산 변경
- 침식 패배 전용 연출 추가
