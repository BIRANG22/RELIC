# 탐사 결과 시간·노드 횟수 카운트업 설계

## 의도

`ExplorationResultPanel`이 열릴 때 소요 시간과 일반 전투·정예 전투·사건 조우 횟수를 최종값으로 즉시 표시하지 않고, 0부터 증가해 결과값에 멈추도록 연출한다.

## 범위

- 소요 시간과 세 종류 노드 입장 횟수만 카운트업한다.
- 침식 레벨, 홍진석 및 나머지 정산 정보는 기존처럼 즉시 표시한다.
- 실제 탐사 결과와 방문 집계 로직은 변경하지 않는다.

## 접근 방식

- 선택: 네 값을 동시에 시작해 인스펙터에서 설정한 동일한 지속 시간에 완료한다. 결과 확인이 빠르고 패널 연출이 일관적이다.
- 대안: 값을 순차 재생하면 주목도는 높지만 결과 확인이 늦어진다.
- 대안: 값별 고정 증가 속도는 값의 크기에 따라 완료 시간이 크게 달라져 소요 시간 표시에 부적합하다.

## 설계

`ExplorationResultPanelUI`가 최종 소요 초와 방문 횟수를 보관하고, 패널 활성화 후 하나의 코루틴에서 정규화된 진행률로 네 표시값을 함께 보간한다. 소요 시간은 보간된 초를 기존 `BattleExplorationElapsedTime.Format`으로 변환하고, 방문 횟수는 정수로 변환해 표시한다.

카운트업 지속 시간은 직렬화 필드로 노출한다. 지속 시간이 0이거나 플레이 모드가 아니면 최종값을 즉시 적용한다. 패널 재오픈 또는 비활성화 시 기존 코루틴을 중단하고, 중단 시에는 최종값을 적용해 불완전한 숫자가 남지 않게 한다. 시간 배율 정지 상황에서도 재생되도록 `Time.unscaledDeltaTime`을 사용한다.

## 검증

- 진행률 0, 중간, 1에서 시간과 횟수 보간값이 기대값인지 EditMode 테스트로 검증한다.
- 소스 구조 테스트로 네 표시값이 카운트업 경로를 사용하고 지속 시간이 인스펙터에 노출되는지 검증한다.
- 런타임 및 Editor C# 프로젝트를 컴파일한다.
- Unity 에디터에서 실제 재생 속도와 시각적 자연스러움은 수동 확인 항목으로 남긴다.

## 멀티플레이 경계

이미 확정된 결과 데이터를 읽어 UI 텍스트만 갱신하는 연출 변경이다. 전투 상태, 방문 기록, 결과 계산 및 동기화 경계에는 영향을 주지 않는다.
